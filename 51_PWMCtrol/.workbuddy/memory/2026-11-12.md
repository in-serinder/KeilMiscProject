### 用户确认的关键前提
- 三路低端驱动带**三个完全独立的负载**，无死区、无互补、无换向时序。
- CONFIG 的"持续时间"单位是 **ms**（原描述 ns 为笔误）。
- 频率范围 **0.1Hz ~ 1MHz** → 必须双 PWM 引擎（PWMA 硬件 ≥21.12Hz / T0 软件 <22Hz）。
- ECHO 周期 **50ms**（默认值），占用约 15% 带宽。

### 硬件事实（已查证 STC8H1K08-36I-TSSOP20，非 T 版）
- Flash 8K / SRAM 约 1.2K（128 data + 128 idata + 1K xdata）；Keil SMALL 下 data 128B 是硬瓶颈。
- ADC **10 位**，仅 9 通道（ADC0/1、ADC8~14）；P1.2~P1.7 无 ADC。12 位是 8H1K08**T** 版本。
- 高级 PWM 8 通道 16 位，带互补与死区。**同一通道 P/N 共用占空比** → 3 路独立必须用 PWM1P/PWM2P/PWM3P。
- 建议引脚：PWM = P1.0/P1.2/P1.4；ADC = ADC10/11/12（P3.2/P3.3/P3.4）；UART1 = P3.0/P3.1；P3.5 可作 PWMFLT 硬件过流关断。
- 频率/分辨率互斥：ARR+1 = FOSC/(PSC·f)，1MHz 时占空比仅约 22 级（4.55%）。协议应答必须回"实际生效值"。

### 协议要点（自定，待评审）
- 上位机→下位机 `>`…`<`，下位机→上位机 `[`…`]`；分隔符 `_`；帧长 ≤64B。
- 17 条命令：TYPE-PWMCTROL / PING / VER / INFO / CONFIG / STOP / STOP_<ch> / PROG / RATE / ECHO / GET / ADCREAD / SAVE / LOAD / GUARD / STAT / RESET。
- 错误码 E01~E12；ECHO 格式 `[ECHO_<ch>_<freq>_<duty>_<adc>_<state>]`（state 为尾部可选项）。
- 预制程序 0~9 按独立负载场景拟定（呼吸/软启/软停/闪烁/点动/顺序启动/同步渐变/ADC 定压闭环/温控），**待用户圈定**。

- 其他：占空比精度与高频矛盾、MOS 驱动方式、ADC 采样点（母线 or 负载端）、是否要 PWMFLT 硬件过流关断。

## 第二轮：下位机面板需求 + 文档 v1.1/v0.2

**新增交付**：`docs/03-下位机固件结构文档.md`（FW-001 v1.0）
**同步修订**：02 协议 → v1.1（通道 0-2、频率 1Hz~999kHz、MODE 命令、E13、EVT_MODE/EVT_KEY）；01 架构 → v0.2（同口径）

### 用户补充的硬件/交互事实
- 主频确认 **22.1184MHz**；应用定位：自制**电机**驱动设备。
- 频率范围改为 **1Hz ~ 999kHz**（原 0.1Hz~1MHz）。
- 面板：**8 位数码管 + EC11 编码器 + 模式拨码开关 + 显示切换按钮**。
- 显示：D1-D3 频率；D4=Mode（dp 常亮）；D5-D7 电压或占空比；D8=程序号（dp 亮=通道号）。
- Mode 1 本地 / 2 预制程序（24C02）/ 3 上位机。
- EC11：单击切"频率↔占空比"编辑焦点，双击切通道，编辑中的字段 2s 闪烁。
- 存储：**24C02（256B）** 存预制程序；后期可能换同封装大 Flash 型号。

### 我提出并已确认的决策
- 数码管：板子已定型，**等用户发原理图**（固件侧做成可裁剪宏）。
- 过流保护：**放弃硬件 PWMFLT**，改软件判定（响应 ms 级，不能防短路——已在文档中明示风险）。
- 模式切换：**独立拨码开关**（占 2 IO）。
- 通道号：**统一 0-2**。

### 关键工程结论（已写进 03 文档）
1. **IO 缺口 1~2 个**：需求 18~19，可用仅 17（P1.0-P1.7 + P3.0-P3.7 + P5.4）。
2. **PWMA 的 PWM1~3 共用一个 ARR/PSC → 三通道无法各自不同频率**。这是最可能推翻既有协议的硬约束（Q16 待定）。
3. **8KB Flash 加面板后会写满（估算 7.9K）**，建议直接换 STC8H1K17。
4. 999kHz 无法精确命中：ARR+1=22 → 实际 1005kHz；建议对外标 1Hz~500kHz 精确。
5. 24C02 页大小仅 **8B**、tWR **10ms**，必须按页拆包 + 延迟写 + 读回校验。

## 第三轮：原理图到手 + Python 下位机模拟器

**新交付**：`sim/pwm_sim.py`（GUI 模拟器，约 1000 行）、`sim/README.md`、`sim/requirements.txt`、`sim/run_sim.bat`、`sim/gui_preview.png`
**文档**：`docs/03` 升 v1.1，新增第 16 章（原理图核对 + 显示规则修订）

### 原理图确认的引脚（STC8H1K08-36I-TSSOP20）
- CH0=P1.2(PWM2P)、CH1=P1.7(PWM4N)、CH2=P1.1(PWM1N)
- MAX7219：DIN=P1.3、CLK=P3.7、**LOAD=P1.0**
- 24C02：SDA=P1.4、SCL=P1.5（硬件 I2C 默认组）
- EC11：A=P3.3、B=P3.5、按键=P3.2
- 电压探头：P3.6（ADC14），独立引出，**只有 1 路**
- UART：P3.0/P3.1；空闲：P1.6、P3.4、P5.4

### 由原理图导出的三条硬结论
1. **P1.0 双重身份**（MAX7219 LOAD + PWM1P）：PWM1 只能使能 N 输出，CC1E 必须关闭，否则数码管乱码。建议下版把 LOAD 挪到 P3.4。
2. **三路 PWM 全在 PWMA**（PWM1N/2N/4N 同一时基）→ 三通道**强制同频**，Q16 已被硬件答案确定。
3. EC_B 占 PWMFLT → 本板永久无硬件过流保护。

### 显示规则修订（替代原 D1.dp=单位灯）
频率区用**小数点位置编码单位**：`123`=123Hz、`1.50`=1.5kHz、`20.0`=20kHz、`100.`=100kHz（尾点即 kHz）。
原因：D1.dp 若固定作单位灯，就无法显示 1.50kHz（小数点在 D1 之后）。

### 模拟器要点
- Tkinter + pyserial，Commons：`>…<` 收、`[…]` 发；Device 类与 GUI 解耦，可 `--selftest` 单测。
- 实现：8 位数码管（Canvas 七段 + 闪烁）、EC11 旋钮（拖拽/滚轮 + 单击/双击/长按）、模式拨码 1/2/3、显示切换、电压探头滑杆、三通道卡片、三路示波器（Canvas 方波）、串口日志。
- 频率量化与真机同公式（round 取最近 ARR），故 `[OK_]` 回的生效值与实测一致（20kHz→19998.55Hz）。
- 加了 `enable_dpi_awareness()`（ctypes SetProcessDpiAwareness），窗口 1480x920。
