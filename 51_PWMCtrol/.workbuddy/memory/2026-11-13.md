## 模拟器显示修正：占空比改整数百分比

**背景**：用户指出占空比两位数时，`50.0` 用三位数字 + 一个小数点显示，视觉上就是 `500`，容易误读。

**决策（用户给两个选项，我选前者）**：消隐第一位（D5）、右对齐显示后两位，即 `50` → `" 50"`；不用"消隐第三位"的左对齐 `"50 "`（数字左对齐不合仪表惯例，且 5% 会变成 `"5  "` 更空）。

**改动**：
- 新增 `App._duty_chars(d)`：0~99 用 `"%3d"` 右对齐，100 用 `"100"`；不再带小数点。
- `build_display` 改为调用它；EC11 编辑步进由 0.1% 改为 1%。
- 代价：面板分辨率降为 1%，0.1% 只在上位机侧体现（已写入 docs/03 与 README）。
- `--selftest` 增加"占空比显示检查"表：`0→"  0"`、`5→"  5"`、`50→" 50"`、`99→" 99"`、`100→"100"`。

**同步更新**：`sim/README.md`（字段表）、`docs/03` §5.2 与 §16.3（含"为什么不用 50.0"的理由）、`sim/gui_preview.png` 重截（CH0=1.50kHz/50%）。

**踩坑**：新增静态方法时把它插在已有 `@staticmethod` 之后，造成双装饰器且 `_freq_chars` 掉装饰器 —— 已修正。写代码时注意别在装饰器和方法之间插入。

## 模拟器示波器升级（Multisim 式）

**需求**：原示波器固定"3 个周期窗口"，看不清；要有时基参数，并单独开区域看单周期形状。

**实现**（`pwm_sim.py` 新增 `ScopePanel` + `PeriodView`，替换原 `Scope`）：
- `TB_STEPS` 22 档时基（1s ~ 100ns/div），`fmt_time()` 输出 `1 ms` / `500 µs` / `200 ns`。
- `auto_timebase(f)`：取"10 格≈3 个周期"的最近档（按对数距离），1.5kHz→200µs/div、20kHz→20µs/div、999kHz→200ns/div。
- 触发：选 CH0-2 + ↑/↓，触发点固定在 20% 宽度（顶部黄三角）。t0 = off - 0.2*tspan，`off` 在下降沿时加 duty*T。**波形是"已触发"的静止显示**，不再做相位漂移动画——这才是示波器行为。
- 绘制：10×10 格栅 + 三泳道，逐像素（步长 2px）采样 `level(t)=((t*f)%1)*100<duty`，边沿处补一点画垂直线保证陡峭。
- `PeriodView`：触发通道单个周期，标注 `T`（蓝，下方）、`Ton`（黄，上方）、`Toff`、`f`、`duty`。
- 控制条：时基下拉 / 触发源下拉 / 边沿按钮 / 暂停按钮（暂停冻结绘制，数据仍刷新）。

**数值验证**（别信眼睛）：1.5kHz/50%、200µs/div → t0=-0.4ms、tspan=2ms，边沿落在 x/w = 0.035↓ 0.2↑ 0.3675↓ 0.535↑，周期 3.33 格 ✓ 与设计一致。

**踩坑**：截图时桌面上的 QQ 窗口盖住了应用，抓到半张图；改用 `root.attributes("-topmost", True)` + `root.lift()` 再 `ImageGrab` 窗口矩形。另注意 Tk 未开 DPI 感知时 `winfo_rootx/width` 是逻辑值、截图是物理像素，会裁偏。

### 本机环境踩坑（重要，别再踩）
1. **`dotnet restore` 全线失败**：`NuGet.targets(745,5) Value cannot be null (Parameter 'path1')`，
   `XPlatMachineWideSetting..ctor` → `NuGetEnvironment.GetFolderPath` 返回 null。
   设环境变量（ProgramData/TEMP）、换 PowerShell、关沙箱、干净 `env -i` **都无效**；连参考项目 restore 也失败。
   **绕过**：`D:\VSTudio\MSBuild\Current\Bin\MSBuild.exe <proj> -t:Restore` 能成功，之后 `dotnet build --no-restore` 正常。
2. **Avalonia 窗口被裁一半**：`app.manifest` 没声明 DPI 感知 → Windows 按 125% 位图拉伸，
   声明 `dpiAware/dpiAwareness` + `Program.Main` 调 `SetProcessDpiAwarenessContext(-4)` 后正常。
3. **截图坐标**：DPI 感知进程的窗口，`GetWindowRect` 在 DPI-unaware 的 Python 里是虚拟坐标，
   必须乘 `GetDpiForWindow(hwnd)/96` 再 `ImageGrab`，否则只截到左上 80%。
4. **Avalonia `ComboBox` 没有 `IsEditable`**（与 WPF 不同），要手输端口只能用 `TextBox`。
5. **自定义 `Control` 必须实现 `MeasureOverride`**，否则在居中布局里宽度为 0，`Render` 直接返回。
6. `WinExe` 从命令行启动时 **stdout 仍然有效**，所以 `--selftest` 可直接打印（不必写文件）。
7. 本机 COM1/COM2 是 HHD 的"幽灵口"：枚举得到但打不开，**无法做真实串口联调**；只能靠 `--selftest` 验协议层。
8. GUI 自动化截图：`SetWindowPos(TOPMOST)` 需给 ctypes 声明 `argtypes`，否则 64 位句柄被截断、调用静默失败。

### 验证结果
- `dotnet build --no-restore`：0 警告 0 错误。
- `PWMCtrol.exe --selftest`：14 项全 PASS（帧解析/粘包/超长帧/ECHO 解析/null 电压/CONFIG 拼装/999kHz 不被科学计数法改写）。
- 界面截图见 `docs/ui-preview.png`，三卡片并排、日志与状态栏正常。

**新增/改动**

**踩坑**
1. **未点亮段太显眼**：`#2B1D1A` 在 `#0D1014` 底上会显出"幽灵 8"，小尺寸下数字读不出来。改成与底色完全相同的 `#0D1014` 才像用户参考图那种"挖空 LED"。
2. **反复编译被占用**：截图脚本 terminate 后仍有 `PWMCtrol.exe` / `.NET Host` 残留，`MSB3027 文件被锁定`。解法：`taskkill //IM PWMCtrol.exe //F` + 结束占用 dll 的 `.NET Host` 进程再 build。
3. 自定义控件里的文字要用 `FormattedText`（`new FormattedText(text, culture, FlowDirection.LeftToRight, new Typeface("Consolas"), size, brush)`），`DrawText` 才生效；`TextBlock` 不参与 `Control.Render`。

**验证**：`--ui-demo` 截图三卡分别显示 1.50kHz/50%、20.0kHz/62%、480Hz/88%，波形 `Ton 333.337 µs` / `T 666.675 µs` 与手算一致；电压面板 3.32 V。
