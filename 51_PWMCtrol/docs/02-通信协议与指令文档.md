## 1. 物理层

| 项 | 值 |
| --- | --- |
| 接口 | UART1，TTL 电平（3.3V/5V 需与 MCU 供电一致） |
| 波特率 | 115200 |
| 数据格式 | 8 数据位，无校验，1 停止位（8N1） |
| 流控 | 无 |
| 单字节时间 | 86.8µs |
| MCU 时钟 | 22.1184MHz（T1 12T，reload=0xFFFC，误差 0%） |

> 若实际主频为 22.158MHz，115200 的误差约 0.18%，在 UART 容限内但已接近边界，需实测（见架构文档 Q2）。

## 2. 帧格式

### 2.1 方向约定（**必须严格遵守**）

| 方向 | 起始符 | 结束符 | 示例 |
| --- | --- | --- | --- |
| 上位机 → 下位机（命令） | `>` (0x3E) | `<` (0x3C) | `>STOP<` |
| 下位机 → 上位机（应答/上报） | `[` (0x5B) | `]` (0x5D) | `[OK_STOP]` |

方向写反是最常见的"发出去没反应"原因：固件只把 `>` 开头的串识别为命令，`[RX-OK]` 这类会被当噪声丢弃。

### 2.2 文法

```
CommandFrame  = ">" Command [ "_" Field *( "_" Field ) ] "<"
ReplyFrame    = "[" ReplyBody "]"
Field         = Number | Keyword
Number        = UInt | Decimal
UInt          = DIGIT *( DIGIT )
Decimal       = DIGIT *( DIGIT ) "." DIGIT *( DIGIT )
Keyword       = UPPER *( UPPER | "-" )
DIGIT         = "0".."9"
UPPER         = "A".."Z"
```

约束：

| 项 | 规则 |
| --- | --- |
| 分隔符 | 下划线 `_`（0x5F），**不允许多个连续下划线** |
| 字段数 | 每条命令固定（见第 5 节），多/少均报 `E06` |
| 帧长 | 含起止符 ≤ 64 字节；超长整帧丢弃并报 `E07` |
| 保留字符 | `_` `>` `<` `[` `]`，字段值内不得出现 |
| 空白 | 帧内**不允许**空格、制表、换行 |
| 大小写 | 命令关键字与关键字字段一律大写；数字无前导 `+`；无负数 |
| 前导零 | 允许（`007` = `7`），固件按数值解析 |
| 小数位 | 频率最多 3 位、占空比最多 2 位；多余位数直接截断（不四舍五入） |
| 行尾 | 应答以 `\r\n` 结束（`0D 0A`）；命令的 `\r\n` 可省略，固件忽略帧外所有字节 |
| 编码 | ASCII 0x20~0x7E，其余字节视为噪声 |

### 2.3 应答通用形态

```
[OK ...]      执行成功（后缀带实际生效值）
[ERR_Exx]     执行失败（可带一个诊断字段）
[ECHO ...]    周期上报 / 单次查询结果
[EVT ...]     异步事件（故障等，不请自来）
```

## 3. 数值与单位约定

| 参数 | 单位 | 范围 | 分辨率 | 内部表示 |
| --- | --- | --- | --- | --- |
| 频率 freq | Hz | 1 ~ 999000 | 1Hz（输入） | 毫赫兹整数（32 位） |
| 占空比 duty | % | 0.0 ~ 100.0 | 0.1% | 千分比整数 permille（0~1000） |
| 持续时间 dur | **ms** | 1 ~ 4294967295，或 `F` | 1ms | 32 位毫秒；`F` = 0xFFFFFFFF |
| ADC 电压 | mV | 0 ~ 5000 | 1mV | 由 10 位原始值换算 |
| 通道 ch | — | **0 ~ 2** | — | 1 字节 |
| ECHO 周期 | ms | 10 ~ 1000 | 1ms | 16 位 |

> **原需求中"持续时间（ns）"已确认改为 ms**。32 位 ms 可覆盖 49.7 天，`F` 表示永久运行直到 `>STOP<`。

## 5. 指令详解

### 5.1 `>TYPE-PWMCTROL<` — 设备识别

**请求**：`>TYPE-PWMCTROL<`

**应答**：

- 匹配 → `[YES]`
- 不匹配（字面量不同）→ **不应答**（避免总线上多台设备同时响应）

> 建议上位机连接后第一件事就发它，收到 `[YES]` 再进入"就绪"态。超时 3 次即判定连错端口。

---

### 5.2 `>PING<` — 心跳

**请求**：`>PING<`
**应答**：`[PONG]`

用途：测量往返时延、维持 `GUARD` 看护。建议 `GUARD` 开启时上位机每 1s 发一次。

---

### 5.3 `>VER<` / `>INFO<`

**请求**：`>VER<` → **应答**：`[VER_1.0.0]`（协议版本；固件小改动不改协议版本）

**请求**：`>INFO<` → **应答**：`[INFO_PWMCTROL_3_1.0.0_22118]`
字段：型号、通道数、固件版本、主频 kHz。

用途：上位机据此决定显示哪些控件（例如主频字段可用于误差提示）。

---

### 5.4 `>CONFIG_<ch>_<freq>_<duty>_<dur>_<adc><` — 配置并启动通道

**参数**

| 字段 | 名称 | 取值 | 校验失败错误码 |
| --- | --- | --- | --- |
| `ch` | 通道号 | 0 / 1 / 2 | `E01` |
| `freq` | 频率 Hz | 1 ~ 999000（可小数，最多 3 位） | `E02` |
| `duty` | 占空比 % | 0.0 ~ 100.0（可小数，最多 2 位） | `E03` |
| `dur` | 持续时间 | 1 ~ 4294967295（ms）或 `F` | `E04` |
| `adc` | 采集设置 | `0` 不采集 / `1` 采本通道默认 ADC / `A<n>` 指定 ADC 编号（0~14） | `E05` |

**成功应答**：`[OK_<ch>_<freq_eff>_<duty_eff>_<adc_eff>]`

- `freq_eff`：硬件量化后的实际频率，2 位小数（如 `1000.02`）。这是**真值**，不是回显。
- `duty_eff`：量化后的实际占空比，1 位小数。
- `adc_eff`：实际生效的采集设置（`0` / `1` / `A<n>`）。

**失败应答**：`[ERR_E05_<detail>]` 形式，`detail` 为可读诊断（如 `ARR<8`）。

**行为规则**

0. **权限前置**：仅当设备处于 `Mode 3`（上位机模式）时才接受 `CONFIG`/`PROG`；处于 `Mode 1`/`Mode 2` 时回 `[ERR_E13_MODE]`。`STOP`、`GET`、`MODE` 不受模式限制（停止永远放行，安全优先）。
1. 该通道处于 `FAULT` 时一律拒绝，回 `[ERR_E09_FAULT]`，需先 `>STOP<`。
2. 该通道正在运行时：
   - 仅 **duty / adc** 变化 → 平滑生效（输出不中断），状态下不变；
   - **freq 变化** → 关断 → 重配 → 重启（产生 1 个周期以内的输出低）；
   - **dur** 变化 → 重置剩余计时（不重启输出）。
3. 占空比 0.0% → 强制输出低；100.0% → 强制输出高（均不产生窄脉冲）。
4. `dur` 到期：输出低、状态转 `EXPIRED`，参数保留（可再 CONFIG 唤醒）。
5. 频率对应的 `ARR+1 < 8`（约 > 2.7MHz 或无法达到的分辨率）→ 回 `[ERR_E12_RES]`。

**示例**

```
>CONFIG_0_1000_50.0_5000_1<        → [OK_0_1000.02_50.0_1]
>CONFIG_1_5_30_0_0<                 → [OK_1_5.00_30.0_0]       (5Hz 走软件引擎)
>CONFIG_2_20000_12.5_F_A10<         → [OK_2_20016.67_12.5_A10]
>CONFIG_3_1000_50_5000_0<           → [ERR_E01]                (通道号越界)
>CONFIG_0_1000_150_5000_0<          → [ERR_E03]
>CONFIG_0_999000_50_F_0<            → [OK_0_1005381.00_50.0_0] (高段只能命中离散点，见架构文档 6.1)
>CONFIG_0_100_50_F_0<               → [ERR_E13_MODE]           (设备在 Mode 1/2)
```

---

### 5.5 `>STOP<` / `>STOP_<ch><` — 停止

**请求**：`>STOP<` → **应答**：`[OK_STOP]`

- 三通道全部：清 PWM 使能、强制输出低、复位计时、清 `FAULT` 锁存、终止预制程序。
- 生效时间 < 1ms（直接写寄存器，不走主循环等待）。

**请求**：`>STOP_<ch><` → **应答**：`[OK_STOP_<ch>]`

**幂等**：重复发送不产生副作用（可安全重试）。

---

### 5.6 `>PROG_<ch>_<n><` — 启动预制程序

**参数**

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `ch` | 0~2 | 作用通道 |
| `n` | 0~9 | 预制程序号（见第 7 节） |

**成功应答**：`[OK_PROG_<ch>_<n>]`
**失败应答**：`[ERR_E08_<n>]`（程序号非法）、`[ERR_E09_...]`（通道在 FAULT）

**规则**

- 频率沿用该通道当前**生效频率**；若该通道从未 CONFIG 过，用默认 1000Hz。
- 占空比由程序内部曲线驱动，`CONFIG` 的 duty 仅作为"基准值"（部分程序使用）。
- 持续时间沿用该通道当前 `dur`（`F` 则一直跑）。
- 再次 `>PROG_<ch>_<m><` 会切换程序（先停当前曲线再启新的）。
- 需要两个附加参数的程序（如 8/9 号）用扩展语法：`>PROG_<ch>_<n>_<p1>_<p2><`。

---

### 5.7 `>RATE_<ms><` — 设置上报周期

**请求**：`>RATE_50<` → **应答**：`[OK_RATE_50]`
范围 10~1000ms，超范围回 `[ERR_E07_RATE]`。默认 50。

> 建议 10ms 时同时把 `ECHO` 设为 2（变化才发），否则带宽占用会到 75%。

---

### 5.8 `>ECHO_<0|1|2><` — 上报模式

| 值 | 含义 |
| --- | --- |
| `0` | 关闭周期上报（仍可用 `>GET_` 单次查询） |
| `1` | 常发（默认） |
| `2` | 变化才发：仅当 freq/duty/adc 相对上次变化超过阈值（频率 0.1%、占空比 0.5%、ADC 8mV）才发，另有每 10 个周期一次的保底帧 |

**应答**：`[OK_ECHO_1]`

---

### 5.9 `>GET_<ch><` — 单次查询

**请求**：`>GET_2<` → **应答**：`[ECHO_2_1000.02_50.0_1234_R]`（格式同周期上报）

用途：ECHO 关闭时的按需刷新；UI 拖滑块时用它可以立刻拿到反馈。

---

### 5.10 `>ADCREAD_<ch><` — 读 ADC

**请求**：`>ADCREAD_1<` → **应答**：`[ADC_1_512_2500]`（原始值 0~1023、换算电压 mV）

不受 `adc` 使能位限制，用于校准与诊断（此时会临时采样一次，约 100µs）。

---

### 5.11 `>SAVE<` / `>LOAD<` — 配置持久化

**`>SAVE<`** → `[OK_SAVE]` / `[ERR_E11]`

保存内容：三通道的 freq/duty/dur/adc + 全局 RATE/ECHO/GUARD + 校验和。
**不保存运行状态**（掉电后一律为 OFF，符合失效安全）。

> 不要在每次 CONFIG 后自动 SAVE（Flash 写寿命 10 万次，UI 拖动滑块会写穿）。由上位机在"保存配置"按钮里显式发。

**`>LOAD<`** → `[OK_LOAD]` / `[ERR_E11]`（空片/校验失败 → 用出厂默认）

---

### 5.12 `>GUARD_<ms><` — 通信看护

**请求**：`>GUARD_3000<` → **应答**：`[OK_GUARD_3000]`

- `0` = 关闭（默认）
- 非 0：超过该时长没收到任何合法命令帧 → 全部通道 STOP，并在 ECHO 里把 state 置为 `E`，同时上报一次 `[EVT_GUARD_STOP]`
- 任何合法帧（含 `>PING<`）都会重置计时

> 开启后上位机必须保持心跳（建议 1s 一次，看护值 ≥ 3× 心跳周期）。

---

### 5.13 `>STAT<` — 状态统计

**应答**：`[STAT_<rst>_<rxovf>_<framerr>_<echoDrop>_<uptime_s>]`

| 字段 | 含义 |
| --- | --- |
| `rst` | 上次复位原因：`POR` 上电 / `WDT` 看门狗 / `SW` 软复位 / `ISP` 下载 |
| `rxovf` | RX 缓冲溢出次数 |
| `framerr` | 帧错误次数（超长、超时、字段数错） |
| `echoDrop` | ECHO 因背压丢弃的帧数 |
| `uptime_s` | 运行秒数 |

---

### 5.14 `>RESET<` — 软复位

**请求**：`>RESET<` → **应答**：`[OK_RESET]`，100ms 后复位（先保证应答发完）。
复位后所有通道 OFF，配置从 RAM 恢复为 EEPROM 内容（若曾 SAVE）或出厂默认。

---

### 5.15 `>MODE_<n><` / `>MODE?<` — 运行模式

| n | 模式 | 参数来源 | 面板行为 | 上位机权限 |
| --- | --- | --- | --- | --- |
| `1` | 本地面板 | EC11 实时写入通道参数 | 旋转改频率/占空比，全部可编辑 | 只能查询，`CONFIG`/`PROG` 回 `E13` |
| `2` | 预制程序 | 24C02 中的程序参数 | 旋转选程序号，单击启停 | 只能查询，回 `E13` |
| `3` | 上位机 | 串口命令 | 只显示，编辑被忽略 | 全权限 |

**请求**：`>MODE_3<` → **应答**：`[OK_MODE_3]`
**查询**：`>MODE?<` → **应答**：`[MODE_3]`

规则：

- 拨码开关的物理位置**优先于**命令：硬件开关变了，固件跟着变，并主动上报 `[EVT_MODE_<n>]`；此时 `>MODE_n<` 若与开关位置不一致回 `[ERR_E13_MODE]`（以硬件为准）。
- `STOP` 不受模式限制（任何模式都能停机）。
- 模式切换**不改变**当前输出：从 Mode 3 切到 Mode 1 时，PWM 保持当前频率/占空比继续跑，只是改由面板接管参数。
- 上电进入拨码开关指示的模式；若开关在 Mode 3 但串口从未收到合法帧，30s 后按 Mode 1 处理（防止开关误拨导致设备"无人控制"）。

## 6. ECHO 上报规范

### 6.1 帧格式

```
[ECHO_<ch>_<freq>_<duty>_<adc>_<state>]
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ch` | 0~2 | 通道号 |
| `freq` | 小数 2 位 | **实际生效**频率 Hz，如 `1000.02`、`5.00` |
| `duty` | 小数 1 位 | **实际生效**占空比 %，如 `50.0`、`0.0` |
| `adc` | 整数 mV 或 `null` | 未使能采集时返回字面量 `null` |
| `state` | 可选 | `R` 运行 / `S` 停止 / `E` 到期或看护停机 / `F` 故障；缺省视为 `R` |

**示例**

```
[ECHO_1_1000.02_50.0_1234]        ← 运行中，采到 1234mV（state 省略 = R）
[ECHO_2_0.50_30.0_null_R]         ← 0.5Hz 软件引擎，未开 ADC
[ECHO_3_20016.67_12.5_4980_F]     ← 过流故障锁存，输出已关断
[ECHO_1_1000.02_0.0_1234_E]       ← 持续时间到期，占空比归 0
```

### 6.2 调度规则

- 周期 `T` 由 `>RATE_` 设定（默认 50ms）。
- 一个周期内 3 帧**均匀错开**：分别在 `T/6`、`T/2`、`5T/6` 发送，避免瞬时突发。
- 只上报状态为 `R` / `E` / `F` 的通道；`OFF` 状态且从未配置的通道不发。
- 背压：TX 队列水位 > 200B 时跳过本轮 ECHO（保命令应答）；`echoDrop` 计数 +1。

### 6.3 带宽预算

| 场景 | 每秒字节 | 占用（115200） |
| --- | --- | --- |
| RATE=50ms，3 通道全开 ADC | ~1740 B/s | 15% |
| RATE=50ms，无 ADC（`null`） | ~1620 B/s | 14% |
| RATE=10ms，3 通道 | ~8700 B/s | 75%（不推荐，需开 ECHO=2） |
| RATE=200ms，3 通道 | ~435 B/s | 3.8% |

## 7. 预制程序（PROG 0~9）

按"三个独立负载"拓扑拟定，**待你确认/替换**（架构文档 Q9）。

| n | 名称 | 曲线行为 | 默认参数 | 需 ADC | 典型负载 |
| --- | --- | --- | --- | --- | --- |
| 0 | 直通运行 | 保持该通道设定频率与占空比不变，等同于 `CONFIG` 的持续模式 | 无 | 否 | 通用 |
| 1 | 呼吸渐变 | 占空比 0→100→0 三角波循环 | 周期 3s | 否 | LED / 氛围灯 |
| 2 | 软启动 | 0 → 设定值线性上升后保持 | 上升时间 1s | 否 | 电机 / 加热丝 |
| 3 | 软停止 | 设定值 → 0 线性下降后关断 | 下降时间 1s | 否 | 电机 / 电磁阀 |
| 4 | 周期闪烁 | 2Hz 方波，占空比 50%，无渐变 | 2Hz / 50% | 否 | 指示灯 / 蜂鸣 |
| 5 | 点动循环 | 运行 5s → 停止 5s，循环 | 5s / 5s | 否 | 泵 / 间歇加热 |
| 6 | 顺序启动 | CH1→CH2→CH3 依次软启动（各 1s），间隔 500ms | 500ms | 否 | 三路联动上电 |
| 7 | 同步渐变 | 三通道相位一致的 0→100→0 渐变 | 周期 3s | 否 | RGB 混色 |
| 8 | ADC 定压闭环 | 每 100ms 按误差调整占空比（步进 ≤1‰），使该通道 ADC 电压趋近目标 | 目标 = `p1`(mV)，默认 2500 | **是** | 稳压 / 恒压驱动 |
| 9 | 温控占位 | bang-bang：ADC < 阈值 → 100%，> 阈值+回差 → 0% | 阈值 `p1`(mV)，回差 `p2`(mV)，默认 2000/100 | **是** | 加热保温 |

扩展语法（8/9 号需要）：

```
>PROG_1_8_2500_0<        通道1 跑 8 号程序，目标 2500mV
>PROG_2_9_2000_100<      通道2 跑 9 号程序，阈值 2000mV，回差 100mV
```

不带 `p1/p2` 时使用默认值，保证与基础语法 `>PROG_<ch>_<n><` 兼容。

所有曲线的内部步进不小于 10ms，且每次只改 CCR（不改频率），因此运行时无输出毛刺。

## 8. 应答码与错误码

### 8.1 成功应答

| 应答 | 含义 |
| --- | --- |
| `[YES]` | 识别成功 |
| `[PONG]` | 心跳 |
| `[OK_<ch>_<f>_<d>_<a>]` | CONFIG 成功（回生效值） |
| `[OK_STOP]` / `[OK_STOP_<ch>]` | 停止成功 |
| `[OK_PROG_<ch>_<n>]` | 预制程序已启动 |
| `[OK_RATE_<ms>]` / `[OK_ECHO_<v>]` / `[OK_GUARD_<ms>]` | 设置成功 |
| `[OK_SAVE]` / `[OK_LOAD]` / `[OK_RESET]` | 存储/复位成功 |

### 8.2 错误码

| 码 | 含义 | 触发条件 | 上位机建议动作 |
| --- | --- | --- | --- |
| `E01` | 通道号非法 | 非 0~2 | 修正 UI |
| `E02` | 频率越界 | < 1 或 > 999000，或解析失败 | 提示范围 |
| `E03` | 占空比越界 | < 0 或 > 100.0 | 提示范围 |
| `E04` | 持续时间非法 | 0、非数字、非 `F` | 提示范围 |
| `E05` | ADC 参数非法 | 非 0/1/`A<n>`，或 ADC 编号不可用（2~7、15） | 提示可用通道 |
| `E06` | 字段数量错 | 少/多字段 | 检查拼装 |
| `E07` | 未知命令 / 帧超长 / 帧超时 | 命令不在表内，或 > 64B | 检查协议版本 |
| `E08` | 预制程序号非法 | n > 9 | 只显示 0~9 |
| `E09` | 当前状态不允许 | 通道 FAULT 时收到 CONFIG/PROG | 先发 `>STOP<` |
| `E10` | 校验失败 | 启用 CRC 时校验不符 | 重发 |
| `E11` | 存储失败 | Flash 写失败/校验不符 | 提示，重试一次 |
| `E12` | 分辨率不足 / 引擎不可用 | 该频率下 `ARR+1 < 8` | 降低频率或改策略 |
| `E13` | 模式不允许 | 设备处于 Mode 1 / Mode 2 时收到 CONFIG / PROG | 先发 `>MODE_3<`，并提示"设备面板锁定中" |

错误应答可带一个诊断字段（不下划线）：`[ERR_E12_RES]`、`[ERR_E09_FAULT]`、`[ERR_E13_MODE]`。上位机解析时只取第一段错误码，忽略诊断段。

### 8.3 异步事件

| 事件 | 含义 |
| --- | --- |
| `[EVT_FAULT_<ch>]` | 软件过流/超限保护触发，该通道已强制关断并锁存 |
| `[EVT_GUARD_STOP]` | 通信看护超时，全部通道已停 |
| `[EVT_MODE_<n>]` | 面板（拨码开关）切换了模式，通知上位机刷新权限态 |
| `[EVT_KEY_<k>]` | 面板按键事件摘要（`ENC` 旋转 / `CLK` 单击 / `DBL` 双击 / `SEL` 切换显示），供上位机日志与联动 |
| `[EVT_BOOT_<rst>]` | 上电/复位通知（上位机可据此重置 UI 状态） |

事件帧与应答帧共用一个发送队列，上位机解析器需按首字段分派，不能假设"发完命令下一个帧就是它的应答"。

## 9. 兼容性与扩展

### 9.1 字段扩展原则

1. **追加在尾部**，老固件会因字段数不符回 `E06`；上位机应以 `>VER<` 结果决定是否使用扩展字段。
2. 未知命令一律回 `E07`，不允许静默忽略（便于定位版本错配）。
3. `state` 字段是尾部可选项，解析时按字段数判断（4 段 = 老格式，5 段 = 新格式）。

### 9.2 可选 CRC8

```
>CRC_1<   →  [OK_CRC_1]
帧格式：  >CONFIG_1_1000_50.0_5000_1*3F<
```

多项式 `0x31`（CRC-8/MAXIM），范围 `>` 之后到 `*` 之前（不含 `>`、`*`、校验值）。默认关闭，强干扰环境再开。

### 9.3 版本协商流程

```
上位机 → >VER<            → [VER_1.0.0]
上位机 → >INFO<           → [INFO_PWMCTROL_3_1.0.0_22118]
（上位机据 INFO 的通道数/主频决定 UI 与误差提示）
```

## 11. 上位机实现要点

### 11.1 发送侧

1. **一次只发一条命令**，等应答或超时（300ms）再发下一条。三条命令并行会拿错应答。
2. 幂等性分级：`STOP` / `RATE` / `ECHO` / `SAVE` 可安全重发；`CONFIG` / `PROG` 重发等价于重新执行（会重置计时），重试前要确认超时确实是丢包而不是慢响应。
3. 拼帧时校验：只允许 `A-Z a-z 0-9 . _ -`，其它字符直接拒绝发送（防止拼装 bug 造成固件解析错乱）。

### 11.2 接收侧

1. 字节流 → 状态机（`SEEK` / `IN_FRAME` / `DELIVER`），只在 `[` 与 `]` 之间取内容；帧外字节计入"噪声字节数"便于诊断。
2. `[` 到达时若上一帧未结束（超 100ms），丢弃上一帧。
3. 分派顺序：`EVT_` → 事件；`ECHO_` → 遥测；`OK_`/`ERR_`/`YES`/`PONG`/`VER`/`INFO`/`STAT`/`ADC` → 命令应答（交给当前等待者）。
4. 收到 `ERR_` 时把原始帧写入日志并显示错误码含义，不要只弹"操作失败"。
5. ECHO 更新按 100ms 合并到 UI，避免 20Hz×3 引发绑定风暴。

### 11.3 显示规范（重要）

- 请求值/生效值分离显示：`50.0% (生效 49.99%)`。
- 频率 > 20kHz 时，占空比输入框旁边提示当前分辨率（见架构文档 6.1 表）。
- 链路统计常驻状态栏：RTT、丢帧数、`echoDrop`、复位原因。

### 11.4 调试友好性

- 日志面板提供"原始/解析"两种视图，可复制单帧。
- 提供"手工发帧"输入框（高级模式），现场排查最快的手段。

## 附录 A：常见联调故障对照

| 现象 | 最可能原因 | 排查 |
| --- | --- | --- |
| 发 `>TYPE-PWMCTROL<` 无 `[YES]` | 波特率/接线反（TX-RX 未交叉）；主频设置与固件不符 | 先用 `>PING<` + 串口助手看是否有任何回显；核对 ISP 里的 IRC 频率 |
| 收到乱码 | 波特率不匹配或主频宏与实际不符 | `>INFO<` 看 `fosc` 字段；22.1184 应为 `22118` |
| 命令有应答但 PWM 无输出 | 引脚未设推挽（STC8H 上电为高阻）、MOS 栅极未下拉、通道处于 FAULT | 万用表量 MCU 引脚；`>GET_<ch><` 看 state |
| ECHO 时断时续 | TX 队列背压或 RATE 太快 | 调大 `RATE`、`>STAT<` 看 `echoDrop` |
| 占空比设 0.1% 实际没变化 | 该频率下分辨率不足 | 看 `[OK_]` 回的 `duty_eff` |
| 到期不关断 | 频率变化路径未重启计时（固件 bug） | 用 `>GET_` 观察 remain；对照 5.4 规则 2/4 |
| 上电瞬间负载抖一下 | 栅极无下拉 / 初始化顺序错（先使能 PWM 后锁电平） | 硬件加 10k 下拉；固件第一句就锁低 |
