## 2. 系统概述

```
│ · 三通道面板 / 曲线       │                                        │ · ADC 采样          │
│ · 预制程序 / 日志         │                                        │ · 失效安全          │
└──────────────────────────┘                                        └──────┬──────────────┘

                                                                     ┌─────▼──────┐

                                                                     │ 栅极 10k↓  │
```

### 2.2 角色与职责

| 角色 | 职责 | 明确不负责 |
| --- | --- | --- |
| 上位机 | 设备识别、参数下装、状态可视化、预制程序选择、日志与导出、链路超时重试 | 不做闭环控制、不参与实时时序 |
| 下位机 | 参数校验、PWM 生成、持续时间计时、ADC 采集、ECHO 上报、失效安全 | 不做复杂 UI 逻辑、不缓存历史曲线 |
| 链路 | 单向命令 + 单向周期上报，无流控信号线 | 不支持硬件流控 |
| 负载侧 | 3 路互相独立 | 通道间无联动、无死区、无互补 |

### 2.3 已确认前提（本次评审确认）

| 编号 | 结论 | 影响 |
| --- | --- | --- |
| P1 | 三路低端驱动带**三个独立负载**，通道间无关联 | 无需死区、无需互补输出、无需换向时序；PROG 场景按独立通道设计 |
| P2 | CONFIG 的"持续时间"单位是 **ms**（原描述 ns 为笔误） | 32 位毫秒计数即可，最大 49.7 天，实现最简 |
| P3 | 频率范围 **1Hz ~ 999kHz**（v0.2 修订，原 0.1Hz~1MHz） | 双引擎：PWMA 硬件（≥21.12Hz）+ Timer0 软件（1~20Hz）；>500kHz 只能命中离散点 |
| P4 | ECHO 上报周期 **50ms** | 带宽占用约 16%，UI 20Hz 刷新足够 |

## 3. 硬件平台与资源约束

### 3.1 芯片能力（STC8H1K08，非 T 版）

| 资源 | 规格 | 对本项目的意义 |
| --- | --- | --- |
| 内核 | 1T 8051，22.1184MHz IRC | 22.1184/115200 = 192，波特率误差 0% |
| Flash | 8KB | 放不下浮点库 + printf，必须整数运算、精简格式化 |
| SRAM | 约 1.2KB（128B data + 128B idata + 1KB xdata） | Keil SMALL 模式下 128B data 是硬瓶颈，缓冲一律 xdata |
| 高级 PWM | 8 通道（PWM1~PWM8），16 位，带互补与死区 | 用 PWM1P/PWM2P/PWM3P 作 3 路独立输出 |
| ADC | **10 位**，9 通道（ADC0/1、ADC8~14），最快 500K | 分辨率 4.88mV@5V，够做电压监视，不够做精密计量 |
| 定时器 | T0/T1/T2 | T0 作 100µs 基础时基（兼软件 PWM），T1 作波特率发生器 |
| 串口 | UART1（P3.0/P3.1）+ UART2 | UART1 用于上位机；UART2 预留调试口 |
| 其他 | 比较器、WDT、IAP/EEPROM 区 | 过流硬件关断、看门狗、配置掉电保存 |

> ADC 精度提醒：同封装 **STC8H1K08T** 才是 12 位 ADC。本机若实物是 1K08（非 T），就按 10 位设计。

### 3.2 硬约束清单（架构必须满足）

| 编号 | 约束 | 后果 / 应对 |
| --- | --- | --- |
| C1 | 同一 PWM 通道的 P/N 输出共用占空比（互补关系），**不能**当两个独立通道 | 3 路独立必须取 **PWM1P / PWM2P / PWM3P**；PWM1N/2N/3N 留作后续半桥扩展 |
| C2 | TSSOP20 上可用 ADC 仅 ADC0、ADC1、ADC8~ADC14 共 9 路；P1.2~P1.7 **无 ADC** 功能 | 3 路电压采集必须落到 ADC10/11/12（P3.2/P3.3/P3.4） |
| C3 | ADC 与 PWM 抢引脚：P1.0 = ADC0 = PWM1P；P1.1 = ADC1 = PWM1N | 选了 P1.0 作 PWM1P，就永久失去 ADC0（本设计无需 ADC0） |
| C4 | UART1 固定占用 P3.0/P3.1，它们同时是 ADC8/ADC9 | 可用 ADC 实际只剩 7 路，其中 3 路给电压采集 |
| C5 | 内部 RAM 仅 256B（direct 128B） | 协议缓冲、TX 队列、ADC 历史全部放 xdata，data 只放热变量 |
| C6 | Flash 仅 8KB，无硬件乘除法以外的高阶运算加速 | 占空比/频率全部用定点整数；禁止 float |
| C7 | 频率与占空比分辨率互斥（见 6.1） | 1MHz 时占空比仅约 22 级（4.5%），协议必须回"实际生效值" |
| C8 | 除 P3.0/P3.1 外，所有 I/O 上电为**高阻输入** | 上电第一件事：把 3 个 PWM 脚锁成推挽并输出低，否则栅极悬空 |
| C9 | P3.5 具备 PWMFLT（硬件故障关断）输入 | 强烈建议接外部过流比较器，做硬件级关断（见 10） |

### 3.3 建议引脚分配

> 封装引脚序号请以最终原理图核对（不同资料对 TSSOP20 的 1/20 脚定义有出入），下表只锁定**端口**。

| 端口 | 复用能力 | 本项目用途 | 备注 |
| --- | --- | --- | --- |
| P1.0 | ADC0 / RxD2 / PWM1P | **PWM CH1 输出**（推挽） | 有效电平=高，导通低端 NMOS |
| P1.2 | T2 / SS / PWM2P | **PWM CH2 输出**（推挽） | 无 ADC，纯 PWM 脚 |
| P1.4 | I2CSDA / MISO / PWM3P | **PWM CH3 输出**（推挽） | 同上 |
| P1.1 / P1.3 / P1.5 | PWM1N / PWM2N / PWM3N | 预留（互补管脚） | 未来半桥方案直接用 |
| P1.6 / P1.7 | PWM4P / PWM4N / PWM5_2 | 预留 | 可做第 4 路或指示灯 |
| P3.0 | ADC8 / RxD / INT4 | **UART1 RX** | 上电为准双向，需重配 |
| P3.1 | ADC9 / TxD | **UART1 TX** | 同上 |
| P3.2 | ADC10 / INT0 / PWMETI | **ADC CH-1 电压**（CH1 负载端/母线） | PWMETI 可用于 PWM 同步触发采样 |
| P3.3 | ADC11 / INT1 | **ADC CH-2 电压** | |
| P3.4 | ADC12 / T0 / PWM4P_2 / CMPO | **ADC CH-3 电压** | 若用于 T0 需重选（T0 用内部计数即可） |
| P3.5 | ADC13 / T1 / PWMFLT | 预留：**硬件故障输入** | 接比较器 OC 输出，双沿触发 |
| P3.6 / P3.7 / P5.4 | ADC14 / CMP- / CMP+ / RST / MCLKO | 预留：按键、LED、蜂鸣器 | P5.4 出厂为 RST，需在 ISP 里改成 I/O |

### 3.4 硬件设计建议（影响固件架构，需一并确认）

1. **栅极必须 10kΩ 下拉到 GND**，保证 MCU 复位/上电/编程期间负载不误导通。这是低端驱动唯一的"物理保险"。
2. **ADC_VRef+ 不可悬空**：接 VCC 或外部基准。若接 VCC，则所有电压换算都以 VCC 为基准，需在协议里上报 VCC 实测值（用 ADC15 内 1.19V 反算）以修正误差。
3. 三路负载的采样点位置要明确：**母线电压**还是**负载端 PWM 波形电压**。后者随占空比变化，必须与 PWM 谷点同步采样（见 8.2），否则读数跳动严重。
4. 建议 P3.5 接一颗比较器（如 LM393）做过流检测，输出接 PWMFLT，实现"硬件在 1 个 PWM 周期内关断"，软件只负责善后。纯软件保护在 22MHz 上无法保证微秒级。
5. 若负载是感性（电机/电磁阀），MOS 漏源并续流二极管、栅极串 22~100Ω、必要时加 RC 吸收。
6. 串口建议加 100Ω 串阻 + TVS；长线或强干扰场合改 RS485（见 Q12）。

## 4. 关键设计决策

| 编号 | 决策 | 备选 | 理由 | 代价 |
| --- | --- | --- | --- | --- |
| D1 | **双 PWM 引擎**：≥22Hz 用 PWMA 硬件，<22Hz 用 T0 软件 PWM | 单一软件 PWM / 单一硬件 PWM | 硬件方案抖动≈0、CPU 占用≈0；软件方案才能到 0.1Hz | 两套代码路径 + 切换时序 |
| D2 | 协议沿用 **ASCII 行帧**（`>` 命令 `<`，`[` 应答 `]`） | 二进制帧（TLV + CRC16） | 可读、可手敲、串口助手上直接调试；与既有项目习惯一致 | 带宽利用率低（约 50%），高密度数据不适合 |
| D3 | 字段分隔符 `_`，保留字符 `_` `>` `<` `[` `]` | 空格 / 逗号 | 与用户给定格式一致；空格在串口助手里易丢 | 字段值不能含下划线（本项目无此需求） |
| D4 | 应答返回**实际生效值**，而非回显请求值 | 回显请求值 | 频率/占空比会被硬件量化，回显会让上位机显示假数据 | 上位机需要做"请求值 vs 生效值"对比提示 |
| D5 | **单一 100µs 时基**（T0），同时驱动软件 PWM、ms 计时、ECHO 节拍 | 多个定时器各管一摊 | T0/T1 已被 T1 占去波特率，T2 留作他用；单时基最省 | 软件 PWM 抖动 1 个 tick（100µs） |
| D6 | 中断只做"搬运与计数"，业务在**主循环无阻塞状态机**里跑 | 在 ISR 里解析/格式化 | 8KB Flash + 慢速 8051，长 ISR 会丢串口字节 | 主循环必须严格非阻塞，禁止 delay |
| D7 | ECHO 由定时器**节拍均匀铺开**（50ms 内 3 帧错开），并带**背压**（TX 队列水位高则丢帧） | 50ms 到点连发 3 帧 | 避免瞬时突发占满 TX；粘包对端更友好 | 单通道刷新率仍为 20Hz |
| D8 | **失效安全默认关断**：上电、复位、看门狗、通信看护超时、参数非法一律输出低 | 保持上次状态 | 三路驱动的是真实功率器件 | 断电重启后不会自动恢复运行（需上位机重下装） |
| D9 | **每通道独立状态机**，CONFIG/PROG 只影响目标通道 | 全局单一状态机 | 三通道业务上独立；STOP 才做全局 | 需要 3 份通道上下文 |
| D10 | 协议**向下兼容可扩展**：可选第 5 字段 state、可选 CRC8、可选 PROG 扩展参数 | 一次定死 | 现场调试时往往要临时加字段 | 解析器要容忍字段数变化 |

## 5. 下位机固件架构

### 5.1 分层

```
┌─────────────────────────────────────────────────────────┐
│ app 应用层     app_channel.c   3 通道状态机 / 时长计时   │
│                app_preset.c    预制程序 0~9 曲线发生器    │
│                app_safety.c    失效安全 / 看护 / 故障处理  │
├─────────────────────────────────────────────────────────┤
│ proto 协议层   proto_rx.c      字节流 → 帧（状态机）      │
│                proto_cmd.c     语义校验 + 分发            │
│                proto_tx.c      应答格式化 + TX 环形队列   │
├─────────────────────────────────────────────────────────┤
│ hal 硬件层     hal_uart.c / hal_pwm.c / hal_adc.c        │
│                hal_tick.c / hal_eeprom.c / hal_gpio.c    │
├─────────────────────────────────────────────────────────┤
│ bsp 板级       board.h（引脚、时钟、常量全部集中）        │
│                stc8h.h（官方寄存器定义）                  │
└─────────────────────────────────────────────────────────┘
```

依赖方向严格向下，`app` 不直接碰寄存器，`hal` 不知道"通道"这个概念。

### 5.2 模块职责

| 模块 | 职责 | 关键约束 |
| --- | --- | --- |
| `hal_tick` | T0 @100µs 中断，维护 `tick32`；提供 `now_ms()` | ISR 内不调用任何格式化函数 |
| `hal_uart` | UART1 初始化（115200，12T + reload 0xFFFC）、RX 环形缓冲入队、TX 中断发送 | RX 缓冲 128B xdata，溢出置 `ovf` 标志 |
| `hal_pwm` | PWMA 初始化、频率+占空比设置、启停、强制电平、软件 PWM 通道 | 频率变化需"关断→重配→重启"，占空比变化可只写 CCR |
| `hal_adc` | 10 位 ADC 初始化、单次/多次平均采样、通道切换 | 采样不能在 PWM 上升沿附近进行 |
| `hal_eeprom` | IAP 读写配置区（3 通道参数 + 全局设置，带校验和） | 写周期内禁止中断访问 Flash |
| `proto_rx` | 帧边界识别、长度上限、错误恢复 | 必须能在"半帧 + 噪声"后自恢复 |
| `proto_cmd` | 参数解析（整数/小数定点）、范围校验、命令分发 | 不做任何耗时动作，只置标志/调 hal |
| `proto_tx` | 应答拼装、ECHO 拼装、发送节流 | 所有输出经同一队列，避免交叉写 SBUF |
| `app_channel` | 3 份通道上下文、到期判定、状态迁移 | 到期关断在 tick 回调里只置标志，关断动作在主循环 |
| `app_preset` | 按程序号生成目标占空比曲线，周期性写 CCR | 曲线按 tick 或按 ms 步进，全部整数 |
| `app_safety` | 上电关断、看门狗喂狗、通信看护、故障锁存 | 任何异常路径都要能到达"全部输出低" |

### 5.3 调度模型

前后台结构，**不引入 RTOS**（8KB Flash 不适合）：

- **中断层**（快进快出，总时长 < 20µs）
  - UART1 RX/TX：单字节入/出队，只碰指针
  - T0 @100µs：`tick32++`；软件 PWM 通道比较；每 10 tick 置 `ms_flag`；ECHO 节拍计数
  - ADC（可选中断）：结果入 8 点滑动窗
- **主循环层**（顺序执行，每项都不阻塞）
  1. `proto_rx_poll()` 取帧并解析
  2. `proto_cmd_dispatch()` 执行命令、生成应答
  3. `app_channel_tick()` 处理到期关断、状态迁移
  4. `app_preset_tick()` 推进曲线
  5. `hal_adc_tick()` 采样本轮需要上报的通道
  6. `proto_tx_pump()` 把队列里的字节喂给发送中断
  7. `app_safety_tick()` 看护、喂狗

### 5.4 中断优先级

| 优先级 | 中断 | 周期 | 允许的最坏时长 |
| --- | --- | --- | --- |
| 最高 | UART1（RI/TI） | 86.8µs/字节 | < 10µs（只搬字节） |
| 高 | T0 | 100µs | < 15µs（含 3 通道比较） |
| 中 | ADC | 按需 | < 10µs |
| 低 | PWMFLT 故障 | 事件 | < 5µs（只置故障位 + 关断使能） |

> 计算依据：100µs 内 22.1184MHz 有 2211 个时钟周期，T0 ISR 用 330 周期即占 15% CPU，留足余量给主循环。

### 5.5 关键数据结构（仅结构定义，非实现）

| 结构 | 字段要点 | 存放区 |
| --- | --- | --- |
| `ch_ctx_t` × 3 | 请求频率/占空比、生效频率/占空比、ARR/PSC/CCR、持续 ms、剩余 ms、状态、ADC 使能、ADC 通道号、上次 ECHO 值 | xdata（约 20B/通道） |
| `proto_rx_t` | 帧缓冲 64B、写指针、状态、溢出标志 | xdata 64B |
| `tx_ring_t` | 256B 环形队列 + 头尾指针 + 水位 | xdata 256B |
| `g_cfg_t` | ECHO 周期、ECHO 使能、看护超时、VCC 校准值、版本 | xdata 16B |
| `adc_win_t` × 3 | 8 点环形窗 + 和 | xdata 约 20B/通道 |

xdata 预算：3×20 + 64 + 256 + 16 + 60 ≈ 456B，占 1KB 的 45%，留有余量给栈（xdata 栈也要算）。

### 5.6 通道状态机

```
        ┌──────────┐  CONFIG/PROG 校验通过 + 启动
        │  OFF (0) │────────────────────────────────┐
        │ 输出低    │                                 ▼
        └──────────┘                          ┌─────────────┐
             ▲                                │ RUNNING (1) │
             │  STOP / 到期 / 故障 / 复位      │ 输出 PWM    │
             │                                └──────┬──────┘
             │                                       │ 持续时间耗尽
             │                                ┌──────▼──────┐
             └────────────────────────────────│ EXPIRED (2) │ 输出低，保留参数
                                              └─────────────┘
                                                     │ 可被再次 CONFIG 唤醒
                                                     ▼ (RUNNING)
        ┌─────────────┐  硬件 PWMFLT / 过压欠压 / 看护超时
        │ FAULT (3)   │◄────── 任意状态；只可由 >STOP< 或复位清除
        │ 输出低，锁存 │
        └─────────────┘
```

状态迁移规则：

- `CONFIG` 在 `RUNNING` 时到达：**占空比变化→平滑生效**（无中断）；**频率变化→关断→重配→重启**（产生一次 < 1 周期的中断），状态保持 RUNNING。
- `EXPIRED` 后该通道 ECHO 上报频率为生效频率、占空比 0.0、state=E。
- `FAULT` 为锁存态，任何 CONFIG/PROG 都被拒（回 `[ERR_E09]`），必须先 `>STOP<`。

### 5.7 命令处理流水线

```
字节 → [RX 环形缓冲] → 帧提取(> ... <) → 长度检查
     → 分词(按 _) → 命令查表 → 参数类型/范围校验
     → 执行(HAL 调用 / 状态置位) → 应答格式化 → [TX 队列] → 发送中断
```

任一环节失败都走"错误码 + 立即应答"，**不允许静默丢弃**（便于上位机定位）。仅当帧长超过 64B 或起始符错误时静默丢弃，并置错误计数器（可 `>STAT<` 读取）。

## 6. PWM 引擎设计

### 6.1 硬件引擎（PWMA）参数求解

公式（STC8H 高级 PWM）：

```
f_pwm = FOSC / (PSC × (ARR + 1))        PSC ∈ 1..16，ARR ∈ 1..65535
duty  = CCR / (ARR + 1)                  CCR ∈ 0..ARR+1
```

给定目标频率 f，求解顺序：**PSC 从 1 递增，取第一个使 ARR+1 ≤ 65536 的值**（保证分辨率最大）。

| 目标频率 | PSC | ARR+1 | 实际频率 | 占空比分辨率 |
| --- | --- | --- | --- | --- |
| 1Hz | 软件引擎 | — | — | 1/10000（100µs 步进） |
| 10Hz | 软件引擎 | — | — | 1/1000 |
| 21.12Hz | 16 | 65536 | 21.1200Hz | 0.0015% |
| 50Hz | 7 | 63195 | 50.0002Hz | 0.0016% |
| 1kHz | 1 | 22118 | 1000.02Hz | 0.0045% |
| 10kHz | 1 | 2211 | 10005.6Hz | 0.045% |
| 20kHz | 1 | 1105 | 20016.7Hz | 0.090% |
| 50kHz | 1 | 442 | 50041.6Hz | 0.226% |
| 100kHz | 1 | 221 | 100082Hz | 0.45% |
| 200kHz | 1 | 110 | 201076Hz | 0.91% |
| 500kHz | 1 | 44 | 502691Hz | 2.27% |
| 1MHz | 1 | 22 | 1005381Hz | **4.55%** |

> 上表按 `ARR+1` 向下取整估算；固件实际取**最接近目标**的整数（四舍五入），个别频点与表中差 < 0.2%（例：20kHz 实测 19998.55Hz）。一切以 `[OK_...]` 回的生效值为准。

**结论（必须在协议里体现）**：协议允许 0.1% 粒度的占空比输入，但硬件只在其可分辨范围内生效。因此：

- 生效占空比 = `round(permille × (ARR+1) / 1000)`，再回算成百分比回给上位机；
- 上位机收到 `[OK_...]` 后应显示"生效值"，并在请求值与生效值偏差 > 0.5% 时给黄色提示；
- 1MHz 场景下不要用占空比做精细调节（改用频率/开关策略）。

### 6.2 软件引擎（< 22Hz）

- 时基：T0 100µs（10kHz）。周期计数 `period_ticks = 1/(f × 100µs)`，1Hz → 10000 tick（16 位够用，实现仍按 32 位写以便将来扩到 0.1Hz）。
- 阈值 `thr_ticks = period_ticks × permille / 1000`，**在配置时一次算好**，tick 内只做整数比较。
- 三个通道共享一个 tick 计数器，各自维护 `cnt`（每 tick 自增，到 `period_ticks` 归零）。
- 抖动：≤ 1 tick（100µs）。对 1Hz 是 0.01% 的影响，可忽略；对 20Hz（周期 50ms = 500 tick）是 0.2%，仍优于切到硬件后能得到的分辨率下限。

### 6.3 引擎选择与切换

```
if f >= 22.0Hz  → HW 引擎 (PWMA)
else            → SW 引擎 (T0)
```

切换流程（避免毛刺）：`关断输出(强制低) → 切换引擎归属 → 参数装载 → 重新使能`。整个切换在主循环里完成，最长 1ms，期间该通道输出低（对加热/LED 无感，对电机是一次极短关断）。

### 6.4 边界处理

| 情形 | 行为 |
| --- | --- |
| 占空比 0.0% | **强制输出低**（不依赖 CCR=0，避开"最小 1 tick 脉冲"的不确定性） |
| 占空比 100.0% | **强制输出高**（CCR=ARR+1 或改 GPIO 强推挽高，需在同一时刻切换，避免半周期误输出） |
| 频率 0 | 非法，回 `[ERR_E02]`（要停就用 STOP） |
| 频率 > 1MHz | 非法，回 `[ERR_E02]`；实测上限 1005kHz 时提示改用 STC8H 系列更高主频 |
| 频率 < 0.1Hz | 非法，回 `[ERR_E02]` |
| 该频率下 ARR+1 < 8 | 拒绝，回 `[ERR_E12]`（分辨率不足 12.5%，没有工程意义） |

### 6.5 精度与抖动预算

| 项 | 指标 | 说明 |
| --- | --- | --- |
| 频率误差（HW） | ≤ 1/(ARR+1)，典型 ±0.005% | 由量化决定，可回算上报 |
| 占空比误差（HW） | ≤ 1/(ARR+1) | 同上 |
| 占空比抖动（HW） | 0（纯硬件） | |
| 占空比抖动（SW） | ≤ 100µs / 周期 | 低频时可忽略 |
| 通道间相位 | 无要求（三个独立负载） | 后续做半桥才需要 |

## 7. 时间管理

| 项 | 设计 |
| --- | --- |
| 时基 | T0 @100µs，`tick32`（32 位，回绕 4.97 天） |
| 毫秒钟 | 每 10 tick 累加 `ms32`（回绕 49.7 天） |
| 持续时间 | 32 位 ms，`永久` = 特殊值 `0xFFFFFFFF`（对应协议 `F`） |
| 计时方式 | 每 ms 递减 `remain_ms`（比记录到期时间戳更省 RAM，3 通道才 12B） |
| 到期动作 | tick 里只置 `expired_flag` 并立即关断输出（安全优先），主循环负责状态迁移与 ECHO 反映 |
| 并发 | 3 通道各自计时独立；`STOP` 一次性迁到 OFF 并清 `remain_ms` |
| 精度 | ±1ms（受主循环延迟影响），对 5s 以上的持续时间可忽略；1~10ms 的短脉冲建议一次只跑一个通道 |

## 8. ADC 子系统

### 8.1 通道映射

| 逻辑通道 | ADC 引脚 | ADC 编号 | 10 位原始满量程 | 用途 |
| --- | --- | --- | --- | --- |
| CH1 | P3.2 | ADC10 | 0~1023 | CH1 负载端/母线电压 |
| CH2 | P3.3 | ADC11 | 0~1023 | CH2 同上 |
| CH3 | P3.4 | ADC12 | 0~1023 | CH3 同上 |

`>CONFIG_..._<adc><` 的 adc 字段：

- `0` = 不采集，ECHO 回 `null`（不占用采样时间）
- `1` = 采集该通道绑定的 ADC（上表默认映射）
- `A<n>` = 显式指定 ADC 编号（多通道共用一个采样点时用，如三路都看母线）

### 8.2 采样时序

- 采样必须在 **PWM 谷点**（输出低电平期间）进行，否则负载端电压随占空比波动，读数会跟占空比走。
- 做法：在 T0 tick 里，当该通道软件计数器处于谷点区间时置"可采样"标志；硬件引擎用 `PWMETI`（P3.2 外部触发）或直接在 ISR 里判断 ARR 状态。
- 采样一次约 4µs（500K 采样率），3 通道 × 8 次平均 = 96µs，占 50ms 周期的 0.2%，完全可接受。

### 8.3 滤波与换算

- 8 点滑动平均（去极值可后置优化），抑制开关噪声。
- 电压换算：`mV = raw × VCC_mV / 1024`。`VCC_mV` 由 ADC15 读内部 1.19V 反算：`VCC_mV = 1190 × 1024 / raw15`，上电测一次，运行中每 10s 复测（温漂）。
- 上报单位统一 **mV 整数**，不带小数，省带宽。

### 8.4 故障判定（可选，默认关闭）

| 判据 | 动作 |
| --- | --- |
| 使能了 ADC 且读数 0（< 50mV）持续 200ms | 判定断线/负载开路，置告警位（不强制停机） |
| 读数 > 设定上限（需配置） 持续 20ms | 判定过压，通道转 FAULT 并关断 |

阈值通过协议扩展字段配置，默认不启用，避免误动作。

## 9. 通信子系统

### 9.1 物理与链路参数

| 项 | 值 |
| --- | --- |
| 接口 | UART1，P3.0 RX / P3.1 TX |
| 波特率 | 115200，8N1，无流控 |
| 时钟 | 22.1184MHz，T1 12T 模式，reload = 0xFFFC，**误差 0%** |
| 单字节时间 | 86.8µs |
| 帧上限 | 64 字节（含 `>`/`<`） |
| 编码 | ASCII，仅允许可打印字符 |

### 9.2 帧解析状态机

```
      任意字节
        │
   ┌────▼─────┐  '>'   ┌──────────────┐  '<'   ┌────────────┐
   │  SEEK    │───────►│  IN_FRAME    │───────►│  DELIVER   │
   │ 丢弃噪声  │        │ 累积到 64B   │        │ 交给 cmd   │
   └────┬─────┘        └──────┬───────┘        └────────────┘
        │ '[' 属下行帧        │ 超长 / 超时(50ms 无后继)
        ▼                     ▼
   下行帧忽略并计数      丢弃整帧 + 回 [ERR_E07]
```

要点：

- 解析器**只认 `>` 起始 `<` 结束**；同时容忍 `[` `]` 形式（兼容旧上位机/手工调试）。
- 帧间隔超时 50ms：一帧没写完就丢弃，防止半帧永久占住缓冲。
- 逐字节推进，不缓存整行，天然处理粘包/拆包。

### 9.3 缓冲与背压

| 缓冲 | 容量 | 水位策略 |
| --- | --- | --- |
| RX 环 | 128B | 主循环每轮必须取空；溢出即丢新字节并计 `ovf` |
| TX 环 | 256B | 水位 > 200B 时**暂停 ECHO**（保命令应答优先）；> 250B 时丢弃最新 ECHO 帧并计 `drop` |

### 9.4 ECHO 调度

- 周期 `T=50ms`（可由 `>RATE_` 改 10~1000ms）。
- 一周期内 **3 帧均匀错开**：`t = T/6, T/2, 5T/6` 各发一帧（默认 8.3/25/41.7ms），避免瞬时突发。
- 只上报 `RUNNING` 或 `EXPIRED` 且使能了 ECHO 的通道；`OFF` 通道不发（省带宽）。
- 上报值与上次相比完全无变化的通道，可选"抑制上报"（`>ECHO_2<` 模式，默认关闭以免上位机误判断线）。

带宽核算（50ms、3 通道均运行、均开 ADC）：

| 项 | 计算 | 结果 |
| --- | --- | --- |
| 单帧长度 | `[ECHO_1_1000.02_50.0_1234]` ≈ 27B + `\r\n` | 29B |
| 每周期字节 | 29 × 3 | 87B |
| 每秒字节 | 87 × 20 | 1740B/s |
| 带宽占用 | 1740 / 11520 | **15.1%** |
| TX 忙时占比 | 87 × 86.8µs / 50ms | 15.1% |

留出 85% 给命令与应答，安全。若把 RATE 改到 10ms，占用升到 75%，此时必须开 ECHO 抑制，否则应答延迟明显。

## 10. 安全与失效处理

| 场景 | 期望行为 | 实现层 |
| --- | --- | --- |
| 上电 / 复位 | 3 路全部输出低，通道状态 OFF，参数从 EEPROM 恢复但不自动运行 | bsp 最早初始化 + app_safety |
| 编程（ISP 下载）期间 | 输出低（靠硬件下拉保证） | 硬件 |
| 看门狗溢出 | 复位 → 回到上电态（全关） | WDT，主循环每轮喂狗 |
| 通信看护超时（`>GUARD_<ms>`，默认关闭） | 全部通道 STOP，ECHO 继续上报 `state=E` 便于诊断 | app_safety |
| 参数非法 | 拒绝，通道保持原状态不变 | proto_cmd |
| 硬件过流（PWMFLT 有效） | **硬件立即封锁输出**，软件在 ISR 里锁存 FAULT，回 `[EVT_FAULT_<ch>]` | hal_pwm + app_safety |
| Flash 配置校验失败 | 用出厂默认值，`>STAT<` 报 `cfg_err` | hal_eeprom |
| 串口断线 | 硬件无感；若开了 GUARD 则超时后全停 | — |
| 主循环卡死（异常） | 看门狗复位（约 1s 内） | WDT |

**失效安全默认值清单**（EEPROM 空片时的出厂态）：`ECHO=1`、`RATE=50ms`、`GUARD=0`、三通道 OFF、freq=1000Hz、duty=0.0%、dur=F、ADC=0。

### 11.2 线程模型

```
SerialPort 读线程 ──字节──► FrameCodec(单线程消费) ──Frame──► Channel<Frame>
                                                                  │

                                     ▼
                       Dispatcher.UIThread.Post(批量刷新 VM)
```

- **绝不**在 UI 线程做字节解析（50ms×3 帧 + 用户连点会卡）。

- 遥测更新按 100ms 合并，避免 20Hz × 3 通道触发 60 次 PropertyChanged 风暴。
- 曲线用固定长度环形缓冲（如 600 点 = 30 秒@20Hz），跨线程只传快照。

## 13. 验收标准与测试计划

### 13.1 协议一致性

| 用例 | 期望 |
| --- | --- |
| `>TYPE-PWMCTROL<` | `[YES]` |
| `>TYPE-OTHER<` | 无应答（不冒认） |
| 字段数错、非数字、负数 | `[ERR_E06]` / `[ERR_E0x]`，通道状态不变 |
| 64B 超长帧 | 丢弃 + `[ERR_E07]` |
| 半帧后断 50ms | 丢弃，链路继续可用 |
| 噪声中插入合法帧 | 正确识别 |

### 13.2 功能边界

- 频率端点：0.1Hz / 21.12Hz / 22Hz（引擎边界）/ 1MHz，各取 0%、0.1%、50%、99.9%、100% 占空比，示波器核对。
- 持续时间：1ms / 5000ms / F，测到期关断时刻误差 ≤ 2ms。
- ADC：断开负载（0V）、接已知电压（如 2.500V），误差 ≤ ±25mV（10 位 + VCC 校准后）。
- 三通道并发：三通道不同频率/占空比同时跑 10 分钟，互不干扰。

### 13.3 稳定性

- 连续运行 24h，ECHO 丢帧率 < 0.1%，无复位（读 `>STAT<` 的复位原因）。
- 拔插串口 20 次，重连成功率 100%。
- 上位机断开 1 分钟后重连，设备仍稳定（GUARD 关闭时不误停）。

### 13.4 安全

- 运行中触发 PWMFLT：输出在 1 个 PWM 周期内关断，ECHO 报 FAULT。
- 运行中按复位：输出立即为低（示波器确认无毛刺）。
- 上位机发非法参数风暴（1000 帧/秒）：设备不重启、不失控。

## 附录 A：与既有项目的经验对齐

本项目沿用同系列项目已验证的几条做法，避免重复踩坑：

- 命令帧 `>` … `<`，应答帧 `[` … `]`，解析器双向容忍（详见 `keil-c51-stc8` 技能 6.1.1）。
- 串口初始化后**立即 `EA = 1`**，不要等主循环前才开，否则初始化耗时（EEPROM/ADC 校准）会漏掉上位机握手帧。
- 22.1184MHz / 115200：12T 模式 reload = `0xFFFC`，注意 `AUXR &= 0x3F`（清 T0/T1 的 12T 位是 bit6/bit7，别只清 bit6）。
- 所有"地址 + 数据包"组装缓冲一律 `xdata`，禁止局部小数组，防止 128B data 越界静默改写相邻变量。
