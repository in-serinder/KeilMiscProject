## 1. 口径变更（相对前两版）

| 项 | 旧 | 新 | 影响 |
| --- | --- | --- | --- |
| 通道号 | 1 / 2 / 3 | **0 / 1 / 2** | 协议、显示、UI 全部对齐面板的 0-2 |
| 频率范围 | 0.1Hz ~ 1MHz | **1Hz ~ 999kHz** | 软件引擎只需覆盖 1~20Hz，负担下降 |
| 过流保护 | 硬件 PWMFLT + 比较器 | **软件限流/过流判定**（已确认放弃硬件方案） | 响应从 µs 级退化到 ms 级，见第 9 章 |
| 面板 | 无 | **8 位数码管 + EC11 + 模式拨码 + 切换按钮** | 新增显示与人机两个子系统，占 Flash/RAM/IO |
| 存储 | 仅内部 Flash | **24C02（256B）存预制程序 + 内部 EEPROM 存配置** | 新增 I2C 子系统与页写约束 |
| 模式 | 无 | **Mode 1 本地 / 2 预制程序 / 3 上位机** | 协议加 `MODE` 命令与 `E13` 权限码 |

## 2. 硬件资源再核算

### 2.1 IO 需求（按最新需求统计）

| 功能 | 脚数 | 备注 |
| --- | --- | --- |
| PWM 输出 ×3 | 3 | P1.0 / P1.2 / P1.4（PWM1P/2P/3P，独立占空比） |
| UART1 | 2 | P3.0 / P3.1 |
| ADC 电压采集 ×3 | 3 | P3.2 / P3.3 / P3.4（ADC10/11/12） |
| 24C02（I2C） | 2 | 硬件 I2C 会抢 ADC 脚，优先软 I2C |
| 8 位数码管 | 2~16 | 取决于驱动方案（见 2.3） |
| EC11 A/B | 2 | 正交解码，必须独立脚 |
| EC11 按键 | 1 | 手势识别 |
| 显示切换按钮 | 1 | 电压 / 占空比切换 |
| 模式拨码（3 档） | 2 | 二进制编码 |
| **合计** | **18~19** | 可用仅 **17** |

### 2.2 缺口

```
可用 IO：P1.0~P1.7（8）+ P3.0~P3.7（8）+ P5.4（1）= 17
需求：  3 + 2 + 3 + 2 + 2~3 + 2 + 1 + 1 + 2 = 18~19
缺口：  1~2 个
```

**这不是可以靠软件绕过的问题**，必须在硬件定型前定案。

### 2.3 三种补齐方案（需你选）

| 方案 | 做法 | 省脚 | 代价 | 评价 |
| --- | --- | --- | --- | --- |
| **A. 数码管走 I2C 型驱动** | 用 TM1650 / HT16K33 之类（2 线），与 24C02 **共用同一条 I2C 总线** | 2 | 需换驱动芯片；总线要分地址 | **最优**，一次补齐 19→17，且自带扫描不占 CPU |
| **B. 按键复用 + 拨码减档** | 长按 EC11 = 切换显示（取消独立按钮）；拨码改 2 档（Mode 2 由 EC11 进入） | 2 | 交互变复杂；Mode 2 进入路径变隐晦 | 可接受，但操作反直觉 |
| **C. 砍 1 路 ADC** | 只采母线电压，放弃 2 路负载电压 | 1~2 | 失去分路电压监视 | 与你"5-7 位显示采集电压"的需求冲突 |

若数码管是 **74HC595（3 线）或 TM1638（3 线）**，则必须选 B 或 C；若已定型为 595，建议 **B**（EC11 长按兼作显示切换），把独立按钮的脚省下来给 24C02。

> 你说"板子已定型，我发原理图"——在原理图到达前，本节按"待确认"处理；固件侧会把这 4 个功能做成**可裁剪宏**（`BOARD_HAS_DISP_BTN`、`BOARD_MODE_SW_BITS`、`BOARD_ADC_CH`、`BOARD_EEPROM_BUS`），换板只改 `board.h`。

### 2.4 引脚分配草案（v2，待原理图定稿）

| 端口 | 功能 | 备注 |
| --- | --- | --- |
| P1.0 | PWM CH0 | 推挽，上电先锁低 |
| P1.2 | PWM CH1 | 推挽 |
| P1.4 | PWM CH2 | 推挽 |
| P1.1 / P1.3 / P1.5 | 数码管（SCL/SDA 或 SER/SCK/RCLK） | 空闲副功能为 PWM1N/2N/3N，不冲突 |
| P1.6 / P1.7 | 24C02 软 I2C（SDA/SCL） | 也可与数码管共总线（方案 A） |
| P3.0 / P3.1 | UART1 RX / TX | 上电即为准双向，需重配 |
| P3.2 / P3.3 / P3.4 | ADC10 / ADC11 / ADC12 | 三路电压采集 |
| P3.5 / P3.6 / P3.7 | EC11 A / B / KEY | EC11 建议 100nF 硬件消抖 |
| P5.4 | 显示切换按钮 或 拨码位 | 出厂为 RST，须在 ISP 里改为 I/O |
| — | 拨码位 2 | 若不足则与上格共用/按方案 B 减档 |

### 2.5 硬件定案清单（我需要的确认项）

1. 数码管驱动：型号、位数、共阴/共阳、段码顺序（A→dp 的位映射）。
2. 数码管是**单独 8 位一体**，还是 2 个 4 位拼接（影响地址与亮度一致性）。
3. 拨码开关实际档位数与接线（2 档还是 3 档）。
4. 蜂鸣器有无（按键反馈缺失时，用数码管整屏闪烁代替）。
5. 电机是否需要**正反转**（若需要，方向控制信号需要额外 IO 或外接继电器/H 桥，见 Q26）。

## 3. 固件总体架构

### 3.1 分层

```
┌──────────────────────────────────────────────────────────────┐
│ app   app_channel.c  通道上下文与状态机（3 份）                │
│       app_preset.c   预制程序曲线（0~9）                       │
│       app_mode.c     模式判定 + 权限闸门                       │
│       app_panel.c    面板：显示内容生成 + 按键手势 + 菜单态     │
│       app_safety.c   软过流、看门狗、通信看护、失效安全         │
├──────────────────────────────────────────────────────────────┤
│ proto proto_rx.c / proto_cmd.c / proto_tx.c                   │
├──────────────────────────────────────────────────────────────┤
│ hal   hal_tick.c  hal_uart.c  hal_pwm.c  hal_adc.c            │
│       hal_disp.c  hal_ec11.c  hal_ee24.c  hal_gpio.c          │
├──────────────────────────────────────────────────────────────┤
│ bsp   board.h（全部引脚/常量/裁剪宏）  stc8h.h                 │
└──────────────────────────────────────────────────────────────┘
```

依赖单向向下：`app_panel` 只读 `app_channel` 的对外接口，不直接碰寄存器；`hal_disp` 不知道"频率"是什么，只接收 8 个字节的段码。

### 3.2 模块职责

| 模块 | 职责 | 关键约束 |
| --- | --- | --- |
| `hal_tick` | T0 @100µs：`tick32`、ms 计数、软件 PWM 比较、显示扫描节拍、人机扫描节拍 | ISR 内禁用任何格式化/整除大数 |
| `hal_uart` | 115200 收发、RX 128B 环、TX 256B 环 | 只搬字节，不解析 |
| `hal_pwm` | PWMA 参数求解、CCR 更新、强制电平、启停 | 频率变化走"关断→重配→重启" |
| `hal_adc` | 10 位 ADC、通道切换、8 点滑窗 | 与 PWM 谷点对齐采样 |
| `hal_disp` | 段码表（code 区）、8 位缓冲、扫描/写驱动芯片、亮度 | 若走 I2C 型驱动，则只在内容变化时写 |
| `hal_ec11` | 正交解码、去抖、手势判定 | 5ms 扫描，不用外部中断（抖动大） |
| `hal_ee24` | 24C02 读/页写、ACK 轮询、跨页拆分 | 页 8B，tWR 10ms |
| `app_panel` | 把通道状态 + 编辑状态翻译成 8 位段码；处理单击/双击/长按/旋转 | 纯逻辑，可单元测试（在 PC 上跑） |
| `app_mode` | 拨码读取、模式切换、权限判定 | `STOP` 永远放行 |
| `app_safety` | 软过流、堵转、通信看护、WDT | 任何分支都能到"全关" |

### 3.3 调度（前后台，无 RTOS）

| 节拍 | 频率 | 内容 | 预算 |
| --- | --- | --- | --- |
| T0 ISR | 100µs | `tick32++`；软件 PWM 三通道比较；每 10 tick 置 `ms_flag`；显示扫描分频 | < 15µs |
| 主循环 A | 每轮 | 协议取帧/解析/分发、TX 泵 | 非阻塞 |
| 主循环 B | 每 1ms | 通道到期判定、软件 PWM 状态迁移、按键扫描、显示刷新 | < 200µs |
| 主循环 C | 每 10ms | ADC 采样、预制程序步进、闪烁相位 | < 300µs |
| 主循环 D | 每 100ms | ECHO 组装、模式去抖、软过流判定、喂狗 | < 500µs |
| 主循环 E | 事件驱动 | 24C02 落盘（延迟写）、SAVE/LOAD | 可阻塞 15ms（此时 PWM 由硬件维持） |

**铁律**：主循环任何一项都不得 `while` 等标志；24C02 的 10ms 写周期放在 E 档，且写之前先把显示内容准备好，避免闪烁。

### 3.4 中断优先级与时间预算

| 优先级 | 中断 | 周期 | 最坏耗时 | 说明 |
| --- | --- | --- | --- | --- |
| 高 | UART1 | 86.8µs/字节 | 8µs | 只入/出队 |
| 中 | T0 | 100µs | 15µs | 软件 PWM + 节拍 |
| 低 | ADC | 按需 | 8µs | 可选，也可主循环轮询 |

数码管如果走 **74HC595**：每 500µs 刷新一位（8 位 → 250Hz 帧率），16 位软件移位约 250 周期 ≈ 12µs，占 CPU 2.4%；建议放在 T0 ISR 的分频里做，避免再加一个定时器。
如果走 **TM1638/HT16K33**：芯片自己扫描，CPU 只在内容变化时写 8 字节，几乎零开销。

### 3.5 三层状态机

```
系统态：  BOOT → SELF_TEST → RUN(Mode1|Mode2|Mode3) → FAULT_SYS
通道态：  OFF → RUNNING → EXPIRED → (再配置) → RUNNING
         任意 → FAULT（锁存，需 STOP 清除）
面板态：  VIEW → EDIT_FREQ ⇄ EDIT_DUTY → VIEW
         VIEW → PROG_SELECT(Mode2) → VIEW
```

三者的关系：系统态决定"谁有权改参数"，通道态决定"输出什么"，面板态决定"数码管显示什么"。

### 3.6 数据流

```
上位机命令 ─┐
EC11/按键  ─┼→ app_mode(权限闸门) → app_channel(参数/状态) → hal_pwm → 引脚
24C02      ─┘                            │
                                         └→ app_panel → hal_disp → 数码管
                                         └→ proto_tx → ECHO（仅 Mode3 主动上报）
ADC → hal_adc → app_channel(电压) → app_panel(显示) / ECHO
```

## 4. PWM 引擎（1Hz ~ 999kHz）

### 4.1 分工

| 区间 | 引擎 | 依据 |
| --- | --- | --- |
| 1Hz ~ 20Hz | T0 软件 PWM（tick 100µs） | 硬件 PWMA 最低 21.12Hz |
| 21.12Hz ~ 999kHz | PWMA 硬件 | 零抖动、零 CPU |
| 20~21.12Hz 死区 | 落软件引擎 | 保证连续，不出现"无引擎可用" |

切换阈值宏 `FREQ_HW_MIN_MHZ = 21120`（毫赫兹），低于它一律软件。

### 4.2 频率求解与"离散命中"

`ARR+1 = FOSC / (PSC × f)`，PSC 取使 `ARR+1 ≤ 65536` 的最小值。**频率不是连续可调，只能命中离散点**：

| 目标 | PSC | ARR+1 | 实际 | 偏差 |
| --- | --- | --- | --- | --- |
| 21.12Hz | 16 | 65536 | 21.1200 | 0% |
| 50Hz | 7 | 63195 | 50.0002 | +0.0004% |
| 1kHz | 1 | 22118 | 1000.02 | +0.002% |
| 20kHz | 1 | 1105 | 20016.7 | +0.08% |
| 100kHz | 1 | 221 | 100082 | +0.08% |
| 500kHz | 1 | 44 | 502691 | +0.54% |
| **999kHz** | 1 | 22 | **1005381** | **+0.64%（且已超出声明上限）** |

> **必须告知用户（Q17）**：>500kHz 之后 ARR 只有 44→22 几档，相邻频率间隔达 20~45kHz，"999kHz" 实际会落到 1005kHz 或 962kHz。建议对外标注 **1Hz~500kHz 精确可调**，500kHz~1MHz 标注"仅离散点"。
> 若你坚持要 999kHz，只能命中 962kHz（ARR=23）或 1005kHz（ARR=22），协议应答里会回真值。

### 4.3 占空比换算

```
CCR = (permille × (ARR+1) + 500) / 1000      // 四舍五入，32 位中间量
duty_eff = CCR × 1000 / (ARR+1)              // 回算给协议
```

`ARR+1 ≤ 1000` 时（约 f > 22kHz）会出现多个 permille 落到同一 CCR，此时 `duty_eff` 与请求值不等——**这正是协议要求回生效值的原因**。

### 4.4 边界

- `permille = 0` → 强制低（关断），不走 CCR。
- `permille = 1000` → 强制高（常通），不走 CCR。切换时先关后开，避免半周期毛刺。
- 频率变化时：`关断 → 停计数器 → 改 PSC/ARR → 重载 CCR → 启动`，全程 < 1ms。
- 三通道共用 PWMA 时基？**不共用**。PWMA 的 PWM1/2/3 共享同一个计数器（ARR/PSC 相同），这是硬约束：**三通道频率必须相同，占空比可各自不同**。

> ⚠️ 这条极其重要，必须现在确认：STC8H 高级 PWM 的 PWM1~PWM4 属于同一个 PWMA 单元，共享 ARR 与 PSC。若三通道需要**不同频率**（协议允许，示例也写了 50Hz/5Hz/20kHz 并发），则硬件引擎只能给一个通道用，另外两个必须走软件引擎——那 CPU 与抖动都会变差。
>
> 可选解法：
> 1. **限制为"三通道同频"**（电机设备通常够用）——最简单，全部硬件，零抖动。
> 2. 一路硬件 + 两路软件（软件引擎需扩到 999kHz，不可行，故软件路只能限制在 ≤2kHz）。
> 3. 换带 PWMA+PWMB 的型号（如 STC8H3K 系列），两个独立时基。
>
> 这一条可能推翻"三通道任意频率"的既有假设，请务必先定（Q16）。

## 5. 显示子系统（8 位数码管）

### 5.1 位分配

| 位 | 常态内容 | dp 语义 | 备注 |
| --- | --- | --- | --- |
| D1 | 频率 百位/首位 | **亮 = kHz 单位**（灭 = Hz） | 单位指示 |
| D2 | 频率 十位/次位 | 小数点（需要时） | |
| D3 | 频率 个位/末位 | 小数点（需要时） | |
| D4 | **Mode**（1/2/3） | **常亮 = 该位为 Mode** | 你指定的语义 |
| D5 | 参数 首位 | 小数点 | 电压 / 占空比 |
| D6 | 参数 次位 | 小数点 | |
| D7 | 参数 末位 | 小数点 | |
| D8 | **预制程序号 0~9** | **亮 = 显示通道号 0~2** | EC11 按下/旋转后 2s 内显示通道号 |

### 5.2 各字段编码

**频率（D1~D3，3 位有效数字 + 变位小数点）**

| 实际频率 | 显示 | dp |
| --- | --- | --- |
| 1Hz | `  1` | 无 |
| 50Hz | ` 50` | 无 |
| 999Hz | `999` | 无 |
| 1.5kHz | `1.50` | D1 亮（kHz）+ D2 小数点 |
| 20kHz | `20.0` | D1 亮 + D2 dp |
| 100kHz | `100` | D1 亮 |
| 999kHz | `999` | D1 亮 |

规则：<1000Hz 用整数 Hz；≥1000Hz 用 kHz 且保留 3 位有效数字。这样 1Hz~999kHz 全程只需 3 位数字。

**Mode（D4）**：`1` / `2` / `3`，dp 常亮。
**参数区（D5~D7）**，由"切换按钮"或长按在两种之间切：

| 显示内容 | 格式 | 例 | 小数点 |
| --- | --- | --- | --- |
| 电压 | `X.XX` V | `5.00` / `0.85` | D5 后 |
| 占空比 | `0`~`100`（整数，右对齐、首位消隐） | `  5` / ` 50` / `100` | 无小数 |

> 电压用 V 而非 mV：10 位 ADC（4.9mV/LSB）配 2 位小数足够，且 3 位刚好装下 0.00~5.00。

**D8**：常态显示当前运行的预制程序号（0~9，未运行为 `-`）；按下/旋转 EC11 后 2s 内改为显示**通道号**并把 dp 点亮。

### 5.3 闪烁规则

- 被编辑的字段以 **2Hz** 闪烁（亮 250ms / 灭 250ms），由 10ms 档软件计数生成相位，不占额外定时器。
- 闪烁只作用于"正在编辑的那 3 位"，其余位稳定显示。
- 模式或通道切换时整屏闪 2 次（每次 100ms），作为无蜂鸣器时的操作反馈。
- 告警（FAULT）时 D4 与 D8 同时慢闪（1Hz），直到 STOP 清除。

### 5.4 刷新策略

- 显示内容是"8 个字节的段码 + 8 个 dp 位"，由 `app_panel` 在**内容变化时**才重算，主循环每 10ms 比对一次，变化才下发。
- 若为 595 方案：`hal_disp` 维护 `buf[8]`，T0 分频 500µs 扫一位，256 步完成一帧（250Hz，肉眼无闪）。
- 若为 I2C 型驱动：只在 `buf` 变化时写 8 字节，代价约 1ms（400kHz 下）。

### 5.5 段码

段码表放 `code` 区（`const uint8_t code SEG_DIGIT[10]`），共阴/共阳由宏 `DISP_ACTIVE_LOW` 决定，取反在初始化时一次性生成到 `xdata` 镜像（省 ROM）。
字符集：`0-9`、`-`（未运行）、空白；不实现字母表，避免 1KB 级字库。

## 6. 人机交互（EC11 + 切换按钮 + 拨码）

### 6.1 EC11 解码

- 5ms 轮询 A/B 两相，4 状态正交表（`prev<<1 | cur`）判方向，**每 4 个边沿计 1 格**。
- 消抖：连续 2 次采样一致才认；建议硬件 100nF + 10k 上拉。
- 加速度：格间间隔 < 30ms 视为快转，步进 ×10。

### 6.2 手势

| 手势 | 判定 | 动作 |
| --- | --- | --- |
| 旋转 | — | 改当前编辑值（或 Mode2 下选程序号） |
| 单击 | 按下 < 800ms，释放后 350ms 内无第二次按下 | Mode1：频率 ↔ 占空比 切换编辑焦点；Mode2：启动/停止当前程序 |
| 双击 | 两次按下间隔 < 350ms | 切换通道 0→1→2→0，D8 显示通道号 2s |
| 长按 | 按住 > 1200ms | **Mode1：启动/停止当前通道**（必须有，否则本地无法开机）；同时可兼作"切换显示内容"（若方案 B 缺按钮） |

> 需要你确认：Mode1 下的**启停**用长按，是否符合你的操作习惯？（Q20）

### 6.3 编辑态

```
VIEW ──单击──> EDIT_FREQ ──单击──> EDIT_DUTY ──单击──> VIEW
                 │ 旋转            │ 旋转
                 └ 改频率（立即生效）└ 改占空比（立即生效）
```

步进档位（按当前量级自适应，避免转 200 圈才到目标）：

| 频率 | 步进 | 快转 |
| --- | --- | --- |
| < 100Hz | 1Hz | 10Hz |
| < 1kHz | 10Hz | 100Hz |
| < 10kHz | 100Hz | 1kHz |
| < 100kHz | 1kHz | 10kHz |
| ≥ 100kHz | 10kHz | 100kHz |

占空比：0.1% 步进，快转 1%，范围夹在 0.0~100.0。

### 6.4 参数生效与落盘

- 旋转即生效（电机调速需要即时手感），但 **24C02/EEPROM 落盘延迟到停止操作 2s 后**，避免每格写一次 Flash。
- 落盘前比较：与已存值相同则不写（省寿命）。

## 7. 模式管理

### 7.1 定义

| Mode | 名称 | 参数来源 | 面板可编辑 | 上位机可写 |
| --- | --- | --- | --- | --- |
| 1 | 本地面板 | EC11 直接写通道参数 | ✅ | ❌（`E13`） |
| 2 | 预制程序 | 24C02 中的程序记录 | 只能选程序/启停 | ❌（`E13`） |
| 3 | 上位机 | 串口命令 | ❌（只显示） | ✅ |

### 7.2 权限矩阵

| 操作 | Mode1 | Mode2 | Mode3 |
| --- | --- | --- | --- |
| EC11 旋转 | 改参数 | 选程序号 | 无（显示通道号） |
| EC11 单击 | 切编辑焦点 | 启停程序 | 切显示内容 |
| EC11 双击 | 切通道 | 切通道 | 切通道 |
| EC11 长按 | 启停通道 | 启停程序 | 无 |
| 上位机 `CONFIG`/`PROG` | `E13` | `E13` | 生效 |
| 上位机 `STOP` | **生效** | **生效** | **生效** |
| 上位机 `MODE_n` | 需与拨码一致 | 同 | 同 |

`STOP` 全模式放行——面板卡死或误操作时，上位机必须能刹车。

### 7.3 切换行为

- 物理拨码优先：读到的档位就是当前模式，`>MODE_n<` 与拨码不一致时回 `E13`。
- 切模式**不改变输出**：从 Mode3 切到 Mode1，PWM 继续按原参数跑，只是改由面板接管。
- Mode2 进入时若该通道无程序记录，D8 显示 `-`，不自动启动。
- 上电默认 = 拨码档位；若拨到 Mode3 但 30s 内无合法帧，降级为 Mode1（防误拨导致"无人可控"）。

### 7.4 拨码读取

2 位二进制（00/01/10 → Mode1/2/3，11 保留=Mode1），每 100ms 读一次，连续 3 次一致才切换（防抖）。
拨码变化时主动上报 `[EVT_MODE_<n>]`。

## 8. 存储子系统（24C02）

### 8.1 物理约束

| 项 | 值 | 影响 |
| --- | --- | --- |
| 容量 | 256B | 必须精打细算，见分区表 |
| 页大小 | **8B** | 页写跨页会回卷覆盖，必须按 8B 对齐拆包 |
| 写周期 tWR | **10ms**（24C01/02） | 写完必须等或 ACK 轮询，主循环不能死等 |
| 地址宽度 | 1 字节片内地址 | 简单 |
| 擦写寿命 | 100 万次（保守 10 万） | 必须"变化才写 + 延迟写" |

### 8.2 分区表（256B 用满）

| 地址 | 长度 | 内容 |
| --- | --- | --- |
| 0x00 | 8 | 头：`'P''W''M''C'` + 版本 + 通道数 + 校验和 |
| 0x08 | 8 | 全局：默认模式、亮度、ECHO 周期、标志位、预留 |
| 0x10 | 16 | 通道 0 参数 |
| 0x20 | 16 | 通道 1 参数 |
| 0x30 | 16 | 通道 2 参数 |
| 0x40 | 160 | 预制程序 0~9（每 16B） |
| 0xE0 | 32 | 预留：用户配方 / ADC 校准 / 设备序列号 |

**通道参数 16B 布局**：`freq_mhz(4)` `duty_permille(2)` `dur_ms(4)` `adc_sel(1)` `preset(1)` `state_flags(1)` `crc8(1)` `reserved(2)`

**预制程序 16B 布局**：`prog_no(1)` `ch_mask(1)` `base_freq_mhz(4)` `base_duty(2)` `p1(2)` `p2(2)` `cycle_ms(2)` `crc8(1)` `rsv(1)`

### 8.3 写策略

1. **只在显式/延迟事件写**：面板停止操作 2s、上位机 `>SAVE<`、Mode2 启动新程序时记录"最近使用"。
2. **变化才写**：整块 8B 比对，相同跳过。
3. **ack 轮询**：写完轮询 ACK（最多 20ms），超时置 `E11` 错误计数，不阻塞主循环（状态机化）。
4. **读回校验**：写完立即读回比对，不符则重写一次，再失败置故障标志。
5. 上电加载时校验 CRC，失败则用出厂默认并置 `cfg_err`（`>STAT<` 可见）。

### 8.4 与内部 EEPROM 的分工

STC8H 片内有 4KB IAP/EEPROM 区，用它存**设备配置**（模式、亮度、校准值等小数据），24C02 专存**预制程序**（用户可换片/复制）。好处：

- 换 24C02 不影响设备基本设置；
- 片内 EEPROM 写更快，适合频繁变更的配置；
- 两份数据互不牵连，掉电恢复逻辑简单。

> 若你希望"完全按你的设想，全部存 24C02"，也可以——只需删掉 `hal_iap` 一层，配置与程序共用 24C02 的分区。

## 9. 软件过流 / 超限保护（替代硬件方案）

已确认放弃 P3.5 + 比较器的硬件关断，因此保护能力必须如实标注。

### 9.1 可用判据

| 判据 | 手段 | 响应时间 | 能防什么 |
| --- | --- | --- | --- |
| 母线电压跌落 | ADC 采母线，跌 >10% 持续 5ms | ~5ms | 严重过载、堵转 |
| 占空比限幅 | 配置 `MAX_DUTY`（如 95%）跑电机 | 立即 | 避免长时间全导通过热 |
| 软启动斜坡 | 启动 300ms 内占空比线性上升 | — | 启动冲击电流 |
| 堵转计时 | 相同占空比下电压持续偏低 500ms | 500ms | 堵转 |
| 看门狗 | WDT 溢出复位（全关） | 1s | 固件跑飞 |

### 9.2 响应与锁存

判定成立 → 立即 `hal_pwm` 强制低 → 通道转 `FAULT` → 上报 `[EVT_FAULT_<ch>]` → 只有 `>STOP<` 或复位可清除。

### 9.3 能力边界（必须写进用户手册）

- **不能保护短路**：短路电流在 µs 级上升，软件 5ms 级反应时 MOS 已经炸了。短路保护只能靠硬件（保险丝、自恢复保险、比较器）。
- **不能替代电流环**：没有采样电阻就测不到电流，所谓"过流"实际是"电压跌落推断"。
- 若负载是昂贵的电机或大功率 MOS，**强烈建议二期补一颗比较器 + 采样电阻**（我们已把 P3.5 的 PWMFLT 能力记录在案，改板时可直接接回）。

## 15. 我对你原描述的几点质疑（请你判断）

1. **"前三位显示频率"** 只够 3 位数字，而你的量程跨 6 个数量级（1Hz~999kHz）。必须引入单位指示与变位小数点，否则 1.5kHz 和 150Hz 显示无法区分。我在 5.2 给了方案，需要你确认。
2. **"5-7 位显示电压/占空比"** 也是 3 位：占空比 100.0% 装不下，电压 5000mV 装不下。我改成 "V 两位小数" 与 "100% 无小数"。
3. **"Mode 用第 4 位 + dp"** 语义清楚，但 **Mode 的切换本身没有输入源**——你的描述里只有 EC11 和"切换按钮"（那是切显示内容的）。我已按"独立拨码开关"设计，会占 2 个 IO，而 IO 已经不够，所以 Q26/Q22 必须回答。
4. **"三个通道"** 若真要跑电机，通常还需要**方向**或**刹车**信号；纯低端 PWM 只能单向调速。若你的电机是单向（风扇、水泵、加热），没问题；若是双向，硬件要改。
5. **24C02 只有 256B**，存 10 条预制程序已是上限（每条 16B 用掉 160B），再加配置就满了。若将来程序要带更多参数，直接上 24C32/24C64（引脚兼容，只改地址宽度）。

| 1 | **P1.0 既是 MAX7219 的 LOAD，又是 PWM1P 输出** | PWM1 通道**只能使能 N 输出**（CC1NE），CC1E 必须保持关闭；否则数码管会跟着 PWM 乱码。建议下一版把 LOAD 挪到 P3.4 |
| 2 | 三路 PWM 全部来自 PWMA（PWM2P / PWM4N / PWM1N），**共用 ARR+PSC** | 三通道**必须同频**、占空比各自独立。这是硬件决定的，不是软件选择（详见 4.4 与 Q16） |
| 3 | EC_B 占用了 PWMFLT（硬件故障输入） | 与"放弃硬件过流"的决策一致，但意味着：**本板永远不具备硬件级短路保护**，只能靠保险丝 + 软件 5ms 级判定 |
| 4 | 24C02 挂在 I2C 默认引脚组（P1.4/P1.5） | 可直接用硬件 I2C，400kHz 下写 8B 约 0.2ms + 10ms 器件忙；**不需要软 I2C** |
| 5 | 只有 1 路 ADC（P3.6/ADC14），是独立引出的"电压表" | ECHO 的 `adc` 字段语义降级为"是否附带探头读数"，不再表示"每通道独立采样" |
| 6 | ADC_VRef+ 直接接 VCC | 电压换算 = `raw × VCC / 1024`，必须用内部 1.19V（ADC15）反算 VCC 做补偿，否则 5V±5% 会带来 ±5% 读数误差 |

### 16.3 显示方案修订（取代 §5.2 的频率表）

原方案"D1 的 dp 固定作 kHz 单位灯"与"1.50 kHz 需要小数点在 D1 之后"冲突。改为**小数点位置编码单位**，8 个 dp 各有明确用途，不再需要单独的单位灯：

| 显示 | 取值范围 | 含义 |
| --- | --- | --- |
| `123` | 1 ~ 999 | 整数 Hz（无小数点 = Hz） |
| `1.50` | 1.00 ~ 9.99 kHz | 小数点在 D1 后 |
| `20.0` | 10.0 ~ 99.9 kHz | 小数点在 D2 后 |
| `100.` | 100 ~ 999 kHz | 尾点即单位标记 |

规则一句话：**频率区出现小数点就是 kHz，位置决定量级；不出现就是 Hz。** 100kHz 以上的尾点虽略丑，但语义唯一、覆盖全量程，且该频段本来只用于特殊场合。

其余字段不变：D4 = Mode（dp 常亮）、D5-D7 = 电压 `X.XX`V 或占空比（**整数 0~100，右对齐、首位消隐**：`5`→`  5`、`50`→` 50`、`100`→`100`）、D8 = 程序号（dp 亮 = 通道号）。

> 占空比为什么不用 `50.0`：三位数字配一个小数点，视觉上极易读成 `500`（实际发生过）。改成整数百分比后不再有歧义；代价是面板分辨率为 **1%**，0.1% 的精细调节只在上位机侧体现。若确实需要面板显示 0.1%，只能借 D8 的一位（会牺牲程序号/通道号显示）。

### 16.4 对协议的影响

| 项 | 影响 |
| --- | --- |
| 通道号 | PWMCTL_0/1/2 与协议 0/1/2 一一对应，无映射 ✓ |
| `adc` 字段 | `0` = ECHO 不带电压；`1` = 带探头读数；`A14` = 显式指定（只有 ADC14 实际可用） |
| 三通道频率 | 若目标板按现状实现，`CONFIG` 改某通道频率时，**三通道同步变频**（硬件共用时基），应答回的都是同一个 freq。上位机需提示 |
| 硬件过流事件 | `EVT_FAULT` 只可能由软件判定产生，不会再出现"硬件瞬断" |

### 16.5 建议的下一版改动（不影响现在做靶）

1. LOAD 从 P1.0 挪到 P3.4，彻底消除与 PWM1P 的复用之争。
2. 若将来要硬件过流保护，需腾一个脚（P1.6 或 P5.4）接比较器输出，或用更大封装。
3. P3.4/P5.4/P1.6 三个空脚建议定为：拨码位1、拨码位2、蜂鸣器，并在丝印上标明。
