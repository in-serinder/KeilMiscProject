# 24Cxx 多路 EEPROM 烧录器 · 下位机固件

MCU：**STC8G1K08A**（1T 内核，22.1184MHz 内部 IRC，8K Flash / 256B idata / 1K xdata）
编译器：Keil C51（uVision 5，C51 V9.59）
协议：帧格式、命令、流程与 `lower-level_simulation/CMD.md` 完全一致。
**唯一的差别**：模拟器把"槽位地址 → 芯片型号"写死成一张测试表（0x50=24C01…），
本固件把两者解耦，型号按实际板子配置（默认全部 24C64），详见第 5 节。

当前构建结果（`UV4 -b`）：

```

0 Error(s), 0 Warning(s)
```

## 2. 引脚分配

| 功能 | 引脚 | 端口模式 | 说明 |
| --- | --- | --- | --- |
| UART1 RXD / TXD | P3.0 / P3.1 | 准双向 | 115200 8N1 |
| I2C SCL / SDA | P3.2 / P3.3 | 准双向 | **`P_SW2.I2C_S = 00`**（STC8G1K08A 专用表），外接 4.7k 上拉 |
| TM1637 CLK / DIO | P5.4 / P5.5 | 推挽输出 | 沿用原工程引脚（P5.4 出厂默认是 I/O） |
| EEPROM WP0 / WP1 | P3.4 / P3.5 | 推挽输出 | 低电平 = 允许写；8 脚封装没有这两个脚，等于空操作 |

> **引脚冲突已修正**：原 `HW_24c64.h` 把 `IC0_WP/IC1_WP` 定义在 P5.4/P5.5，和
> `TM1637.h` 的 CLK/DIO 撞车（两处不可能同时工作）。现 WP 挪到 P3.4/P3.5；
> 若板子上 WP 直接接地，把 `CFG_EEPROM_WP_ENABLE` 置 0。
>
> ⚠️ **I2C 引脚组因芯片而异，这是最容易踩的坑**：
>
> | 芯片 | I2C_S=00 | 01 | 10 | 11 |
> | --- | --- | --- | --- | --- |
> | **STC8G1K08A / 08-8Pin** | **P3.2/P3.3** | P5.4/P5.5 | 无 | **无（保留）** |
> | 其它 STC8G（如 1K17A） | P1.5/P1.4 | P2.5/P2.4 | P7.7/P7.6 | P3.2/P3.3 |
>
> 08A 上把 `I2C_S` 写成 11 是**保留值**：I2C 不接任何引脚，
> 结果是 SCL 完全不动（指示灯不亮）、`I2CRXD` 恒读 **0xFF**、ACK 又恰好被判成 0 所以不报错。
> 现在 `board.h` 用 `CFG_MCU_IS_08A` 自动选对这张表。

## 4. 协议实现

### 4.1 帧格式

```
>内容<\r\n
```

* `>` 之前的一切字节（含孤立 CR/LF）当噪声丢弃；
* 帧内出现 `\r` / `\n` → 该帧判非法，回 `R-ERR`；
* 内容超长（>63 字节）→ 丢弃并回 `R-ERR`；
* 数据字节 ASCII 十六进制，两位一组、逗号分隔、大小写不敏感，发送统一大写。

### 4.2 命令与状态

| 上位机 → | MCU → | 进入状态 | 备注 |
| --- | --- | --- | --- |
| `>ROUTER_0x50<` | `R-S` / `R-ERR` | `ST_ROUTER_SET` | 只接受 0x50~0x57，且必须在本器件表内 |
| `>EDGE_0x1FFF<` | `R-S` / `R-ERR` | `ST_EDGE_SET` | 必须先有 ROUTER；EDGE ≤ 该器件最大地址 |
| `>INT_R<` | `R-S` | `ST_READ_WAIT` | 必须处于 `ST_EDGE_SET`，随后 MCU 主动推包 |
| `>INT_W<` | `R-S` | `ST_WRITE_WAIT` | 同上 |
| `>W_[16字节]<` | 先 `RX-OK`，再 `R-S`/`R-ERR` | `ST_WRITE_CURR`→`ST_WRITE_OVER` | 失败时地址不增加并回 IDLE |
| `>RX-OK<` | —（读流程内部消化） | — | 顶层收到单独的 RX-OK 回 `R-ERR` |
| `>TX-OVER<` | `R-S` | `ST_IDLE` | 只允许在 `WRITE_WAIT/WRITE_OVER` |
| `>ABORT<` | `R-S` | `ST_IDLE` | 任意状态可中止 |
| `>TYPE_ECHO<` | `YES` | 不变 | 多设备总线上确认目标设备 |
| `>DISP_TEST<` | `YES` / `R-ERR` | 不变 | **调试用**，见 9.1：引脚受控回 YES 并点亮 8.8.8.8 |
| `>I2C_TEST<` | `YES` / `R-ERR` | 不变 | **调试用**：只探测当前槽位器件是否 ACK，不读写数据 |
| `>SCAN<` | `>SCAN_[XX]<` | 不变 | **调试用**：扫描 0x50~0x57，位掩码 XX（bit0=0x50…bit7=0x57），1 = 该地址有器件应答 |

状态机：

```
        ROUTER           EDGE            INT_W            W_ 包
 IDLE ────────> ROUTER_SET ────────> EDGE_SET ────────> WRITE_WAIT ────> WRITE_CURR
  ^                 │                   │                   │                │
  │                 │                   │  INT_R            │                v
  │                 │                   └──────> READ_WAIT   │           WRITE_OVER
  │                 │                          │  ^          │   TX-OVER/出错  │
  │                 └── 任何错误 / ABORT ───────┴──┘          └────────────────┘
  └──────────────── 读流程结束(TX-OVER) / 2s 超时(R-ERR) / ABORT
```

### 4.3 读流程

```
上位机 -> >ROUTER_0x50<   MCU -> R-S
上位机 -> >EDGE_0x1FFF<   MCU -> R-S
上位机 -> >INT_R<         MCU -> R-S
循环：
    MCU -> >R_[16字节]<           // 有效字节 n = min(16, EDGE-addr+1)，其余补 0x00
    上位机 -> >RX-OK<             // 2s 内必须回
    addr += n
最后一包确认后：
    MCU -> >TX-OVER<              // 然后回 IDLE（EDGE 被清，下次要重发 ROUTER+EDGE）
```

* 2s 超时 / 收到非 `RX-OK` 帧 → 回 `R-ERR` 并回 IDLE；
* 读 I2C 出错（NACK）→ 回 `R-ERR` 并回 IDLE；
* 读过程收到 `ABORT` → 回 `R-S` 并回 IDLE（模拟器没有这条，属实物增强）。

### 4.4 写流程

```
上位机 -> >ROUTER_0x50<   MCU -> R-S
上位机 -> >EDGE_0x1FFF<   MCU -> R-S
上位机 -> >INT_W<         MCU -> R-S
循环：
    上位机 -> >W_[16字节]<
    MCU -> >RX-OK<                // 整包已收下
    MCU -> 写 I2C（按页拆分）+ 写周期等待
    MCU -> >R-S< / >R-ERR<        // 只有收到 R-S 才发下一包
最后一包后：
    上位机 -> >TX-OVER<   MCU -> R-S，回 IDLE
```

* 只把前 n 个字节写进 EEPROM，填充的 `0x00` 不会写到 EDGE 之后；
* 写失败（NACK）→ 地址不增加，回 `R-ERR` 并回 IDLE（已写入的字节保留）。

### 4.5 边界规则（与模拟器一致）

| 规则 | 实现位置 |
| --- | --- |
| 当前地址从 0x00 开始 | `cmd_int_r()` / `cmd_int_w()` 里 `s_addr = 0` |
| 有效长度 `n = min(16, EDGE - addr + 1)` | `pkt_len()` |
| 写只写 n 字节，读缺的补 0x00 | `cmd_w()` / `run_read()` |
| 地址按 n 自增（不是固定 +16） | `s_addr += n` |
| `addr > EDGE` 即任务结束 | `run_read()` / `cmd_w()` 的防御分支 |
| 非法参数、越界、状态不匹配、超时统一 `R-ERR` | `reply_err()`，不维护错误码 |

## 5. 24Cxx 器件表（槽位地址 ≠ 芯片型号）

**槽位地址和芯片型号是两件事**，固件里分开配置：

* `ROUTER_0x50` 只决定 I2C 从机地址（0x50~0x57）；
* 该槽位插的是什么片子，由 `HW_24c64.c` 里的 `EE_SLOT_TYPE[8]` 决定。

```c
/* 索引 = I2C 地址 - 0x50，默认 8 个槽位都是"2 字节地址、不限容量" */
code uint8_t EE_SLOT_TYPE[8] =
{
    EE_SLOT_CHIP_DEFAULT, EE_SLOT_CHIP_DEFAULT,   /* 0x50 0x51 */
    EE_SLOT_CHIP_DEFAULT, EE_SLOT_CHIP_DEFAULT,   /* 0x52 0x53 */
    EE_SLOT_CHIP_DEFAULT, EE_SLOT_CHIP_DEFAULT,   /* 0x54 0x55 */
    EE_SLOT_CHIP_DEFAULT, EE_SLOT_CHIP_DEFAULT    /* 0x56 0x57 */
};
/* 默认值在 HW_24c64.h：EE_SLOT_CHIP_DEFAULT = EE_CHIP_24C1024 */
```

`EE_CHIP_24C1024` 在这里的作用是**"2 字节地址的最大型号"**：片内地址 2 字节、
EDGE 上限 0x1FFFF。这样 **24C32 / 64 / 128 / 256 / 512 / 1024 插到任何槽位都能直接用**，
不用为每种容量重新烧固件：

* 地址宽度一样（都是 2 字节），所以读写时序完全一致；
* 每次最多写 16 字节且地址 16 对齐，而器件页最小 32 字节，**永远不可能跨页**，
  所以页大小差异对协议没有影响。

只有 **24C01 / 02 / 04 / 08 / 16**（片内地址 **1 字节**）必须显式配置，否则会多送一个
地址字节，片子把地址当数据收，读写全错。

混装板子（每个槽插不同片子）直接改这个数组，例如：

```c
{ EE_CHIP_24C01, EE_CHIP_24C08, EE_CHIP_24C16, EE_CHIP_24C64,
  EE_CHIP_24C128, EE_CHIP_24C256, EE_CHIP_24C512, EE_CHIP_24C1024 }
```

型号库（`EE_TYPES[]`，单位：字节）：

| 型号 | 容量 | 最大地址 | 片内地址字节 | 页大小 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 24C01 | 128B | 0x0007F | 1 | 8 | A2A1A0 全做片选 |
| 24C02 | 256B | 0x000FF | 1 | 8 | |
| 24C04 | 512B | 0x001FF | 1 | 16 | 高位地址占器件地址 bit1 |
| 24C08 | 1KB | 0x003FF | 1 | 16 | 高位地址占器件地址 bit2:1 |
| 24C16 | 2KB | 0x007FF | 1 | 16 | 高位地址占器件地址 bit3:1 |
| 24C32 | 4KB | 0x00FFF | 2 | 32 | |
| 24C64 | 8KB | 0x01FFF | 2 | 32 | |
| 24C128 | 16KB | 0x03FFF | 2 | 64 | |
| 24C256 | 32KB | 0x07FFF | 2 | 64 | |
| 24C512 | 64KB | 0x0FFFF | 2 | 128 | |
| **24C1024（默认）** | **128KB** | **0x1FFFF** | **2** | **256** | A16 走器件地址 A1（`EE_1024_A16_MASK`）；作默认值 = "2 字节地址不限容量" |

> ⚠️ **两次踩过的坑**（现象都是 `EDGE` 回 `R-ERR`）：
> 1. 上一版按"地址→型号"硬查表（沿用模拟器测试表 0x50=24C01，上限 0x7F），
>    板上 0x50 是 24C64 时 `EDGE_0x00FF` 就被拦；
> 2. 上一轮默认值改成 24C64 后，0x57 插 24C128 时**写入能成**（EDGE 0x1A9D < 0x2000），
>    但**读全片 16KB 时 EDGE 0x3FFF > 0x1FFF → R-ERR**。
>
> 现在默认取 24C1024（上限 0x1FFFF），2 字节地址系列全都能跑，这类"写成功读报错"
> 不会再出现。
>
> 配置错了的后果：EDGE 上限判断不对 + 页写拆分不对（会写坏数据），
> 所以换料一定要同步改 `EE_SLOT_TYPE`。

**关于 24C04/08/16**：这类器件只有 1 字节片内地址，高位地址由器件地址低位承载，
所以它们会占用 2/4/8 个连续 I2C 地址。固件按
`base = chip & ~(((1<<page_bits)-1)<<1)` 自动算出基地址。
也就是说 24C08 挂在 0x51 时，实际基地址是 0x50，会占用 0x50/0x52/0x54/0x56。
总线上因此不能同时挂 24C01（0x50）和 24C08 —— 这是器件特性，不是固件问题。

## 6. I2C 通讯频率

STC8 硬件 I2C 主机：`f_SCL = FOSC / 2 / (MSSPEED*2 + 4)`，MSSPEED 为 `I2CCFG[5:0]`。

22.1184MHz 下（`EE_I2C_MSSPEED`，见 `HW_24c64.h`）：

| MSSPEED | 实际 f_SCL | 适用 |
| --- | --- | --- |
| 53 | 100.5 kHz | 老 24C01/24C02（100kHz 上限） |
| **20（默认）** | **251.3 kHz** | 与模拟器 `--i2c-rate 250000` 对齐，通用最稳 |
| 12 | 395.0 kHz | 24C32 以上，整片烧录最快 |
| 63 | 85.0 kHz | 长线/弱上拉时的保守值 |

> ⚠️ **原工程里 `I2CCFG = 0xE0 | 25` 是错的**：`0xE0` 的 bit5 属于 `MSSPEED[5]`，
> 实际 `MSSPEED = 0x39 = 57` → f_SCL ≈ **93.7kHz**（不是注释写的 205kHz）。
> 本固件改成 `0xC0 | MSSPEED`，bit5 不再被误置。
> 上板后建议用逻辑分析仪量一下 SCL：应接近 251kHz（单 bit 周期约 3.98µs）。

## 7. 24C64 写周期等待（可调宏）

写一页 EEPROM 后器件内部要 tWR 才能接受下一条命令，24C64 手册给的是 **5ms**。
固件把它做成宏，位于 `hardware/HW_24c64.h`：

```c
/* 写周期等待（默认 24C64 的 5ms；24C01/02 手册是 10ms，可改成 10） */
#ifndef EE_WRITE_CYCLE_MS
#define EE_WRITE_CYCLE_MS       5
#endif

/* 0 = 固定延时（默认，简单可靠）
 * 1 = ACK 轮询（写完立刻试地址，收到 ACK 就往下走，整片能快 20~30%） */
#ifndef EE_WC_USE_ACK_POLL
#define EE_WC_USE_ACK_POLL      0
#endif

/* 轮询上限：一次约 30us，400 次 ≈ 12ms 兜底，兜底后再补 EE_WRITE_CYCLE_MS */
#ifndef EE_WC_POLL_MAX
#define EE_WC_POLL_MAX          400
#endif
```

实现方式（`HW_24c64.c`）：

* `EE_WC_USE_ACK_POLL == 0`：`#define ee_wait_cycle(d, addr) delay_ms(EE_WRITE_CYCLE_MS)`
  —— 就是宏函数，改宏立即生效，不占 ROM；
* `EE_WC_USE_ACK_POLL == 1`：`ee_wait_cycle()` 变成真正的 ACK 轮询函数，
  超时兜底仍是 `delay_ms(EE_WRITE_CYCLE_MS)`。

各型号 tWR（最大值，数据手册）：

| 型号 | tWR |
| --- | --- |
| 24C01 / 24C02 | 10 ms |
| 24C04 ~ 24C512 | 5 ms |
| 24C1024 | 5 ms |

> 混装多种芯片时按键件里最慢的给；本工程默认值 5ms 是按 24C64 给的，
> 若插座上可能插 24C01/02，建议改成 10。

## 8. 时序预算（默认 251kHz / 115200）

单包（16 字节）：

| 环节 | 耗时 |
| --- | --- |
| 收 `W_[16字节]` 帧（51 字符 @115200） | ≈ 4.4 ms |
| 回 `RX-OK` + 写完后回 `R-S`（13 字符） | ≈ 1.1 ms |
| I2C 页写 19 字节（START+器件+2 地址+16 数据） | ≈ 0.7 ms |
| 写周期等待 | 5 ms（可宏调 / 可改轮询） |
| **每包合计** | **≈ 11 ms** |

整片估算（读流程每包 ≈ 5.6ms）：

| 器件 | 包数 | 写（5ms 固定） | 写（ACK 轮询） | 读 |
| --- | --- | --- | --- | --- |
| 24C01 128B | 8 | ≈ 0.13 s | ≈ 0.10 s | ≈ 0.05 s |
| 24C64 8KB | 512 | ≈ 5.8 s | ≈ 4.6 s | ≈ 2.9 s |
| 24C256 32KB | 2048 | ≈ 23 s | ≈ 18 s | ≈ 11 s |
| 24C512 64KB | 4096 | ≈ 46 s | ≈ 36 s | ≈ 23 s |

瓶颈主要在串口（ASCII 十六进制把数据放大了 3 倍）和 5ms 写周期，不在 I2C。

## 9. 数码管显示

前两位状态码，后两位当前 ROUTER 地址（如 `0x50` → `50`）。

**状态码只挑七段管能看清的字母**（`0-9 A b C d E F H I L n o P S t U y -`）：

| 状态 | 显示 | 含义 |
| --- | --- | --- |
| 空闲且未选器件 | `IdLE` | 上电初始 |
| 空闲但已选过器件 | `Id50` | 流程结束回 IDLE，保留地址 |
| 已设 ROUTER | `SE50` | **S**elect，等 EDGE |
| 已设 EDGE | `Ed50` | **Ed**ge，等 INT_R / INT_W |
| 写流程进行中 | `UC50` | **U** = write，**C** = busy |
| 读流程进行中 | `dC50` | **d** = download（上位机按钮也是 Download） |

内容不变时不重刷（省 TM1637 总线时间）。

> **为什么流程内只有一个码（不再区分等待/当前包/完成）**：
> 这三个子状态每个只持续几毫秒（一包 16 字节 ≈ 10ms），切换频率 90~180Hz，
> 人眼会把相邻几帧**叠加**起来看。例如 `C`(0x39 = a,d,e,f) ∪ `o`(0x5C = c,d,e,g)
> = a,c,d,e,f,g = **0x7D，正好是数字 "6"** —— 于是 `UC50` 看起来像 `U650`，
> `dC50` 看起来像 `d650`。这不是段码表错，而是时间上的叠加。
> 现在写流程全程显示 `UC`、读流程全程显示 `dC`，不闪也就不会叠加。

> **为什么不用 W / R**：
> * 七段管画不出 **W**，只能用 `0x3E`（b,c,d,e,f）拼成 **U** 形，所以写流程统一用 `U`；
> * **R** 只能用 `e+g` 两段（`0x50`）拼，屏幕上就是一根中横加一小段竖，像个杂点，
>   所以状态码里改成 `SE / Ed / UC / dC`，彻底避开 R。
> * 想恢复逐包状态或换别的字母，只改 `display.c` 里的 `s_pfx[9][2]` 表即可，
>   段码表里 `'W'`/`'R'`/`'o'`/`'-'` 都还保留着。

### 9.1 全黑怎么办（重要）

**第一嫌疑：电平不匹配，不是时序。** TM1637 手册的开关/时序特性测试条件是
**VDD = 4.5 ~ 5.5V**，且输入高电平门限 `VIH = 0.7 × VDD`：

| 模块 VDD | MCU IO 电平 | VIH 门限 | 结果 |
| --- | --- | --- | --- |
| 5V | 5V | 3.5V | ✅ 正常 |
| 5V | 3.3V | 3.5V | ❌ 3.3V 永远达不到门限 → **全黑** |
| 3.3V | 3.3V | 2.31V | ⚠️ 认得到，但器件不在手册保证范围（亮度偏暗） |

所以**模块 VDD 必须和 MCU 的 IO 电平一致**，5V/5V 最稳。3.3V MCU 配 5V 模块时必须加电平转换
（或干脆把模块也接 3.3V 先验证通信）。

**第二嫌疑：时序余量。** 手册 AC 参数：`Fmax 500kHz`、`PWCLK ≥ 400ns`、
`tSETUP/tHOLD ≥ 100ns`、**`tWAIT`（CLK↑ → 下一个 CLK↓）≥ 1µs**。
`Delay_us()` 一个单元约 0.65µs，`tm_write` 里 CLK↑ 到下一次 CLK↓ 正好是一个 `TM_DLY`：

```
tWAIT ≈ CFG_TM1637_DLY_US × 0.65us
CFG = 2  ->  1.3us   刚过 1us 最小值，边沿稍慢就丢整帧
CFG = 5  ->  3.3us   ≈100kHz   <-- 默认，稳
CFG = 10 ->  6.5us   ≈50kHz    长线 / 劣质模块
```

上一版默认是 2（照搬原工程的值），余量太小，已改成 **5**。

按顺序排查：

1. **先发 `>DISP_TEST<`**（调试命令，串口助手直接敲即可，不影响正式协议）：
   * 回 `>YES<` 且看到 `8.8.8.8` → 显示链路 OK，剩下的只是状态映射问题；
   * 回 `R-ERR` → 固件读回 CLK/DIO 发现**驱动 0 之后仍读到 1**，说明这两脚不在
     CPU 手上（复用功能/外部强上拉），见第 2 条；
   * 回 `>YES<` 但屏幕还是黑的 → 优先查第 3 条的供电电平。
2. **P5.4 的复位复用**：手册写"出厂时 P5.4 默认为 I/O 口"，只有在 STC-ISP 里主动把
   P5.4 设成复位脚后它才是 nRST（此时内部 4K 上拉常开）。若曾被设成复位脚，
   在 STC-ISP → 硬件选项里改回 I/O 再下载。另外 P5.4 作 I/O 时上电会有约 **6.5ms**
   的 4K 上拉（上电瞬间为高），设计驱动电路时要注意。
3. **供电电平**：见上面的表。用万用表量模块 VDD 和 MCU VCC 是否同一个电压；
   若模块 5V、MCU 3.3V，这就是全黑的原因。
4. **接线**：确认模块 VCC/GND、CLK/DIO 没有接反。若实际是 CLK 接 P5.5、DIO 接 P5.4，
   把 `board.h` 里两行对调即可：
   ```c
   #define TM1637_CLK              P54   /* 换成 P55 */
   #define TM1637_DIO              P55   /* 换成 P54 */
   ```
   如果数码管根本不在 P5.4/P5.5（原工程 `HW_24c64.h` 曾把 P5.4/P5.5 定义成两路
   WP），就改这两行指向实际引脚，并把 `CFG_EEPROM_WP_ENABLE` 关掉或把 WP 挪回去。
5. 屏幕暗但能看到字：加大亮度 `CFG_TM1637_BRIGHT`（0~7），或降低 `CFG_TM1637_DLY_US` 到 3。

## 10. 联调步骤

1. **纯协议对拍**：先跑 `lower-level_simulation`（`python -m eeprom_sim --port COMx`），
   上位机跑通说明命令序列没问题，再换实物。
2. **只接串口**（不插 EEPROM）：发 `>TYPE_ECHO<` 应回 `>YES<`；
   `>ROUTER_0x50<` 回 `R-S`，数码管显示 `SE50`。
3. **数码管自检**：发 `>DISP_TEST<`，应回 `>YES<` 并看到 `8.8.8.8` 闪一下。
4. **接一片 24C64**：`>ROUTER_0x50<` → `>EDGE_0x001F<` → `>INT_W<` → 一包 `W_` 数据 → `>TX-OVER<`，
   再按读流程读回比对。
5. 用逻辑分析仪确认 SCL 频率、ACK 位置；用万用表确认 WP 为低。

常见 `R-ERR` 排查：

| 现象 | 可能原因 |
| --- | --- |
| 所有命令都 `R-ERR` / 无应答 | IRC 不是 22.1184MHz；TX/RX 接反；波特率不是 115200 |
| `ROUTER` 就错 | 地址不在 0x50~0x57 |
| `EDGE` 错 | 没先发 ROUTER；或 EDGE 超过 `EE_SLOT_TYPE` 里配的型号上限（默认 24C64 → 0x1FFF） |
| 写成功读回不对 | WP 被拉高；SCL/SDA 上拉不足；`CFG_I2C_PIN_SEL` 与实物不符 |
| 写中途 `R-ERR` | 器件 NACK（未插好 / 地址不对 / 上拉缺失） |
| 读中途 `R-ERR` | 上位机回 `RX-OK` 超过 2s |
| 数码管全黑 | 见 9.1：先 `>DISP_TEST<`，重点查 STC-ISP 的"复位脚用作 I/O 口" |
| 读回全是 `0xFF`、但不报错 | 二选一：① 片子是空白的（新片正常态）；② **SDA 上拉缺失/不足**（写能成、读全是 1）。用"写入已知图样再读回"区分；先发 `>I2C_TEST<` 确认器件在线 |

### 10.1 为什么"全 0xFF 且不报错"说明总线其实是通的

固件对每个 ACK 都做判断，任何一个 NACK 都会回 `R-ERR`。
"读出 256 字节 0xFF 且没有报错"要求：器件地址、2 个地址字节、重复 START 后的读地址
**全部被 ACK**（SDA 被拉低），而 16×8 个数据位**全部读到 1**（SDA 为高）。
一条被拉死/悬空的线不可能同时满足这两点，所以：

* I2C 时钟和从机应答都是有效的 → 不要再怀疑"完全没通"；
* 数据全 1 只有两种解释：芯片未写过（空白 = 0xFF），或 SDA 没有真正的上拉
  （写的时候主机推挽能驱动，读的时候"1"只能靠上拉，只有 MCU 内部弱上拉时极易全读成 1）。

验证方法：写 16 字节已知图样（含 0x00）再读回。

* 读回一致 → 总线与上拉都没问题，之前的 0xFF 就是空白片；
* 写不报错但读回仍全 FF → 补 4.7k~10k 上拉到 VCC（SCL、SDA 都要），
  或把 `EE_I2C_MSSPEED` 改到 53（100kHz）先跑通。

### 10.2 用 LED 观察 SCL 的注意点

* I2C 空闲时 SCL 为高；一包 16 字节事务约 0.7ms，读流程每包之间还要等上位机
  `RX-OK`（约 4~5ms），所以 SCL 低电平占空比只有 10~15%，LED 是**暗亮/闪**，不会常亮；
* LED 必须并接（SCL→限流电阻→LED→VCC，或反过来的低有效接法），**不能串在总线里**；
* 限流电阻别太小（建议 ≥1k）。SCL 被拉低时要靠引脚吸收 LED 电流，阻值过小会把
  低电平抬到 VIL 以上，反而把本来就正常的通信搞坏；
* 想确认"这根线到底动不动"，万用表直流档量 SCL 对地电压最直接：通讯时平均电压
  应明显低于 VCC；一直等于 VCC 才说明这脚没在动（接错网络或引脚未作 I/O）。

### 10.3 "写 0x50 成功，写 0x57 第一包就 R-ERR" 怎么看

这是**该槽位没有器件应答**，不是协议问题。判断链条：

1. 上位机在流包期间把 `RX-OK` / `R-S` 从日志里隐藏了（免得刷屏），但 **`R-ERR` 永远打印**。
   所以日志里"没有 RX-OK、只有一个 R-ERR"其实表示：**整包收到了**（RX-OK 被隐藏），
   是**写 EEPROM 失败**。
2. 同一份代码、同样的 16 字节、同样的 5ms 写周期，写 0x50 跑满 512 包都没错 →
   驱动、时序、页拆分、写周期都没问题。
3. 两次唯一的差别是器件地址：0x50 → `0xA0`，0x57 → `0xAE`。地址没人应答就是 NACK。

`ROUTER` 只校验 0x50~0x57 并选型号，**不探测器件**，所以空槽位能一路 `R-S` 过
`ROUTER` / `EDGE` / `INT_W`，到第一包数据才炸 —— 看着就像"协议坏了"。

一条命令就能确认插了几个工位：

```
>SCAN<
>SCAN_[01]<     ← bit0=0x50 … bit7=0x57，只有 0x50 应答（其余槽位空）
>SCAN_[81]<     ← 0x50 和 0x57 都有片子
```

* `XX` 里没有对应位 → 那个槽位真的没片子（或片子地址不是它：24Cxx 的 A2/A1/A0 引脚
  决定 0x50~0x57，全部接地才是 0x50）；
* 有对应位但写仍 `R-ERR` → 查该路 **WP 是否被拉高**（WP=1 时器件会 ACK 但丢弃写周期）
  和上拉电阻。

> 顺带说：上位机的写队列是"按勾选的槽位逐个写"。默认只勾 0x50，
> 如果日志里出现 `Writing ... to 0x57`，说明 0x57 那行也被勾上了（或点了全选）。
> 板上只插一片时，把多余槽位取消勾选即可。

## 11. 已知限制 / 扩展方向

1. **多通道靠 ROUTER 地址区分**：一条 I2C 总线最多 8 个地址。
   若需要 74HC595 片选通道，当前命令集里没有通道号，需要上位机配合扩展，
   例如加一条 `>CH_n<`：
   ```c
   /* HW_595.c 里 3 根线：SER/SCLK/RCLK，n=0~7 */
   void CH_Select(uint8_t n) { /* 移位 -> RCLK 上升沿锁存 */ }
   /* copier.c 的 dispatch 里加分支 */
   else if (has_prefix(s, "CH_")) { parse 数字 -> CH_Select(n); reply_ok(); }
   ```
   同时上位机的 `ParserTXModel` 要能发出 `CH_n`，否则实物通道选择永远停在 0。
   目前固件**不启用**这段，保证与现有上位机/模拟器行为完全一致。
2. **24C04/08/16 会占用多个 I2C 地址**（见第 5 节），总线规划时要留开。
3. **W 包固定 16 字节**（比模拟器更严格地按规范解析），少于 16 字节回 `R-ERR`；
   上位机 `ParserTXModel.WritePacket` 已自动补 0 到 16 字节，正常不会触发。
4. **单帧缓冲**：只有一块 64 字节帧缓冲，主机必须严格"命令-应答"式交互
   （现有上位机就是这样）。若要支持流水线，改成环形队列即可。
5. **无 CRC**：协议本身是文本帧 + 严格长度校验，误码由上位机重试兜底；
   如果要更强保护，可在数据包后加 2 位校验和（需要同步改上位机）。
6. **数码管 W 字母**为七段近似显示（0x3E），需要更贴近的观感可改
   `TM1637_CharToSeg()` 里的码表。
