# CMD.md — 模拟下位机指令文档

本文档描述 **上位机 ↔ 模拟下位机（STC8G1K08A + 多片 24CXX）** 之间的串口协议。

---

## 1. 串口参数

| 项目   | 值        |
| ------ | --------- |
| 波特率 | 115200    |
| 数据位 | 8         |
| 校验   | 无 (None) |
| 停止位 | 1         |
| 流控   | 无        |

## 2. 帧格式

所有命令、应答、数据帧统一为：

```
>内容<
```

- 以 `>` 开始，以 `<` 结束。
- **帧尾附加标准换行间隔 `\r\n`**：发送方每发一帧都在 `<` 之后追加 `\r\n`（CR LF）。
- 收到**完整帧**（遇到 `<`）后即处理；`<` 之后的 `\r\n` 属于帧间隔，被接收方忽略。
- 帧内不允许出现换行（`\r` / `\n`）；若在帧内容中出现则视为非法帧，丢弃当前帧并回 `R-ERR`。
- 接收方**容错**：`\r\n`、单独 `\n`、单独 `\r` 或两者的组合作为帧间隔均可接受；`>` 之前的任意垃圾字节一律忽略。
- 数据字节使用 ASCII 十六进制，**每字节两位**，逗号分隔，大小写不敏感（输出统一大写）。

示例（`⏎` 表示 `\r\n`）：

```
>ROUTER_0x50<⏎
>R-S<⏎
>R-ERR<⏎
>RX-OK<⏎
>TX-OVER<⏎
>R_[00,1A,FF,02,...,0E]<⏎
>W_[00,1A,FF,02,...,0E]<⏎
```

字节流视角（上位机发 `>ROUTER_0x50<`）：

```
3E 52 4F 55 54 45 52 5F 30 78 35 30 3C  0D 0A
 >  R  O  U  T  E  R  _  0  x  5  0  <   \r \n
```

## 3. 数据格式与地址规则

- **数据**：`[00,1A,FF,...]`，每字节两位十六进制。
- **ROUTER 地址**：`>ROUTER_0x50<` 中的 `0x50` 是 **7 位 I2C 芯片地址**。
  - 实际写地址 = `(0x50 << 1) | 0` = `0xA0`
  - 实际读地址 = `(0x50 << 1) | 1` = `0xA1`
- **EDGE 末尾地址**：`>EDGE_0x00FF<` 指定本次传输的末尾地址。
  - 读写固定从 `0x00` 开始，到 EDGE 结束。
  - EDGE 不能超过当前路由设备最大地址。
- **包长**：固定 16 字节一包。
  - 写：上位机发送的 W 包固定 16 字节；下位机只把有效字节写入，填充的 `0x00` 不写入 EDGE 之后。
  - 读：下位机返回的 R 包固定 16 字节；读到 EDGE 后剩余字节补 `0x00`。
  - 有效长度 `N = min(16, EDGE - 当前地址 + 1)`。

## 4. 模拟 I2C 设备表

| I2C 地址 | 型号    | 容量    | 字节数 | 地址范围          | 写/读地址   | bin 文件                |
| -------- | ------- | ------- | ------ | ----------------- | ----------- | ----------------------- |
| 0x50     | 24C01   | 1Kbit   | 128    | 0x00 ~ 0x7F       | 0xA0 / 0xA1 | eeprom_0x50_24C01.bin   |
| 0x51     | 24C08   | 8Kbit   | 1024   | 0x00 ~ 0x3FF      | 0xA2 / 0xA3 | eeprom_0x51_24C08.bin   |
| 0x52     | 24C16   | 16Kbit  | 2048   | 0x00 ~ 0x7FF      | 0xA4 / 0xA5 | eeprom_0x52_24C16.bin   |
| 0x53     | 24C64   | 64Kbit  | 8192   | 0x0000 ~ 0x1FFF   | 0xA6 / 0xA7 | eeprom_0x53_24C64.bin   |
| 0x54     | 24C128  | 128Kbit | 16384  | 0x0000 ~ 0x3FFF   | 0xA8 / 0xA9 | eeprom_0x54_24C128.bin  |
| 0x55     | 24C256  | 256Kbit | 32768  | 0x0000 ~ 0x7FFF   | 0xAA / 0xAB | eeprom_0x55_24C256.bin  |
| 0x56     | 24C512  | 512Kbit | 65536  | 0x0000 ~ 0xFFFF   | 0xAC / 0xAD | eeprom_0x56_24C512.bin  |
| 0x57     | 24C1024 | 1Mbit   | 131072 | 0x00000 ~ 0x1FFFF | 0xAE / 0xAF | eeprom_0x57_24C1024.bin |

说明：

- 每个设备独立一个 bin 文件作为模拟永久存储。
- 启动时加载；不存在则创建并用 `0xFF` 填充到对应字节数。
- **内存为主存储，磁盘为镜像**：写命令只改内存；在**流程结束**（`>TX-OVER<`）、**中止**（`>ABORT<`）、**写失败**以及**进程退出**时统一落盘一次。读操作从内存读取。
- 可用 `--flush-each-packet` 恢复“每写一包立即落盘”的旧行为。
- 落盘采用“写临时文件 + 原子替换”，短暂被占用（如杀毒软件扫描）会自动重试；重试仍失败只告警、不当作业务失败（内存数据仍保留，留待下次落盘）。
- 24C01~24C16 使用 1 字节地址 + 页选择；24C64~24C1024 使用 2 字节地址。

## 5. 命令集合

### 5.1 上位机 → 下位机

| 命令             | 说明                                                                       | 下位机应答                    |
| ---------------- | -------------------------------------------------------------------------- | ----------------------------- |
| `>ROUTER_0x50<`  | 指定 I2C 芯片地址，必须在 0x50 ~ 0x57                                      | `>R-S<` / `>R-ERR<`           |
| `>EDGE_0xXXXX<`  | 指定末尾地址，范围 0x00 ~ 当前设备最大地址                                 | `>R-S<` / `>R-ERR<`           |
| `>INT_R<`        | 启动读，下位机开始逐包发送                                                 | `>R-S<` / `>R-ERR<`           |
| `>INT_W<`        | 启动写，等待上位机发 W 包                                                  | `>R-S<` / `>R-ERR<`           |
| `>W_[d1,…,d16]<` | 写一包 16 字节，先 `>RX-OK<`，写完 `>R-S<` / `>R-ERR<`                     | `>RX-OK<` + `>R-S<`/`>R-ERR<` |
| `>RX-OK<`        | 读流程中，上位机收到一包后的确认                                           | （下位机继续发下一包）        |
| `>TX-OVER<`      | 写流程结束通知                                                             | `>R-S<` / `>R-ERR<`           |
| `>ABORT<`        | 中止当前任务                                                               | `>R-S<` / `>R-ERR<`           |
| `>TYPE_ECHO<`    | 查询当前设备是否为指定的工作设备，直接返回 `YES`（随时可调用，不影响状态） | `>YES<`                       |

### 5.2 下位机 → 上位机

| 应答 / 数据      | 说明                                              |
| ---------------- | ------------------------------------------------- |
| `>R-S<`          | 一切正确                                          |
| `>R-ERR<`        | 一切错误，不细分                                  |
| `>YES<`          | `TYPE_ECHO` 的应答：当前设备即为指定的工作设备    |
| `>R_[d1,…,d16]<` | 读流程中发出的一包数据                            |
| `>RX-OK<`        | 写流程中收到完整 W 包                             |
| `>TX-OVER<`      | 读流程中发完最后一包并收到 `>RX-OK<` 后的结束标志 |

### 5.3 TYPE_ECHO 说明

`>TYPE_ECHO<` 用于上位机查询当前下位机是否为指定的工作设备，下位机直接返回 `>YES<`。

- 可在任意状态调用（包括空闲、会话建立过程中），**不影响任何状态、边界与数据**。
- 应答固定为 `>YES<`。
- 用于多设备总线下确认目标设备，或联调时校验链路连通。

示例：

```
上位机 -> >TYPE_ECHO<
下位机 -> >YES<
```

## 6. 数码管显示（模拟）

4 位数码管：**前两位状态指令，后两位当前路由 I2C 芯片地址**。

| 状态          | 数码管        | 说明                          |
| ------------- | ------------- | ----------------------------- |
| ST_IDLE       | `IDLE`        | 空闲                          |
| ST_ROUTER_SET | `IDxx` / 保持 | 已设 ROUTER，等待 EDGE        |
| ST_EDGE_SET   | `IDxx` / 保持 | 已设 EDGE，等待 INT_R / INT_W |
| ST_WRITE_WAIT | `WWxx`        | 写等待                        |
| ST_WRITE_CURR | `WCxx`        | 正在写当前包                  |
| ST_WRITE_OVER | `WOnn`        | 当前包写完成                  |
| ST_READ_WAIT  | `RWxx`        | 读等待                        |
| ST_READ_CURR  | `RCxx`        | 正在读当前包                  |
| ST_READ_OVER  | `ROxx`        | 当前包读完成                  |

`xx` = 当前路由的 I2C 芯片地址（如 `0x50` → `50`）。注意：后两位是 I2C 芯片地址，不是 EEPROM 操作地址。

控制台输出示例：

```
[TM1637] IDLE
[TM1637] WW50
[TM1637] WC50
[TM1637] WO50
[TM1637] RW50
[TM1637] RC50
[TM1637] RO50
```

## 7. 读流程

```
上位机 -> >ROUTER_0x50<      下位机 -> >R-S<
上位机 -> >EDGE_0x007F<      下位机 -> >R-S<
上位机 -> >INT_R<            下位机 -> >R-S<
循环：
    下位机 -> >R_[d1,…,d16]<
    上位机 -> >RX-OK<
    下位机 -> 地址增加 N，继续下一包
最后一包：
    下位机 -> >R_[d1,…,d16]<   // 不足 16 字节补 0x00
    上位机 -> >RX-OK<
    下位机 -> >TX-OVER<
```

要求：

- 下位机从 `0x00` 开始读。
- `N = min(16, EDGE - 当前地址 + 1)`，读 N 字节，剩余补 `0x00`。
- 每发完一包等待上位机 `>RX-OK<`，最大 2s。
- 2s 未收到 → 回 `>R-ERR<`，停止读流程，回 ST_IDLE。
- 收到 `>RX-OK<` 后地址增加 N。
- 当前地址超过 EDGE 且已确认 → 发 `>TX-OVER<`。

## 8. 写流程

```
上位机 -> >ROUTER_0x50<      下位机 -> >R-S<
上位机 -> >EDGE_0x007F<      下位机 -> >R-S<
上位机 -> >INT_W<            下位机 -> >R-S<
循环：
    上位机 -> >W_[d1,…,d16]<   // 不足 16 字节补 0x00
    下位机 -> >RX-OK<
    下位机 -> 模拟 I2C 写约 0.8ms
    下位机 -> 等待 20ms 写周期
    下位机 -> 写入内存（默认暂不落盘）
    下位机 -> >R-S< / >R-ERR<
    上位机 -> 收到 >R-S< 后发下一包
最后一包后：
    上位机 -> >TX-OVER<
    下位机 -> 统一落盘（写 bin 文件）
    下位机 -> >R-S<
    下位机 -> 回到 ST_IDLE
```

要求：

- 从 `0x00` 开始写，`N = min(16, EDGE - 当前地址 + 1)`。
- 只把前 N 字节写入模拟 EEPROM 内存。
- 收到完整 W 包后先回 `>RX-OK<`，再模拟 I2C 写 + 20ms 写周期，成功后更新内存并回 `>R-S<`。
- **默认落盘时机**：W 包阶段只写内存；整批写完成后由 `>TX-OVER<` 触发统一落盘（一次流程只写一次磁盘）。`>ABORT<`、写失败、进程退出也会兜底落盘。
- 写成功后地址增加 N；失败地址不增加。
- 上位机必须等 `>R-S<` 才能发下一包。
- 掉电语义：若在 `>TX-OVER<` 之前断电/异常退出且来不及兜底落盘，未落盘的数据可能丢失（内存为主存储）。需要“每包即时落盘”时用 `--flush-each-packet`。

## 9. 错误处理

所有错误统一返回 `>R-ERR<`，不细分。以下情况返回 `>R-ERR<`：

- ROUTER 地址不在 0x50 ~ 0x57 范围。
- EDGE 小于 0x00 或超过当前设备最大地址。
- 未设置 ROUTER 就发 EDGE。
- 未设置 EDGE 就发 INT_R / INT_W。
- 状态不匹配，例如未 INT*W 就发 W*。
- 地址越界。
- I2C 模拟 NACK（可配置错误注入）。
- 读流程中等待 `>RX-OK<` 超过 2s。
- 数据格式错误（非法 ASCII 十六进制）。
- 包长度不是 16 字节。

错误后：停止当前任务、清空临时状态、回到 ST_IDLE，**保留已成功写入的数据和 bin 文件**。

### 9.1 容错与鲁棒性

- 下位机对**任何**畸形/未知帧（如误输入 `>TYPE-ECHO<`、乱码、空帧、帧内换行等）都只回 `>R-ERR<`，**不会崩溃或退出**，随后仍可继续正常响应后续命令。
- 帧外（`>` 之前）的垃圾字节会被忽略；遇到 `>` 才开始接收帧内容，遇到 `<` 结束。
- 帧内出现换行 `\n` / `\r` 视为非法，丢弃当前帧并回 `>R-ERR<`。
- 串口读取出现瞬时异常时，记录日志并继续运行；连续错误过多才退出（防止无限刷屏）。
- 只有 stdio 输入 EOF 或串口被关闭时下位机才结束进程。

---

## 10. 超时与流控

- 读流程：下位机发完一包后等待 `>RX-OK<`，最大 2s；超时回 `>R-ERR<` 并回 ST_IDLE。
- 写流程：上位机等待 `>RX-OK<` / `>R-S<` 建议 2s 超时（由上位机负责）。
- 所有流控确认必须成对出现，避免半包卡死。

---

## 11. 上位机对接注意事项

- 所有帧统一使用 `>内容<` 格式，并在 `<` 之后追加 `\r\n` 作为帧间隔。
- 发出命令后必须等待下位机对应应答。
- 写流程：发 `>W_[...]<` 后先等 `>RX-OK<`，再等 `>R-S<`；只有收到 `>R-S<` 才能发下一包；最后一包后发 `>TX-OVER<`，等 `>R-S<`。
- 读流程：发 `>INT_R<` 后等 `>R-S<`，然后接收 `>R_[...]<`；每收到一包回 `>RX-OK<`；收到 `>TX-OVER<` 表示读完。
- 地址自增按有效字节数 N，不是固定 +16。
- **写/读流程结束后下位机回到 ST_IDLE，会清空 EDGE**；再次读写前需重新发 `>ROUTER_<` 与 `>EDGE_<`。
- 数码管显示仅模拟，不参与协议。
