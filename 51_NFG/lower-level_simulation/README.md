# NFG 即时销毁存储卡 —— 下位机模拟程序

模拟基于 **AS6C62256**（32K × 8 SRAM）的「即时销毁存储卡」下位机行为，用于与上位机联调。
无需真实硬件：SRAM 用内存字节数组模拟，可持久化到文件（模拟纽扣电池保持）。

- **串口参数**：`115200 8N1`
- **协议**：上位机命令 `>命令内容<`，下位机应答 `[应答内容]`
- **语言 / 依赖**：Python 3（真实串口需要 `pyserial`；`--stdio` 模式无需任何依赖）

## 二、运行说明

### 1. 安装依赖（仅真实串口需要）

```bash
pip install pyserial
```

### 2. 启动模拟下位机

```bash
# 真实串口（默认 COM1，115200 8N1）
python nfg_sim.py

# 显式指定端口
python nfg_sim.py --port COM3 --baud 115200

# 无串口环境：用标准输入输出模拟串口
python nfg_sim.py --stdio
```

每行输入一条命令（无需换行也可，程序按 `>` ... `<` 帧解析）：

```bash
# Linux / macOS
printf '>PING<>NFG_INFO<>AUTHSET_123456<>AUTH_123456<...' | python nfg_sim.py --stdio

# Windows PowerShell
echo ">PING<>NFG_INFO<" | python nfg_sim.py --stdio
```

## 四、存储结构

| 区域 | 地址范围 | 大小 | 用途 |
|---|---|---|---|
| 明文区 | `0x0000 ~ 0x7FEF` | 32752 字节 | 存储明文数据（2047 个 16 字节包） |
| 特征码 / 密码区 | `0x7FF0 ~ 0x7FFF` | 16 字节 | 存储密码特征码 |

- 初始值 `0xFF`；明文区 `32752 = 16 × 2047` 正好整除。
- 读写从 `0x0000` 开始，到 `0x7FEF` 结束。
- 最后一包不足 16 字节自动补 `0x00`。

---

## 五、特征码算法

密码为**六位数字**。由密码生成 16 字节特征码的算法（适配 8051、资源占用小）：

```
feature[i] = ((password[i % 6] + i * 0x5A) & 0xFF) ^ 0x3C     (i = 0..15)
```

- `password[i % 6]`：第 i 位密码字符的 ASCII 码。
- 常量：盐值 `0x5A`、异或键 `0x3C`（见 `nfg_sim.py` 的 `FEATURE_SALT` / `FEATURE_XOR_KEY`）。

**未设置密码**判定：特征码区**全 `0xFF`** 或**全 `0x00`** → `NFG_0`。

> 该算法由模拟程序自行定义，只需 `AUTHSET` 与 `AUTH` 使用同一算法即可保证一致。
> 若与真实 8051 固件对接，请保证固件采用完全相同的算法。

示例（密码 `123456`）：

```
特征码 = 0D,B0,DB,7E,A1,C4,71,94,3F,62,85,28,55,F8,23,46
```

## 六、协议速查

### 上位机 → 下位机

| 命令 | 说明 | 应答 |
|---|---|---|
| `>AUTH_六位数字密码<` | 验证密码 | `[AUTH_OK]` / `[AUTH_ERR]` |
| `>AUTHSET_六位数字密码<` | 设置 / 覆盖密码 | `[SET-OK]` / `[SET_ERR]` |
| `>NFG_INFO<` | 查询是否已设置密码 | `[NFG_0]` / `[NFG_1]` |
| `>INT_W<` | 进入写模式 | `[RX-OK]` / `[RX-ERR]` |
| `>W_[d1,...,d16]<` | 写一包 16 字节 | `[RX-OK]` / `[RX-ERR]` |
| `>TX-OVER<` | 写结束 | `[RX-OK]` |
| `>INT_R<` | 启动读取 | `[RX-OK]` / `[RX-ERR]` |
| `>ABORT<` | 中断当前读写 | `[ABORT-OK]` |
| `>PING<` | 在线检测 | `[PONG]` |
| `>DESTROY<` | 立即销毁 | `[DESTROY-OK]` |

### 下位机 → 上位机

| 帧 | 说明 |
|---|---|
| `[AUTH_OK]` / `[AUTH_ERR]` | 验证成功 / 失败 |
| `[SET-OK]` / `[SET_ERR]` | 设置成功 / 失败 |
| `[NFG_0]` / `[NFG_1]` | 未设置 / 已设置密码 |
| `[RX-OK]` / `[RX-ERR]` | 操作成功 / 失败（含越界、未认证、超时） |
| `>R_[d1,...,d16]<` | 读流程数据包 |
| `>TX-OVER<` | 读流程结束 |
| `[ABORT-OK]` | 中断成功 |
| `[PONG]` | 在线应答 |
| `[DESTROY-OK]` | 销毁完成 |

> 数据字节为 ASCII 十六进制、每字节两位、逗号分隔、输出大写，例如 `00,1A,FF`。
> 命令大小写不敏感。

## 七、写流程

```
上位机 -> >AUTH_密码<          下位机 -> [AUTH_OK]
上位机 -> >INT_W<             下位机 -> [RX-OK]
循环   -> >W_[d1,...,d16]<    下位机 -> [RX-OK]      （地址 += 16）
上位机 -> >TX-OVER<           下位机 -> [RX-OK]
```

- 未认证时 `>INT_W<` 返回 `[RX-ERR]`。
- 越界（地址超过 `0x7FEF`）返回 `[RX-ERR]`，**地址不增加**。
- 写失败返回 `[RX-ERR]`，地址不增加。
- `>ABORT<` 可随时中断，返回 `[ABORT-OK]`。

## 八、读流程

```
上位机 -> >AUTH_密码<          下位机 -> [AUTH_OK]
上位机 -> >INT_R<             下位机 -> [RX-OK]
循环   -> <R_[d1,...,d16]<    上位机 -> [RX-OK]      （地址 += 16）
结束   -> >TX-OVER<
```

- 未认证时 `>INT_R<` 返回 `[RX-ERR]`。
- 第一包由 `INT_R` 的应答后立即推送。
- 下位机每发一包等待上位机 `[RX-OK]`，超时（默认 2s）返回 `[RX-ERR]` 并停止。
- `>ABORT<` 可随时中断，返回 `[ABORT-OK]`。

## 十二、`sram.bin` 说明

- 程序**上电时**从 `sram.bin` 加载 SRAM；文件不存在则用 `0xFF` 填充。
- **每次**写包、设置密码、销毁后立即保存。
- **程序退出时**（含 Ctrl-C、stdin 关闭）也会保存，模拟纽扣电池保持。
- 文件固定 **32768 字节**，与 AS6C62256 一一对应：

| 文件偏移 | 对应 SRAM 区域 |
|---|---|
| `0x0000 ~ 0x7FEF` | 明文区 |
| `0x7FF0 ~ 0x7FFF` | 特征码 / 密码区 |

- 使用 `--no-persist` 可禁用持久化（纯内存运行，便于反复干净测试）。
- 想恢复出厂（未设置密码、全 `0xFF`）：删除 `sram.bin`，或发送 `>DESTROY<`。

## 十三、与真实硬件对接提示

模拟程序与真实 8051 固件对接时，需保证：

1. **特征码算法完全一致**（本文第五节）。如固件算法不同，请修改
   `nfg_sim.py` 的 `compute_feature()` 以对齐。
2. 串口参数一致：`115200 8N1`。
3. 帧格式一致：命令 `>...<`，应答 `[...]`，读数据 `>R_[...]<`，读结束 `>TX-OVER<`。
