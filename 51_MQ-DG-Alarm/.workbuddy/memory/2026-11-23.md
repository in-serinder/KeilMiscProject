## 修 BUG（同日，用户回报"两个键都加 10"+"ADC 好像没启动"）

**① 按键全判成 add —— 根因是键值格式理解错（已修正，并同步改了 keil-c51-stc8 技能）**
- TM1637 的 42H 键值是**低电平有效单字节**：空闲 `0xFF`；`b4=0`→K1 行(add)、`b3=0`→K2 行(sub)，
  `b7..b5` 是列号低有效编码，`b2..b0` 恒为 1。
  K1×SEG1=`0xEF`、K2×SEG1=`0xF7` —— **两者 bit0 都是 1**，旧版用 `raw & 0x0001` 判 add，
  于是两个键都命中 add，sub 永远不生效。
- 新 `key.c`：`z=~b; if(z&0x07) return 0; if(z&0x10) ADD; if(z&0x08) SUB;`
  已删掉 `CFG_KEY_ADD_BIT/SUB_BIT` 掩码配置，改为行位判据（与 A 接哪条 SEG 无关）。

**② ADC 排查**
- 逐字比对官方例程后确认 `ADCCFG=0x2F`、`ADCTIM=0x3F`、`ADC_FLAG=0x20/START=0x40` 写法正确。
- 真正的问题是"超时静默返回 0"，导致"没转换"和"输入 0V"无法区分。
  现在 `ADC_Read` 超时返回 `0xFFFF`、`MQ_Read` 全超时返回 `0xFFFF`，主程序显示 **Err**；
  显示 0 = ADC 正常但 P3.2 是 0V（查传感器供电/预热/AO 接线）。
- 超时判据从 250 次空转(~113us) 放宽到 2000 次(~1ms)，并在超时路径撤掉 START。

构建：默认 / `CFG_KEY_RAW_SHOW=1` / `CFG_KEY_GPIO_MODE=1(+RAW)` 三种组合均 0 Error 0 Warning；
默认配置 data=66.1B、code=3330B。

## 第三轮：读官方 PDF，纠正分辨率 + 接上串口调试（用户回报"一直显示 Err"）

**手册查证（STC8G 系列技术手册 1240 页，16 章；TM1637 V2.6）**
- `ADC_CONTR`：B7 POWER / B6 START（完成后硬件自动清）/ B5 FLAG（软件清零）/ B4 EPWMT / B3~B0 CHS ✓ 原写法正确。
- `ADCCFG` B5=RESFMT、B3~B0=SPEED（FADC=SYSclk/2/(SPEED+1)）；`ADCTIM` B7 CSSETUP / B6~B5 CSHOLD / B4~B0 SMPDUTY，
  官方推荐 0x3F，SMPDUTY 不得 <10。
- **★ 分辨率：STC8G1K08 / STC8G1K08A 都是 10 位（满量程 1023）。** 之前按 12 位写（TH_MAX=4095、
  默认 1200、步长 10）是错的 → 改为 TH_MAX=1023、默认 400、步长 5、回差 12。
- **★ 通道号随型号变**：A 系列（6 通道）P3.2=ADC2；不带 A 的 1K08（15 通道）P3.2=ADC10。
  开机自动探测 ch2 / ch10，用能完成转换的那个；再读 ch15（内部 1.19V，与外部引脚无关）判断 ADC 本体是否在工作。
- TM1637 键值表与上一轮修正完全一致（K1 行 EF..0F，K2 行 F7..17，无键 FF，低位在前，不支持组合键）。

**新增串口调试（用户要求）**
- `system/uart.c/.h` 重写为纯发送 9600 8N1（T1 12T，`TL1=0xD0 TH1=0xFF`，0% 误差），不再依赖 proto.h。
  整个文件用 `CFG_DEBUG_UART` 包住（关闭时编译成空目标，避免 L16）。
- 开机横幅：端口模式、EEPROM 阈值、`probe ch2/ch10/ref15 -> 实际通道`、`ADCCFG/ADCTIM/ADC_CONTR` 回读。
- 每秒状态行：`v= err= ch= to= g= ctr= key= th= m= b=`；另有按键事件、存盘结果。
- `CFG_KEY_GPIO_MODE=1` 与串口抢 P3.0/P3.1，加了 `#error` 强制二选一。
- ADC 出错后重试周期从 200ms 放宽到 1s（避免 8×4ms 连续空转卡住主循环）。

构建：default / rawshow / gpiokey / restore 四种组合均 0 Error 0 Warning；默认 code=4490B。

## 第四轮：串口日志定位根因（用户回报 v=0 err=1 ctr=00，存盘 FAIL）

**结论：手上这颗片子没有 ADC —— 不是软件问题。**
- 手册 1.4 产品线表：**STC8G1K08-8Pin（无 A）= 6 IO，ADC 列空白**；
  STC8G1K08**A**（含 SOP8/DFN8/DIP8）= 6 IO，**6CH×10bit**（2.2 节明写"6 路高速 ADC"）。
- 8.2 节 SFR 表：1K08-8Pin 的 `0xBC/0xBD/0xBE/0xDE/FEA8h` 全是空的（没有 ADC_CONTR/ADCCFG/ADCTIM）。
  所以日志里 `ctr=00` = 写进去读回 0 = 寄存器不存在；转换永远不完成 → 一直 Err。
- 对策：① 换同封装带 A 的片子（¥0.65 级别，脚位完全兼容）；② 临时改读 MQ 模块 LM393 的 DO。

**同时修掉两个真 bug**
1. **EEPROM 地址越界**：手册 15.3 —— 1K08/1K08A 的 EEPROM 是独立 4K，IAP 地址只有 0000h~0FFFh，
   程序区 8K 是另一块空间。原来放 `0x1C00` 是无效地址 → `save FAIL`。改为 `0x0E00`。
   并增加 `IAP_CONTR` bit4 = CMD_FAIL 的回读诊断（日志打 `cmdfail=`）。
2. **键位反接**：日志显示丝印 add 的键读回 `FFF7`（K2 行）、sub 读回 `FFEF`（K1 行）——
   解码正确，是模块跳线反了。新增 `CFG_KEY_SWAP`（默认 1）交换两行。

**新增能力**
- `ADC_IsPresent()`：开机回读 ADCCFG/ADC_CONTR，判定片上是否有 ADC；没有就数码管显示 `noAd`，
  串口打 `adc=ABSENT(no ADC in this part)`，不再含糊地报 Err。
- `CFG_MQ_DIGITAL`：数字 DO 模式（P3.2 读 LM393 输出，`CFG_MQ_DO_ACTIVE_LOW` 可配），
  把 DO 映射成 0/1023，后面的阈值/报警/显示逻辑一行不改。当前这颗片子可以先用它跑通。
- 通道探测（有 ADC 时）：ch2 / ch10 / ch15(内部 1.19V)，自动挑能转换的那个。

构建：default / digital / digital-nodbg / gpiokey / restore 五种组合均 0 Error 0 Warning；默认 code=4719B。

## 第五轮：用户坚持是 STC8G1K08A，加寄存器级自检（不再靠推断）

用户贴的日志与上一轮**完全相同**（`v=0 err=1 ctr=00`，无 `key raw=`、无新横幅），怀疑没烧新 hex；
但也要准备好"真是 A 片子却读回 0"的可能，所以把结论改成可测量：

**开机自检（adc.c / ADC_Init）**
1. `P3M1 |= 0x04` 后回读作对照组（证明 SFR 读写真通）。
2. `ADC_CONTR = 0x5A` 后回读 → 真寄存器会保留实现的位，不存在则读 0。
3. 写官方配置（ADCTIM=0x3F, ADCCFG=0x2F）后回读，再读 ADCCFG/ADCTIM。
4. 用 **通道 15（内部 1.19V，与外部引脚无关）** 判定 ADC 是否真在转换；
   失败再退一步用官方例程那套（ADCTIM=0x2A, ADCCFG=0x0F 左对齐）重试一次。
5. 结果：`ADC_IsPresent()` / `ADC_GetCfg()`；调试时额外 `ADC_ProbeReg(0..4)`。

串口横幅新增：
```
P5M0=.. P_SW2=80
adc=ok cfg=2F
reg con5A=5A con82=82 cfg=2F tim=3F p3m1=04
```
判读：`con5A=00` → 该地址无 SFR（片子无 ADC）；`tim=00` 而 `cfg=2F` → EAXFR 未生效；
全部正常但仍 Err → 才去查 P3.2 外部。

构建：默认配置 0 Error 0 Warning，code=4963B。

## 第六轮：用户寄回寄存器自检结果 —— 判定 ADC 块缺失，加自动降级

用户实测（新 hex 已烧）：
```
th=eeprom-invalid -> default 400
adc=NOT-WORKING cfg=2F
reg con5A=00 con82=00 cfg=00 tim=01 p3m1=04
probe ch2=FFFF ch10=FFFF ref15=FFFF -> use ch2
```
判读：**P3M1(0xB1) 写读正常**（对照组成立，SFR 总线没问题），
而 ADC_CONTR(0xBC)/ADCCFG(0xDE) 写什么读回 0、ADCTIM(0xFEA8) 读回 0x01，
内部基准通道 15 也转不出结果 → **这颗片子的 ADC 块不存在**（型号/批次/改标），软件无解。

**本轮改动**
1. 自检加宽：新增 `IE2`(0xAF)/`WDT_CONTR`(0xC1)/`CLKDIV`(0xFE01) 对照组，
   一次分清"只缺 ADC 块"与"整片 SFR/EAXFR 坏"。
2. `CFG_MQ_AUTO_DO`（默认 1）：ADC 自检失败 → **自动降级到数字 DO 模式**
   （P3.2 改准双向、读 LM393 输出、`CFG_MQ_DO_ACTIVE_LOW` 可翻转极性），
   阈值/报警/显示逻辑不变，不再显示 noAd 白摆着。
3. 状态行新增 `d=`（0=模拟 1=数字），横幅新增 `mq=digital-DO / analog-ADC`。

**当前状态**：EEPROM 地址已修（0x0E00，应能存住）、键位已交换（CFG_KEY_SWAP=1）、
ADC 走降级。用户下一步：把模块 DO 接到 P3.2（或换真正的 1K08A）。

构建：default / autoDO=0 / forceDO / gpiokey / nodbg / restore 六种组合均 0 Error 0 Warning；
默认 code=5194B。

## 第七轮：确认降级已生效，补最后一个对照（EAXFR）

用户日志 `v=0 err=0 to=0 d=1` → 说明已在数字 DO 模式（自检失败自动降级），v=0 是 P3.2 数字电平低，
不是"ADC 读到 0"。用户坚持芯片是 1K08A（并贴了手册通道表，ch2=P3.2 与我们一致）。

新增探针 `conNoE`：`P_SW2 &= 0x7F`（关 EAXFR）后再写 `ADC_CONTR=0x5A` 并回读，
用来排除"EAXFR=1 导致普通 SFR 读不回"的最后一疑。若 conNoE=5A → 找到软件原因；
若仍 00 → ADC 块确实不存在，只剩片子问题。

**给用户的定性依据（按可信度排序）**
1. `p3m1=04` 对照组正常 + `con5A/con82/cfg=00` + `ref15=FFFF` → ADC 三件套 SFR 不存在。
2. STC-ISP 的"检测MCU选项/下载时识别的型号"是权威判据，可对照丝印。
3. 若换一颗真 1K08A，同一份 hex 应打印 `adc=ok mq=analog-ADC`。

**可选后续路线**：① 换真 A 片子；② 用 DO（已支持，碰一下 GND 即可验证 1023+鸣叫）；
③ 外挂 PCF8591/ADS1115，用空闲的 P3.0/P3.1 软 I2C 接（要新硬件时再实现）。
