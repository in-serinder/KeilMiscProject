## 协议改十六进制 + 写入进度平滑（第二轮联调）

### 编码变更（两端同步）
- `W_` / `R_` 每字节 2 位大写十六进制：`>W_00,1A,FF<`、`>R_00,1A,FF<`（原为十进制）。
- WP / 健康掩码 1 字节十六进制：`SET_..._00_FF_...`（原为 8 位二进制）；`INFO` 一律回十六进制，旧 8 位二进制仍兼容解析。
- 下位机 `parse_hex_byte()` 只接受 1~2 位十六进制，三位十进制会被 `[RX-ERR]` 拒绝（防止两端编码错位）。
- 上位机 `CapsaInfo.Hex/ParseMask`、`WritePacket`、`ReadMemory` 同步修改；`CapsaProtocol.ParseMask` 兼容 8 位二进制。

### 进度“慢-突进”的真实原因（三个叠加）
1. **模拟器每包 fsync**：`_atomic_write` 每 16 B 都 fsync，Windows 建临时文件还触发杀软扫描 → 前几秒 1.4 s/包，之后才 70 包/s。改为写包期间 `durable=False`（只 flush），`TX-OVER`/`ABORT` 时 fsync。
2. **片内进度算错**：`CapsaProtocol.WriteMemory` 的回调第 1 个参数是**百分比**（0-100），第 2 个才是字节数；原代码当成 `current/max` → 卡片永远 1.2%。改为按 `current/100*size` 折算字节数。
3. **UI 回调排队**：`Progress<T>` 逐包 post 到 UI，界面更新落后于传输。改为“后台只写不可变快照（`ProgressSnapshot` 引用原子替换，避免结构体撕裂读）+ `DispatcherTimer` 200 ms 取最新值上屏”，并让传输层每 150 ms 才回调一次。

### 其他修正
- 写入/校验分阶段共用一条进度条：写入 0→85%，校验 85→100%，不再回跳。
- 顺序写入时 `FlushProgress` 把地址小于当前片的卡片直接标满（收尾回调可能被节流吞掉）。
- 卡片改用 `TransferProgress.ChipBytes`（已写字节）驱动：末片只写部分时停在 43.8%，不再“满格后回落”。
- 走查工具 `Diagnostics/ScreenshotHarness.cs` 增加写 156 kbit 的 w1/w2/w3/w4 截图（临时计时/心跳代码已清理）。

## 读取进度修 100% 溢出 + 读取可视化 + 写入/校验文案 + 文件名往返

- **进度 >100% 根因**：`CapsaProtocol.ReadMemory` 的回调传的是**字节数**，而 `WriteMemory` 传的是**百分比**；
  传输层按百分比折算 → 读数被当百分比放大 100 倍。现在两者统一为「百分比 0-100 + 总字节数」，
  `CapsaChipTestService` / `CapsaTransferService` 的折算都按百分比。
- **校验结尾显示“Verifying…”**：`WriteVerifyAsync` 的 finally 里 `FlushProgress()` 把排队中的旧快照刷回了成功文案。
  现在 finally 只停表并清空 `_hasPending` / `_latest`；成功文案改为
  `Write & verify OK · 19.5 KB + 14 B trailer · 19.5 KB used space recorded`。
- **校验方式**：写完后对同一 payload（含 trailer）整段回读，逐字节比对，统计不一致字节数与首个出错偏移
  （`Verify failed · N mismatched byte(s), first at 0xXXXX`）。
- **读取可视化**：`ChipSlotViewModel` 新增 `IsReadActive` / `ReadPercent` / `ReadRatio`，卡片 XAML 在蓝色占用之上叠一层
  绿色（`Capsa.Read`，0.85 不透明度）按 `ReadRatio` 缩放；`ChipBoardViewModel.BeginRead / ReportReadProgress /
  ApplyReadCoverage / ClearReadOverlay`；`ReadPanelViewModel` 注入 Board，读完按 `clamp(total-i×cap)` 铺满；

- **文件名往返**：trailer v2 改为 `[data][文件名 UTF-8][长度 1B]["CSNX"]`（≤40 B，超长退回 `dump.<ext>`），
  仍兼容旧 `CSFX`（只存扩展名）；导出用还原出的文件名作为默认名。

  控件自己处理滚轮（`OnPointerWheelChanged`），不会与 ScrollViewer 双倍滚动。
- **读取模式不能切编码**：`TextEditorView.axaml` 的 ComboBox 原先绑 `IsEnabled="{Binding !IsReadOnly}"`，直接去掉；
  只读会话里 `CommitText()` 本来就早退、`TextEditorView` 也只读不提交，所以切编码只影响解码显示，不写回缓冲区
  （实测 UTF-8 → GB18030 后 `ByteLength` 4096 不变）。

## 编码下拉框改为“真转码”（写入模式不再乱码）

- 原实现：切编码只是 `Text = document.Decode(newEncoding)`，等于拿新编码重新解释旧字节 → 必然乱码。
- 现在 `EditorSessionViewModel.OnSelectedEncodingChanged`：先记住 `_appliedEncoding`（缓冲区当前字节对应的编码），
  写入模式下尝试 `TryTranscode(from, to)`：解码成文本 → 用新编码重新编码 → 替换缓冲区（`EditorChangeSource.Encoding`）。
- 三条安全闸（任一不满足就退回“只换显示编码”，字节不动）：
  1. `LooksLikeText(text)`：出现 U+FFFD 或不可打印控制符（除 \t \n \r）视为二进制；
  2. `from.GetBytes(text)` 必须与现有字节完全一致（旧编码下无损往返）；
  3. `to.GetString(to.GetBytes(text)) == text`（新编码能表示全部字符，否则会变 '?'）。
- 只读会话（读取模式）永远只换显示解码，绝不改字节 —— 保证读回的文件能原样导出。
- `HexEditorView` 记录 `_loadedBytes`：`Encoding` 事件时若字节真的变了才 `Rebuild()`（重新装 LineReader），
  否则只 `ApplyFormatter()`，保留滚动位置。
- 验证：`--self-test` 新增 7 项（utf8↔gbk↔utf16 往返、二进制不动、只读不动、Shift_JIS 表示不了 emoji 时不转码）全 PASS；
  走查新增 `16-encoding-transcoded.png` + `encoding-transcode.txt`（`中文测试 abc` 切 GBK 后 `D6D0CEC4B2E2CAD420616263`，PASS）。
