## 排查“破坏 EEPROM 数据后读取仍通过” + 让校验结论不可能被静默跳过

  ② 改错文件（`24C64` vs `24C128` / 改到别的片）；③ 改的偏移 ≥ `UGS`（哈希只覆盖 `0 ~ used-1`）；
  ④ 破坏后又写了一次（哈希被更新）。

    Mismatch 仍弹 `Data may be corrupted` 但保留数据。
  - `ReadVerifyAsync` 在读取前 `AppServices.Device.ReadDeviceInfoAsync()` 刷新 GET/UGS/DIG，避免用陈旧 used/hash 决定“读多少、和谁比”。

## Capsa 下位机固件（STC8G1K17A）首次实现（11-06）
- 架构：IIC1（P3.2/P3.3，硬件 I2C，I2C_S=11）挂 8×24Cxx(0x50-57) + PCF8574T(0x20)；IIC2（P5.4/P5.5，**软件 I2C**）挂 24C02(0x51) + SSD1315(0x3C,128×32)；UART1 P3.0/P3.1 115200。
- **关键硬件事实**：STC8G1K17A 只有 1 个 I2C 外设（stc8g1k.h 只有一组 0xFE80~0xFE87），手册 2.3.5（TSSOP20/SOP16 管脚说明）P5.4/P5.5 **没有 I2C 复用**（SCL_2/SDA_2 是 8 脚 08A 的映射）→ 用户"两个硬件 IIC"实际是 P1.4/P1.5 与 P3.2/P3.3 两组，P5.4/P5.5 只能软 IIC。已在 README/board.h 说明。
- 新增 firmware/{system,hardware,user,tools}，约 3770 行；capsa.uvproj 由 copier.uvproj 改造（Device=AT89C52 兼容，IROM 0x0000~0x43FF，OutputName=capsa）。
- 编译结果：**data=93.1 / xdata=811 / code=16608（Flash 17408，余 800B），0 Error 0 Warning**。
- 踩坑记录（重要，下次直接用）：
  1. **hardware/board.h 旧文件遮蔽**：`#include "board.h"` 优先当前文件目录，hardware/ 下残留的旧 board.h（TM1637 版）会盖掉 system/board.h → 大量"宏未定义"。删旧文件即解决。
  2. C51 关键字不能做标识符/参数名：`code`、`bit`、`data`（曾用 `uint8_t bit`、`const char code *code`）。
  3. C51 无 64 位整型，`uint64_t` 全改 32 位（1MB×1000 仍 < 2^32）。
  4. SMALL 模式下局部数组占 128B data → 48B 缓冲就溢出（L107 ADDRESS SPACE OVERFLOW）；大数组统一 static xdata。
  5. 头文件跨目录嵌套 include 的正斜杠/相对路径坑：每个 .c 顶部显式 `#include "board.h"` 最稳。
  6. Python heredoc 里 `\0` 会被 bash 变 `\0` → 写进 C 源码变真 NUL（C101 invalid character constant）。用 Edit 工具改这类行。
  7. 未调用函数触发 L16 UNCALLED SEGMENT：要么删，要么真正用起来（本次把 Board_SwI2cPinsOk/EE_ScanMask/I2C2_Probe/PCF_Read 用到上电自检、总线恢复、写保护回读校验里）。
- 设计要点：进度按 5% 节流刷 OLED（一次状态行刷新 ~18ms，不节流会把 5ms 写周期拖成 23ms）；Proto_Poll 加 ES=0/1 临界区防中断覆盖帧；Meta_FirstSet 只清 0x00~0x2B + USED + RESERVED，DI 区仅出厂空白态才规范成 0（延续"寿命计数不清零"规则）。
- 待硬件验证：OLED COM 0x02/0x12、OLED 地址 0x3C/0x3D、软 IIC 速率 CFG_SW_I2C_DELAY、24C02 写周期 5/10ms。
