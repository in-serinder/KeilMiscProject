# 《Capsa 存储卡 · 下位机模拟器 指令文档》

> 适用范围：`CapsaSim`（模拟下位机）与 `Capsa`（上位机）联调
> 协议版本：v1.0 · 帧格式 `>命令<` / `[应答]`
> 传输：串口 115200 8N1（默认 COM1）或 `--stdio` 字节流

---

## 1. 协议约定

| 方向 | 帧格式 | 示例 |
| --- | --- | --- |
| 上位机 → 下位机 | `>命令<` | `>TYPE-CAPASA<` |
| 下位机 → 上位机 | `[应答]` | `[RX-OK]` |
| 下位机 → 上位机（数据） | `>数据<` | `>INFO_...<`、`>R_...<` |

> **数据编码**：`W_` / `R_` 的每个字节统一写成 **2 位大写十六进制**（`FF`、`0A`），
> 用 `,` 分隔；WP / 健康掩码同样写 1 字节十六进制（`FF` / `00`）。
> 相比十进制（最长 3 字符）与 8 位二进制串，单包报文缩短约 25%~75%，串口带宽更省。

* 所有命令与应答均为 ASCII，唯一的例外是 `INFO` 中的卡名称（UTF-8）。
* 帧以 `>` 起始、`<` 结束；应答以 `[` 起始、`]` 结束。解析器会忽略帧外的空白与噪声字节。
* 命令大小写不敏感（`int_w` 与 `INT_W` 等价），但文档统一使用大写。
* 换行符（`\r\n`）可有可无，不参与解析。
* 数值参数同时接受 `0x50` 与 `80` 两种写法（十六进制带 `0x` 前缀）。

## 3. 24C02 元数据映射（256 B）

| 偏移 | 字段 | 长度 | 说明 |
| --- | --- | --- | --- |
| 0x00 | 初始化标志 | 1 B | 0x01 = 已初始化，其他值视为未初始化 |
| 0x01 | WP 掩码 | 1 B | bit0~bit7 对应 0x50~0x57，1 = 写保护 |
| 0x02 | 健康掩码 | 1 B | bit0~bit7 对应 0x50~0x57，1 = 健康 |
| 0x03 ~ 0x16 | 卡名称 UTF-8 | 20 B | `\0` 结尾，禁止 `_` 与 `!` |
| 0x17 ~ 0x18 | 阵列容量 KB | 2 B | uint16，小端 |
| 0x19 ~ 0x1C | 上次修改时间 | 4 B | uint32，Unix 秒 UTC，小端 |
| 0x1D ~ 0x20 | 最后读取时间 | 4 B | uint32，Unix 秒 UTC，小端 |
| 0x21 | 介质枚举 | 1 B | 0 EEPROM / 1 FRAM / 2 EERAM / 3 SRAM |
| 0x22 ~ 0x25 | 芯片型号 | 4 B | uint32，Kbit 数值，小端（24C64 → 64） |
| 0x26 ~ 0x2B | 唯一 UID | 6 B | 6 字节 |
| 0x2C ~ 0x31 | 当前已使用空间 | 6 B | uint48，小端，单位 **B**；只由 `UG` 写入 |
| 0x32 ~ 0x39 | 数据哈希 | 8 B | 上位机计算并下发（`DI`），下位机只存储、不校验 |
| 0x3A ~ 0x3D | 累计写入次数 | 4 B | uint32 小端；由上位机 +1 后经 `DI` 下发，下位机不自动递增；**任何初始化都不清零** |
| 0x3E ~ 0xF5 | 预留扩展 | 184 B | 首次 SET 时清零 |
| 0xF6 ~ 0xFF | 初始化检测区 | 10 B | 全 0xFF = 未初始化 |

> 已使用空间单位是**字节**而不是 KB，最大 `2^48 - 1` B。下位机只负责存储，
> 不做任何统计；首次 SET 时写 `0x000000000000`，之后只能通过 `UG` 更新。
>
> **`0x3A ~ 0x3D`（累计写入次数）是 EEPROM 的寿命指标**：它不是数据内容的一部分，
> 而是记录这块卡被写了多少轮。因此首次 SET、重新初始化、格式化都**不得清零**，
> 只能由上位机在写入完成后经 `DI` 递增。`0x32 ~ 0x39`（哈希）描述的是数据内容，
> 数据被覆写后即失效，允许被清成 8 个 0（上位机把全 0 视为“无记录”）。

字节序统一小端。

## 4. 初始化与检测规则

### 4.1 上电检测

读取 `0xF6 ~ 0xFF` 共 10 字节：

* 全 `0xFF` → **未初始化**
* 存在非 `0xFF` 字节 → **已初始化**

### 4.2 未初始化时

| 命令 | 应答 |
| --- | --- |
| `>GET_!<` | `[SET_ERR]` |
| `>TYPE-CAPASA<` | `[YES]`（设备类型确认与初始化无关） |

### 4.3 首次 SET

1. `0x00 ~ 0x2B` 全部写 `0x00`；
2. 写入 SET 提供的字段；
3. `0x00` 置 `0x01`；
4. `0x2C ~ 0x31` 写 6 字节 `0x00`（已使用空间归零）；
5. `0x3E ~ 0xF5` 写 `0x00`（预留扩展区）；
6. `0x32 ~ 0x3D`（哈希 + 累计写入次数）：
   * 仅当该 12 B 处于**出厂空白态**（全 `0xFF` 或全 `0x00`）时写成 8 + 4 个 `0x00`；
   * 已有记录（哪怕是“检测区丢标志”导致的二次首次初始化）时**原样保留**，
     绝不清零写入次数；
7. `0xF6 ~ 0xFF` 写 `0x00`；
8. UID 为 `!` → 随机生成 6 字节；
9. 型号为 `!` 或 `0` → 写入默认 `64`；
10. 写 24C02 后等待 5 ms；
11. WP 掩码下发 PCF8574（若有变化）并等待 5 ms；
12. 若型号与当前不一致，重建 8 片 bin 文件。

### 4.4 后续 SET

* 只更新非 `!` 字段；
* `0x00` bit0 保持 `0x01`；
* UID 为 `!` 保持不变；
* 型号显式写 `0` 时按 24C64 处理并写入 `64`；
* WP 掩码变化后立即下发 PCF8574 并等待 5 ms；
* **不修改 `0x2C ~ 0x31`**（已使用空间只由 `UG` 更新）；
* **不修改 `0x32 ~ 0x3D`**（哈希与累计写入次数只由 `DI` 更新）。
  “对已初始化卡重新初始化”走的正是这条路径，所以写入次数天然保留。

## 5. 命令一览

### 5.1 上位机 → 下位机

| 命令 | 说明 | 应答 |
| --- | --- | --- |
| `>TYPE-CAPASA<` | 确认是本项目存储卡 | `[YES]` |
| `>SET_名称_WP_健康_容量_型号_修改时间_读取时间_介质_UID<` | 设置属性，`!` 表示不修改 | `[SET-OK]` / `[SET_ERR]` |
| `>GET_!<` | 查询全部属性 | `>INFO_...<` / `[SET_ERR]` |
| `>UG_已使用字节数<` | 设置当前已使用空间（十进制，单位 B） | `[UG-OK]` / `[SET_ERR]` / `[RX-ERR]` |
| `>UGS<` | 查询当前已使用空间 | `[UG-已使用字节数]` / `[SET_ERR]` |
| `>DI_哈希_次数<` | 设置数据哈希（16 位十六进制）与累计写入次数（十进制 uint32），`!` 表示不修改 | `[DI-OK]` / `[SET_ERR]` / `[RX-ERR]` |
| `>DIG<` | 查询数据哈希与写入次数 | `[DIG-哈希-次数]` / `[SET_ERR]` |
| `>ROUTER_芯片地址<` | 选择目标芯片（0x50~0x57） | `[RX-OK]` / `[RX-ERR]` |
| `>ADDR_芯片末尾地址<` | 设置片内末尾地址 | `[RX-OK]` / `[ERR_EXT]` |
| `>INT_W<` | 启动写 | `[RX-OK]` / `[RX-ERR]` / `[ERR_WP]` |
| `>W_d1,d2,…,d16<` | 写一包 16 字节（每字节 2 位十六进制） | `[RX-OK]` / `[RX-ERR]` / `[ERR_WP]` / `[ERR_EXT]` |
| `>TX-OVER<` | 写结束 | `[RX-OK]` |
| `>INT_R<` | 启动读 | `[RX-OK]` / `[RX-ERR]` |
| `>ABORT<` | 中断当前读写 | `[ABORT-OK]` |

### 5.2 下位机 → 上位机

| 应答/数据 | 说明 |
| --- | --- |
| `[YES]` | 设备类型确认 |
| `[SET-OK]` | 属性设置成功 |
| `[SET_ERR]` | 属性设置失败 / 卡片未初始化 |
| `[UG-OK]` | 已使用空间设置成功 |
| `[UG-<字节数>]` | 已使用空间查询结果（十进制，单位 B） |
| `[DI-OK]` | 数据哈希 / 写入次数设置成功 |
| `[DIG-<哈希>-<次数>]` | 查询结果，哈希 16 位大写十六进制、次数十进制 |
| `>INFO_...<` | 属性查询结果（9 字段） |
| `[RX-OK]` | 接收 / 操作成功 |
| `[RX-ERR]` | 接收失败 / 状态不匹配 |
| `[ERR_EXT]` | 地址溢出 |
| `[ERR_WP]` | 写保护开启，拒绝写入 |
| `>R_d1,d2,…,d16<` | 读流程中的一包数据（每字节 2 位十六进制） |
| `>TX-OVER<` | 读流程发送完成 |
| `[ABORT-OK]` | 中断成功 |

> 主机在收到 `>R_...<` 后必须回 `[RX-OK]`，否则下位机等待 `--rx-timeout`（默认 2 s）后回 `[RX-ERR]` 并停止。

## 6. SET / GET 字段编码

固定 9 个字段，使用 `_` 分隔：

| # | 字段 | 编码 | 示例 | `!` 语义 |
| --- | --- | --- | --- | --- |
| 1 | 名称 | UTF-8，禁止 `_`/`!`，≤ 20 B | `DEV1` | 不修改 |
| 2 | WP | 1 字节十六进制（2 字符），bit7~bit0 ↔ 0x57~0x50 | `F0` | 不修改 |
| 3 | 健康 | 1 字节十六进制（2 字符），bit7~bit0 ↔ 0x57~0x50 | `FF` | 不修改 |
| 4 | 容量 | 十进制，KB | `64` | 不修改 |
| 5 | 型号 | 十进制，Kbit；`0` 按 24C64 处理 | `64` / `1024` | 不修改 |
| 6 | 修改时间 | 十进制 Unix 秒 | `1700000000` | 不修改 |
| 7 | 读取时间 | 十进制 Unix 秒 | `1700000000` | 不修改 |
| 8 | 介质 | 十进制 0~3 | `0` | 不修改 |
| 9 | UID | 12 位十六进制（6 B） | `A1B2C3D4E5F6` | 不修改 |

### 示例

```text
首次初始化（24C64 阵列，64 KB）
>SET_DEV1_00_FF_64_64_1700000000_1700000000_0_A1B2C3D4E5F6<
[SET-OK]

只改名称
>SET_DEV2_!_!_!_!_!_!_!_!<
[SET-OK]

查询
>GET_!<
>INFO_DEV2_00_FF_64_64_1700000000_1700000000_0_A1B2C3D4E5F6<
```

字段数量不等于 9、掩码不是 2 位十六进制（兼容旧的 8 位二进制）、UID 非 12 位十六进制、
名称含非法字符或超长、型号不受支持，均返回 `[SET_ERR]`。

> 兼容性：下位机与上位机都仍接受旧的 `00000000` / `11111111` 写法，但 `INFO` 一律回十六进制。
> 新代码请使用 `00` / `FF`。

## 6A. UG / UGS（已使用空间）

已使用空间保存在 24C02 `0x2C ~ 0x31`（uint48 小端，单位 **B**），用来记录上位机
写入存储卡后实际占用的字节数。

### 6A.1 `>UG_已使用字节数<`

| 项目 | 规则 |
| --- | --- |
| 参数 | 十进制字符串，单位 B，例如 `12345` |
| 取值 | `0 ~ 当前阵列总容量`（8 片 24C64 → `0 ~ 65536`） |
| 参数非法 / 越界 | `[RX-ERR]`（含空参数、负数、十六进制、非数字） |
| 24C02 未初始化 | `[SET_ERR]` |
| 成功 | 写 `0x2C ~ 0x31`（6 B 小端）→ 等 5 ms → 落盘 `meta_24c02.bin` → `[UG-OK]` |

* 不修改其他元数据字段，**不**自动更新「上次修改时间」。
* 下位机只存储，不统计；实际占用由上位机计算。
* 阵列总容量随型号变化：8 × 24C256 → 上限 `262144` B。

### 6A.2 `>UGS<`

| 项目 | 规则 |
| --- | --- |
| 24C02 未初始化 | `[SET_ERR]` |
| 已初始化 | 读 `0x2C ~ 0x31` 转十进制 → `[UG-已使用字节数]` |

### 6A.3 示例

```text
>UG_12345<
[UG-OK]

>UGS<
[UG-12345]

# 上限
>UG_65536<
[UG-OK]

# 越界
>UG_65537<
[RX-ERR]

# 未初始化
>UG_100<
[SET_ERR]
>UGS<
[SET_ERR]
```

### 6A.4 与上位机的配合

```text
上位机导入文件 → 按芯片容量切片 → 顺序写 0x50, 0x51, … → 回读校验
      → >UG_<写入总字节数><   → [UG-OK]
      → >UGS<                → [UG-<n>]  （刷新界面的容量占用）
```

界面上的「已使用空间」只认 `UGS` 的返回值；每片卡片的占用由上位机按地址顺序
把总量切开：`chip(i) = clamp(total - i × 单片容量, 0, 单片容量)`。

## 6B. DI / DIG（数据哈希 + 累计写入次数）

两个字段都在 24C02：

| 地址 | 字段 | 长度 | 说明 |
| --- | --- | --- | --- |
| `0x32 ~ 0x39` | 数据哈希 | 8 B | 上位机计算并下发，下位机**只存储** |
| `0x3A ~ 0x3D` | 累计写入次数 | 4 B | uint32 小端，上位机 +1 后下发，下位机**不自动递增** |

> **哈希算法由上位机定义**：本项目上位机固定使用 **FNV-1a 64 位**
> （offset basis `14695981039346656037`，prime `1099511628211`），
> 结果按 16 位大写十六进制发送。下位机不参与计算，换成别的算法只需两端一致。

### 6B.1 `>DI_哈希_次数<`

| 项目 | 规则 |
| --- | --- |
| 字段 1（哈希） | 16 位十六进制字符串，表示 8 字节，如 `A1B2C3D4E5F60708` |
| 字段 2（次数） | 十进制字符串，`0 ~ 4294967295`（uint32） |
| `!` | 该字段不修改；`>DI_!_!<` 合法，等于只做探测 |
| 24C02 未初始化 | `[SET_ERR]` |
| 字段数不等于 2、哈希长度不是 16 / 非十六进制、次数非十进制或越界 | `[RX-ERR]` |
| 成功 | 写 `0x32 ~ 0x39` / `0x3A ~ 0x3D` → 等 5 ms → 落盘 → `[DI-OK]` |

* 不修改其他元数据字段（含已使用空间、时间戳、WP / 健康掩码）。
* 下位机不校验哈希内容，也不在 `TX-OVER` 后自增次数。

### 6B.2 `>DIG<`

| 项目 | 规则 |
| --- | --- |
| 24C02 未初始化 | `[SET_ERR]` |
| 已初始化 | 读 8 B 哈希 → 16 位大写十六进制；读 4 B 次数 → 十进制；回 `[DIG-哈希-次数]` |

### 6B.3 示例

```text
>DI_A1B2C3D4E5F60708_1<
[DI-OK]

>DIG<
[DIG-A1B2C3D4E5F60708-1]

# 只改次数
>DI_!_2<
[DI-OK]
>DIG<
[DIG-A1B2C3D4E5F60708-2]

# 只改哈希
>DI_1122334455667788_!<
[DI-OK]

# 什么都不改（可用于探测命令是否被支持）
>DI_!_!<
[DI-OK]
```

### 6B.4 与上位机的配合

```text
写：TX-OVER 收到 [RX-OK]
      → 上位机对整次写入的数据（含文件 trailer）计算 FNV-1a 64
      → 次数 = DIG 读到的次数 + 1
      → >DI_<哈希>_<新次数><   → [DI-OK]

读：INT_R 读完整卡数据 → TX-OVER
      → >DIG< 取存储的哈希与次数
      → 上位机对读回数据重新计算哈希
      → 一致：正常；不一致：提示“数据可能已损坏”，但**不中断、不丢弃**已读数据
```

* 下位机不返回哈希错误码，也不会主动中断读取。
* 只在「读取长度 = 已使用空间」时比较哈希；`UGS = 0` 时的整卡回退读取会带上 `0xFF` 空白，不参与比较。
* **累计写入次数是寿命指标**：它只增不减，初始化（首次 SET / 重新初始化）与格式化都
  不会清零，唯一的修改途径是写入成功后的 `DI` 递增。上位机把全 `0` 的哈希视为
  “无记录”（格式化 / 初始化后写入的占位值），因此不会误报数据不一致。

## 7. 写流程时序

```text
上位机                                下位机
  |  >ROUTER_0x50<   ----------------->  |  选择芯片，清空 ADDR
  |  <---------------- [RX-OK]           |
  |  >ADDR_0x1FFF<   ----------------->  |  设定末尾地址 0x1FFF（8 KB）
  |  <---------------- [RX-OK]           |
  |  >INT_W<         ----------------->  |  检查 ROUTER/ADDR/WP
  |  <---------------- [RX-OK]           |  进入写模式，指针 = 0
  |  >W_00,1A,FF,…<  ----------------->  |  写入 min(16, ADDR-ptr+1) 字节
  |  <---------------- [RX-OK]           |  指针 += N，落盘 bin，等待 0.8+5 ms
  |  >W_d1..d16<     ----------------->  |
  |  <---------------- [RX-OK]           |
  |  >TX-OVER<       ----------------->  |  结束写会话（保留 ROUTER/ADDR）
  |  <---------------- [RX-OK]           |
```

规则：

| 条件 | 结果 |
| --- | --- |
| 未 `ROUTER` 或未 `ADDR` 就 `INT_W` | `[RX-ERR]` |
| 目标芯片 WP 位 = 1 | `INT_W` / `W_` 返回 `[ERR_WP]` |
| 指针已越过 `ADDR` 仍发 `W_` | `[ERR_EXT]` |
| 一包超过 16 字节 / 字节格式非法 | `[RX-ERR]` |
| `TX-OVER` 之后 | 保留 ROUTER / ADDR，可直接再次 `INT_W` |

* 有效长度 `N = min(16, ADDR - 当前地址 + 1)`；
* 末包不足 16 B 由上位机补 `0x00`，补的字节不会写到 `ADDR` 之后；
* 每包写成功后立即更新 bin 文件。

## 8. 读流程时序

```text
上位机                                下位机
  |  >ROUTER_0x50<   ----------------->  |
  |  <---------------- [RX-OK]           |
  |  >ADDR_0x1FFF<   ----------------->  |
  |  <---------------- [RX-OK]           |
  |  >INT_R<         ----------------->  |  进入读模式，指针 = 0
  |  <---------------- [RX-OK]           |
  |  <---------------- >R_00,1A,FF,…<    |  min(16, ADDR-ptr+1) 字节，末包补 0x00
  |  [RX-OK]         ----------------->  |  指针 += N，等待 0.8 ms
  |  <---------------- >R_d1..d16<       |
  |  [RX-OK]         ----------------->  |
  |  <---------------- >TX-OVER<         |  读结束（保留 ROUTER/ADDR）
```

规则：

| 条件 | 结果 |
| --- | --- |
| 未 `ROUTER`/`ADDR` 就 `INT_R` | `[RX-ERR]` |
| 主机超时未回 `[RX-OK]` | `[RX-ERR]` 并停止 |
| 主机回 `[ABORT]` | `[ABORT-OK]` 并停止 |
| 主机回其他内容 | `[RX-ERR]` 并停止 |

* 读不受写保护影响；
* 每包模拟 I2C 传输 0.8 ms；
* `--stdio` 模式为阻塞等待（管道无跨平台超时读），串口模式严格执行 `--rx-timeout`。

## 9. 写保护与 PCF8574

* PCF8574 位于 I2C2，7 位地址 `0x58`，输出位 `1` = 开启写保护。
* WP 掩码 bit0~bit7 对应 0x50~0x57。
* `SET` 中 WP 掩码变化后立即下发，并等待 5 ms。
* 目标芯片 WP = 1 时：`INT_W` 与 `W_` 均返回 `[ERR_WP]`；读操作不受影响。

示例：`SET_!_00000011_!_!_!_!_!_!_!` → 0x50、0x51 被保护，其余可写。

## 11. 错误码表

| 应答 | 触发条件 |
| --- | --- |
| `[RX-ERR]` | 接收失败、状态不匹配、未 ROUTER/ADDR 就 INT_W/INT_R、串口超时、数据格式错误、未知命令 |
| `[ERR_EXT]` | ADDR 超过当前芯片末地址，或写指针越过 ADDR |
| `[ERR_WP]` | 目标芯片写保护开启，拒绝 INT_W 或 W_ |
| `[SET_ERR]` | SET 字段非法 / 写 24C02 失败，或 GET / UG / UGS 时未初始化 |
| `[UG-OK]` | UG 成功写入已使用空间 |
| `[UG-<n>]` | UGS 查询结果（十进制字节数） |
| `[DI-OK]` | DI 成功写入数据哈希 / 写入次数 |
| `[DIG-<哈希>-<次数>]` | DIG 查询结果 |
| `[ABORT-OK]` | ABORT 成功 |

## 12. 状态保持与默认值

| 项目 | 行为 |
| --- | --- |
| 上电默认 ROUTER | 0x50（但 `INT_W`/`INT_R` 仍要求显式 `ROUTER`） |
| `ROUTER` 之后 | 清空 `ADDR` 与读写模式，必须重新 `ADDR` |
| `ADDR` 之后 | 清空读写模式；指针在 `INT_W`/`INT_R` 时归零 |
| `TX-OVER` 之后 | 保留 ROUTER / ADDR |
| `ABORT` 之后 | 清除读写模式，保留 ROUTER / ADDR |
| `TYPE-CAPASA` | 不改变任何状态 |
| 型号字段 0 | 按 24C64 处理，边界 `0x0000 ~ 0x1FFF` |
| 型号字段 `!` 且首次初始化 | 写入默认 64 |
| 已使用空间 | 首次 SET 归零，之后仅 `UG` 可改，`SET` 不触碰 |
| 数据哈希 | 首次 SET 清成 0（仅出厂空白态），之后仅 `DI` 可改，`SET` 不触碰 |
| 累计写入次数 | **任何初始化都不清零**（寿命指标），仅写入成功后由 `DI` 递增 |

## 14. bin 文件说明

### 14.1 生成

* 启动时按 `--data-dir` 打开目录，不存在则创建；
* 每个 24Cxx 若文件不存在 → 用 `0xFF` 填满对应容量并写盘；
* `meta_24c02.bin` 同理（256 B 全 `0xFF` = 未初始化）。

### 14.2 写入

* 每次 `W_` 成功后立即写回对应 bin（先写 `.tmp` 再 `os.replace`，避免掉电损坏）；
* 写流程中的逐包落盘只做 **flush**（`durable=False`），`TX-OVER` / `ABORT` 时再对该片做一次
  **fsync**（`durable=True`）。原因：每 16 B 包都强制 fsync 会在 Windows 上比真实 I2C 慢一个数量级
  （每包新建临时文件还会触发杀软扫描），导致上位机进度条“爬得很慢再突然拉满”；
* `SET` / `UG` / 型号变更成功后立即写回 `meta_24c02.bin`（fsync）；
* PCF8574 只保存在内存，不落盘。

### 14.3 型号变更

`SET` 修改型号时：

1. 计算新容量并重新分配内存；
2. 原数据按最小长度保留，其余补 `0xFF`；
3. 以新文件名落盘（如 `eeprom_0x50_24C128.bin`）；
4. 删除旧型号文件。

### 14.4 校验

```bash
ls -l data/
# eeprom_0x50_24C64.bin  ... 每片 8192 B
# meta_24c02.bin         256 B

xxd -l 32 data/eeprom_0x50_24C64.bin     # 前 32 字节应为刚写入的内容
xxd -s 0x2C -l 6 data/meta_24c02.bin     # 已使用空间（uint48 小端）
xxd -s 0x32 -l 12 data/meta_24c02.bin    # 数据哈希 8B + 写入次数 4B（uint32 小端）
xxd -s 0xF6 -l 10 data/meta_24c02.bin    # 10 个 0x00 表示已初始化
```

`UG_12345` 之后 `0x2C ~ 0x31` 应为 `39 30 00 00 00 00`（12345 = 0x3039，小端）。

## 附录 A · 实现约定（与任务书字面差异说明）

| 项 | 任务书 | 实现 | 说明 |
| --- | --- | --- | --- |
| `SET` 失败应答 | `[SET_ERR]` | `[SET_ERR]` | 与 `[SET-OK]` 的中划线风格不同，按任务书原文保留 |
| 首次 SET 中 `!` 的健康掩码 | 未定义 | 默认 `0xFF`（全健康） | 避免新建卡“全部异常” |
| 数据包字节编码 | 任务书未规定 | 2 位十六进制（`FF`） | 早期实现用十进制，2026-10-31 按需求改为十六进制省带宽 |
| WP / 健康掩码编码 | `11110000` 形式 | 2 位十六进制（`F0`） | 同上；旧写法仍被接受 |
| 首次 SET 中 `!` 的其他字段 | 未定义 | 名称空、WP=0、容量 0、时间 0、介质 0 | — |
| `W_` 字节数 | 固定 16 | 1~16 均可，少的按 0x00 补齐 | 兼容上位机末包精简发送 |
| `W_` 超过 16 字节 | — | `[RX-ERR]` | 视为格式错误 |
| `--stdio` 读超时 | 2 s | 阻塞等待 | 管道无跨平台超时读；串口模式严格超时 |
| `ROUTER` 之后 | 未定义 | 清空 ADDR，需重新 `ADDR` | 避免跨芯片沿用旧边界 |
| `ADDR` 未 `ROUTER` | — | `[RX-ERR]` | 与“必须先 ROUTER”一致 |
| 读流程外收到 `[RX-OK]` | — | 静默忽略 | 防止主机多发一包 ACK 触发 `[RX-ERR]` |
