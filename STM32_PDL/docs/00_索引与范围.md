## 0. 已确定的技术前提

| 项 | 结论 |
|---|---|
| 定位 | **高频功率记录仪**，**4 路功率（V+I）+ 2 路温度**，长时间记录 |
| 下位机 | **STM32F103C6T6**（32 KB Flash / 10 KB RAM / USB FS / 12 bit ADC） |
| 电压采集 | **每通道独立分压**：CH0=12 V / CH1=24 V / CH2=64 V / CH3=100 V；满量程 14.2 / 28.1 / 75.9 / 102.3 V |
| 电流采集 | **ACS712-05B ×3（±5 A）+ 20 A 版 ×1**（CH3 抓尖峰），运放电平搬移，单极性 |
| 温度采集 | **DS18B20 ×2，两条独立 1-Wire 总线**；PB0/PB1 留空 |
| 通讯 | USB HID 64 B / 1 ms（方案 A，兼容性优先） |
| 下位机模拟器 | **Python + Tkinter** |
| 上位机 | **Avalonia 11.3 / .NET 8 / CommunityToolkit.Mvvm**（`PDL_upper`） |
| 记录模式 | 手动 / 定时 / 触发（电压·电流·功率三选一，带消抖） |
| 存储 | RAW + 四档金字塔（tier0 逐点不丢） |
| 视觉 | 沿用 `51_PWMCtrol` 深色卡片风 |
| 顺序 | 先写模拟器 + 上位机，**硬件等需求定完再设计** |

## 1. 一句话定义

一套用于**长时间记录多路电压 / 电流 / 功率**的测量工具：STM32 下位机负责采样，通过 **USB HID（免驱）** 把数据送到上位机，上位机负责实时显示、长时间落盘、统计与导出。

典型被测对象：设备对外放电口、Buck / Boost / Buck-Boost 模块输出、电池包、DC-DC 电源模块、充电器。

## 2. 本项目的"先画靶子"策略

由于硬件与固件细节尚未开始，本项目采取**协议先行**的做法：

```
        协议文档（唯一真源）
       ┌────────┴────────┐
  下位机模拟器          上位机
  (先做，可跑通全流程)   (本期交付主体)
       │                  │
       └── 未来替换为 ────┘
          真实 STM32 固件
```

- **下位机模拟器**：完整实现协议状态机 + 可控信号模型（含纹波、噪声、漂移、负载跳变），让上位机可以在没有硬件的情况下开发、调试、做自动化测试。
- **上位机**：本期真正要交付的产品。
- **真实固件**：本期只定义接口契约，不写代码。将来模拟器的协议状态机可以平移到 C 语言固件里。

## 4. 术语表

| 术语 | 含义 |
|---|---|
| **功率通道 (CH0–CH3)** | 一路独立的 V/I 测量对，对应一个功率。共 4 路 |
| **温度通道 (TH0–TH1)** | 独立的温度探头，采样节奏与功率通道分开，共 2 路 |
| **tick（采样节拍）** | 一次功率通道扫描的时刻。一个 tick 产生 mask 内每个通道的 (V, I) 各一个值 |
| **采样率 (sample_rate)** | 功率 tick 频率，单位 Hz。所有启用功率通道共用同一个节拍 |
| **上报周期 (report_interval)** | 下位机攒够多久的功率数据向上位机发一次，单位 ms |
| **温度间隔 (temp_interval)** | 温度的独立上报周期，默认 1000 ms |
| **块 (Block)** | 一个上报周期产生的数据集合，可能被拆分到多个 HID 报文里 |
| **原始计数 (raw count)** | ADC 输出的整数码值，未换算成工程单位 |
| **工程单位换算** | 由上位机用通道校准系数把 raw count 换算成 mV / mA；温度直接是 ℃×16 |
| **聚合 (BIN)** | 下位机在时间窗（桶）内做 min/max/avg/rms 统计后只上报统计值，用于高采样率与超长时间记录 |
| **tier / 四档** | 存储档位：0=逐点无损，1=10ms 桶，2=1s 桶，3=60s 桶 |
| **金字塔 (Pyramid)** | 上位机侧 L0–L3 四层多分辨率存储，回放时按缩放级别选层 |
| **spool** | 会话运行期的临时落盘文件，用户"保存"后才转为正式 `.pdl` |
| **消抖 (hold)** | 触发电平必须持续保持的时间，用于滤掉尖峰误触发 |
| **模拟器 (Simulator)** | 用 Python 冒充下位机，实现同一套协议 |
| **会话 (Session)** | 一次记录，从 START 到 STOP 的一份数据文件 |

## 6. 目标场景与由此推导出的硬需求

| 场景 | 需求推导 |
|---|---|
| 设备对外放电口长时间监视（数小时~数天） | 数据量必须可控 → 需要 BIN 聚合模式 + 磁盘写入不能是瓶颈 |
| Buck/Boost 输出稳定性评估 | 需要看纹波与瞬态 → 需要高采样率 RAW 模式 + 四层金字塔保住包络 |
| 效率测量（Pin/Pout） | 两通道需**同一 tick 采样**，且时间戳对齐 → 顺序扫描 + 同通道 V/I 相邻 |
| 多路对比（4 路不同负载点） | 4 路功率需各自独立量程/校准/标签 |
| 发热与功率的关联分析 | 2 路温度与功率共享时间轴 → 温度块插值到功率 tick |
| 掉线不丢数据 | 下位机缓冲 + 溢出计数，上位机检测丢包并告警 |
| 事后复现与出报告 | 记录文件自描述（通道配置、校准系数、采样率、时间基准） |

## 7. 成功判据（Definition of Done）

1. 上位机能自动发现并**唯一识别**本项目下位机（不会误连其他 HID 设备）。
2. 上位机一条指令即可让指定功率通道以指定间隔持续回数据，**运行中参数被锁定**（改参数必须先停止）。
3. 模拟器可在无硬件条件下跑满 24 小时连续记录，上位机不崩、不丢块、内存不涨。
4. 记录文件可在任意机器上离线回放，曲线与实时一致，四层金字塔缩放无卡顿。
5. 真实固件接入时，**上位机代码零改动**，只换传输层。
