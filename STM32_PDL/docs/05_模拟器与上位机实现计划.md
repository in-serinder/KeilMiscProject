## 1. 三条总原则

1. **协议只有一个真源**：`protocol/pdl_protocol.yaml` → 生成 Python 与 C# 的常量/DTO，绝不许两边手抄。
2. **模拟器就是固件的参考实现**：状态机、参数校验、块组装、触发消抖——固件照着抄即可。所以模拟器不能"随便发点假数据"。
3. **上位机不许直接碰传输层**：换 TCP⇄HID 只换一个类，业务代码零改动。

## 4. 模拟器设计

### 4.1 关键类与职责

```python
# frame.py
class Frame:
    type: int; flags: int; seq: int; payload: bytes
    @staticmethod
    def parse(raw: bytes) -> "Frame | None"      # CRC 失败返回 None
    def encode(self) -> bytes                    # 恰好 64 B，不足补 0

class StreamDecoder:
    """喂入 64 B 块，吐出完整块（含分片重组）"""
    def feed(self, chunk: bytes) -> list["Block"]
```

```python
# device.py
class Device:
    state: State            # BOOT/IDLE/ARMED/RUNNING/DRAINING/ERROR
    cfg: list[ChannelCfg]   # 4 功率 + 2 温度
    def handle(self, f: Frame) -> list[bytes]:   # 返回要发的帧（ACK/EVENT）
    def on_tick(self, t_us: int) -> list[bytes]: # 由采样线程调用，产出块
```

**要点**：`handle()` 与 `on_tick()` 必须**无阻塞、无 IO**，输出是一串待发帧。谁发、发多快，交给传输层。这样固件可以直接照搬这个结构。

```python
# sampler.py
class Sampler:
    def tick(self, t_us) -> None                  # 采一次样，进缓冲
    def build_blocks(self) -> list[bytes]         # 按 report_interval 切块并分片
    buffer_level: int
    dropped_ticks: int
```

```python
# trigger.py
class Trigger:
    def arm(self, p: AcquireParams) -> None
    def update(self, v_mv, i_ma, p_mw, dt_us) -> list[Event]
```

消抖实现刻意用**整数 tick 累加**，与固件一致：

```python
if above_start:
    self._hold_us += dt_us
    if self._hold_us >= self.p.start_hold_us:
        self._fire_start()
else:
    self._hold_us = 0        # 关键：回落立刻清零
```

### 4.2 采样线程与时序

```python
period_us = 1_000_000 / sample_rate_hz
next_t = perf_counter_ns() // 1000
while running:
    now = perf_counter_ns() // 1000
    if now >= next_t:
        dev.on_tick(now)
        next_t += period_us
        if now - next_t > period_us:      # 落后太多：跳拍并计 overrun
            next_t = now + period_us
    else:
        sleep_small()                      # 1 kHz 时忙等到 ~200 µs 再 sleep
```

- **不要用 `time.sleep(1/sample_rate)` 做节拍**，Windows 上精度只有 15 ms，会丢一大半 tick
- 5 kHz 时 `period_us = 200`，必须忙等 + 微睡交替

### 4.3 DS18B20 模拟（`onewire.py`）

必须模拟三件事，否则上位机测不出问题：

1. **转换延迟**：12 bit → 750 ms，期间读到的是**上一次**的值
2. **上电默认值 85 ℃**：刚上电读 `0x0550`，模拟器要真的返回这个值
3. **掉线**：`--fault-temp-lost 1` 时返回全 0 或干脆不响应

### 4.4 信号模型（`signals.py`）

每通道独立配置模型 + 相位：

| 模型 | 参数 |
|---|---|
| `dc` | V, I |
| `battery` | 起始电压、内阻、容量 |
| `buck` | Vout、开关频率、纹波幅度、负载阶跃幅度/时刻 |
| `boost` | 同上 + 轻载 PFM 跳周期 |
| `step_load` | 阶跃幅度、上升时间、周期 |
| `sweep` | V 或 I 扫频 |

输出经 `adc.py` 量化：

```python
def quantize(v_volts, vref=3.3, bits=12) -> int:
    code = int(round(v_volts / vref * (1 << bits)))
    return max(0, min((1 << bits) - 1, code))     # 饱和行为要真
```

### 4.5 CLI

```bat
python run_sim.py --listen 127.0.0.1:5555 --hid-pacing on --ram 10240
```

## 5. 上位机设计

### 5.1 传输层（唯一需要分支的地方）

```csharp
public interface ITransport : IDisposable {
    void Open();
    void Close();
    bool IsOpen { get; }
    int  Read(Span<byte> buffer, int timeoutMs);   // 定长 64
    void Write(ReadOnlySpan<byte> frame);          // 定长 64
}
```

| 实现 | 说明 |
|---|---|
| `TcpTransport` | 连模拟器，按 64 B 切块，**必须处理"一次 recv 不足一块"** |
| `HidTransport` | hidapi / HidSharp，`Read` 超时靠轮询实现 |

### 5.2 会话层

```csharp
public sealed class DeviceSession {
    Task<IdentifyAck>  IdentifyAsync(uint nonce, CancellationToken ct);
    Task<ChannelConfig> GetChannelConfigAsync(int ch, CancellationToken ct);
    Task<AcquireAck>   AcquireAsync(AcquireParams p, CancellationToken ct);
    Task<AbortAck>     AbortAsync(bool discard, CancellationToken ct);
    Task<(long offsetUs, long rttUs)> TimeSyncAsync(CancellationToken ct);

    event Action<EventMsg>? EventReceived;
    event Action<Block>?    BlockReceived;
}
```

- 命令用 `SemaphoreSlim(1,1)` **严格串行**，避免回包串到别的命令上
- 每个请求带 SEQ，`Dictionary<ushort, TaskCompletionSource<Ack>>` 匹配
- `ABORT` 超时 2 s，其余 200 ms × 3
- 事件与数据块**不参与**应答匹配（否则高速数据会把 ACK 顶掉）

### 5.3 采集链路

```
IO 线程: Read(64) → FrameCodec.Feed → BlockAssembler
            ├─ ACK   → _pending[seq].TrySetResult
            ├─ BLOCK → _blockChannel.Writer.TryWrite   (有界 256)
            └─ EVENT → _eventChannel.Writer.TryWrite
消费线程: await foreach → Stats.Accumulate / Pyramid.Push / ChartBuffer.Push
UI 线程 : DispatcherTimer(33ms) → 一次性刷新所有绑定 → Chart.InvalidateVisual
```

### 5.4 建链顺序（v1.4 必须逐通道读配置）

```csharp
var id  = await s.IdentifyAsync(nonce);
if (id.Magic != "PDL1" || id.Nonce != nonce) throw new NotPdlDeviceException();
for (int ch = 0; ch < id.PowerChannels; ch++)
    power[ch].Apply(await s.GetChannelConfigAsync(ch));
for (int ch = 0; ch < id.TempChannels; ch++)
    temp[ch].Apply(await s.GetChannelConfigAsync(4 + ch));
await s.TimeSyncAsync(ct);
await s.ReadTempOnceAsync(ct);      // 立刻显示室温
```

> 四路分压比不同（4.3 / 8.5 / 23 / 31），少读一条就少一路正确的量程。

## 6. 测试策略

| 层面 | 方法 |
|---|---|
| 编解码 | golden vector（`02` 文档第 12 章的 EX1–EX6），Python 与 C# 各跑一遍，字节必须完全一致 |
| 协议一致性 | 用 Python 生成"预期字节流"文件，C# 解码后重新编码，比对是否 round-trip |
| 端到端 | 模拟器 + 上位机联跑 10 分钟，断言 `上位机收到的 tick 总数 == 模拟器发出的 tick 总数` |
| 带宽 | `--hid-pacing on` 下 4ch@1kHz 跑 5 分钟，`dropped_ticks == 0` |
| 故障 | 注入丢帧 1% / 延迟 50 ms / 中途断连，断言不崩、有告警、能重连 |
| 长跑 | `--time-scale 100` 跑 24 小时等效，断言金字塔体积与内存符合预算 |
